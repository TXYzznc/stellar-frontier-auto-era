# Design

## Context

用户确认全部18项按顺序设计，完成后集中验收。此前已确认每页功能文档、每个共享Form结构只维护一次。GF UI Standards最新版本优先于旧技能模板与旧Prefab样例。

## Goals / Non-Goals

目标：每页可按入口、字段、控件、权限、异常、返回与精确布局审查；共享结构无重复所有权。非目标：运行实现、生成美术、注册新UIViews、业务规则扩张、用户验收代签。

## Decisions

1. 页面功能文档与家族prefab-layout关联；Form公共壳在共享外壳单一声明。
2. 106份规格包括HUD模块与子页，不对应106个Form；算法编辑与诊断共用画布。
3. 继承数据与权限服务；现场、远程、整备分开。中枢记录嵌入预制阅读组件。
4. 未冻结的细节给出候选方案，不逐项阻塞用户；具体候选列在总索引。
5. 根节点不含Canvas系列组件，列表预制Item，按GF命名与布局规则设计。
6. 本批专业设计包含非机械判断，由当前窗口直接执行。

## Risks / Trade-offs

- 旧中枢样例含范围外内容：记录替换项，不据旧Prefab扩范围。
- 自动生成布局已有本地修改：保持原文件，目标设计验收后再迁移contract.json。
- 规范包含通用手柄建议：第一版PC约束优先，不新增手柄支持。
- 大量页面需要用户审阅：总索引按1—18排列，每页稳定ID方便回改。

## Validation

检查文档链接、18家族覆盖、106页链接与布局、节点命名及主要区域边界。CLI openspec在本环境不可用，未声称strict验证通过。无Unity变更，未执行原型L1—L4。
