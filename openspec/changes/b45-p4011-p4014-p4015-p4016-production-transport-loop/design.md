# B45 运输与生产观察

## Context

算法、生产、转移和仓库分别可测仍不足以证明机器能持续把产物送入库。需要明确运输任务防重、途中货物责任、异常恢复与玩家观察链，形成两类资源的可玩子集。

原始任务：P4-011、P4-014、P4-015、P4-016。用户在2026-10-08确认全量详细规划及“复用现有架构、必要时局部重构”，随后确认本批方向；UI运行验收仅1920×1080，但Prefab结构仍考虑适配。本批增量已实施并验证，见[evidence/implementation-20261008.md](evidence/implementation-20261008.md)，完整外部依赖仍保留。

## Goals / Non-Goals

**Goals:**

- 固定路线任务使用已有任务/货舱查询防重复，串联真实移动、装载、卸载与入库结果。
- 保留取消/失败后的货物及未解决责任，恢复优先完成既有交付。
- 仓库与林木/矿脉现场页接真实读模型，动作反馈和诊断消费真实事件。

**Non-Goals:** 不把两类资源纵切等同于完整G4；不新增复杂物流调度、不绕过b07所有权，不实现全部农业/水域面板，不提供跨仓库瞬移按钮。

实现边界见proposal.md的路径清单。新增产品类型只能进入AutoEra目录并使用AutoEra.*命名空间；本批不修改ScriptsBuiltin、asmdef、HybridCLR/FSR设置或用户任务表。场景/Prefab共享文件在实施前核对占用和精确清单，不按目录通配批量改写。

## Decisions

### 路线与取舍

| 候选 | 优点 | 代价 | 选择 |
|---|---|---|---|
| 复用既有服务并局部修正边界 | 保留既有规则与验证投入，可独立回归 | 需处理旧入口兼容 | 采用，符合用户A |
| 统一底座后重写接入 | 全局模式整齐 | 回归面与前期投入更大 | 不采用 |
| 只补调用，不调整责任 | 局部代码少 | 生命周期/状态风险可能残留 | 不作为本批方案 |

### D1 任务步骤

复用既有固定路线模板和任务查询语义；运输任务记录来源/目的地绑定、物品类型、已承诺/已装/已交付量和当前步骤。已有目标货物时先交付，重复触发合并/拒绝遵循现有防重合同，不再建第二条同责任运输。

### D2 导航与装卸

移动仍通过MachineNavigation与作业点申请；到达和合法停靠后才能提交B43转移。无路径返回真实结果，缓存不足/目的容量不足按既有重试和等待合同处理，不忙等、不清空货舱。现有模板坐标参数按DEC-202保留，目标失效不得自动猜测替代地点。

### D3 责任跨任务保留

任务失败/取消后已在货舱的物品继续有拥有者与交付责任；显示来源、目标和最近失败原因。再次启动同路线应先尝试既有交付；不因重启算法或关闭UI生成额外货物。

### D4 UI只读与操作边界

WarehouseForm读取库存、全局入库余额和分类记录；FieldHudDetail只接林木/矿脉真值，其余仍明确不可用。UI发命令不能直接写余额/搬动物品。沿用读模型订阅和GF对象池，关闭退订不影响运输。

### D5 反馈与分阶段验收

移动、装卸、作业的开始/暂停/完成由实际事件投影；阶段用例可创建明确初始世界输入，但完整正常玩家流程必须由B47的正式新进度入口再次跑通。视觉仅1920×1080，节点布局保留适配结构，缺正式资产的证据明确标为逻辑/灰盒。

## Risks / Trade-offs

- **G4前置与局部范围混淆** → 报告逐列标明林木/矿脉通过、水泵/农业/b07待依赖，不勾选整个原任务或阶段门。
- **取消后清空货舱来消除错误** → 保留未解决责任并以守恒断言阻止丢货式恢复。
- **本次尚无新运行证据** → 本文件定义将来的验证门；历史测试保留时间/版本，不当作本次复跑。
