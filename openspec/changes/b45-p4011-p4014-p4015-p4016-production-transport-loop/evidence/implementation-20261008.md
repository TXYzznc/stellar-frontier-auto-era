## 实现

- 世界持有运输责任，包含任务/机器/来源/目的地/物品、请求量、当前预留量、已装/已交付量与状态/最近失败原因。货物和余额始终由CargoOwnershipAuthority持有；责任阶段在权威发布库存变化前更新，观察者不会读到货舱与责任不一致的瞬间。
- 源与目的通过显式稳定ID及硬件代次绑定；固定路线模板保持坐标参数和原有35逻辑点实际费用（规则基础34，现有额外Delay常量1）。实际缓存与所选物品接入模板，满容量按既有30秒延迟重试。
- 到达合法停靠点、机械臂实际关节可达且接触成立后才预留；准备0.5秒、每秒5单位，跨真实货物批次连续处理。一级2米、二级2.2米及速度+20%沿用既有规则，由专用配置复制成不可变值。
- 取消只释放未提交预留；停电/暂停保留贡献，不补算暂停时间。来源不足、货舱容量不足、目的地失效与无路保留实际货物/交付责任；再次运行同路线先交付已有货物。机器详情只读展示责任并对称退订。
- 批准机械臂原base_yaw与VisualModel为兄弟节点，不能真实驱动末端。通过Unity原生Prefab将VisualModel挂到该既有关节，保持模型、关节ID、绑定姿态及限制；验证实际末端属于全部旋转关节链，不降低几何验证门。
- WarehouseForm读取库存、全局余额与真实入库回执，FieldHudDetail只接林木/矿脉公开量、缓存和生产/装载记录；GF列表池继续负责行生命周期，关闭退订不会停止运输。未接入的出售、筛选、定位等操作明确不可用，不伪造领域命令。
- 公开参数输入保留枚举类型/家族、坐标及数值单位/精度，不把物品和坐标误写成普通数字。
