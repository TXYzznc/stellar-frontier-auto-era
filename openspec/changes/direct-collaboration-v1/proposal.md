# 直接协作与双制作人架构

## 目标
移除常驻任务调度窗口，采用双制作人、角色直连消息、追加日志和角色优先级队列，减少轮询与 token 浪费，同时保证任务不丢失、不被无谓打断、结果可验收。

## 已确认决策
- 移除常驻任务调度角色及其定时效果。
- 制作人·派发负责与用户沟通、整理方案、取得用户选择并直接派发任务。
- 制作人·协作验收负责跨角色协作、决策汇总和结果验收；只有真正需要用户选择时才上报。
- 角色之间直接发送消息；不经过调度器转发。
- 每个角色维护独立的只增日志；关键事件同时记录发送与接收。
- 每个角色维护文本优先级队列；任务详情按需读取。
- 普通通知进入队列，不打断 Active 任务；决策、资源冲突和无法继续才升级。

## 范围
包含日志格式、消息回执、角色队列、双制作人权限、窗口迁移和旧调度器停用。

## 不包含
不修改 Assets/Game/ScriptsBuiltin，不改变业务功能，不自动执行 Git 操作。

## 验收
- 直接消息具备 delivered/accepted/completed 回执和失败留痕。
- 追加日志历史不可修改，可按角色和任务恢复上下文。
- Active 任务收到普通协作请求时不被抢占，安全检查点后处理。
- 任务详情不在常规启动时全部载入，仅领取任务时读取。
- 制作人可从各角色日志重建任务进展并完成验收。
- 常驻调度窗口与定时唤醒停止，旧状态不会重新触发任务。
