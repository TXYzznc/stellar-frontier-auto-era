## Context

ART-006 已通过用户讨论冻结“清朗工程面板”、极简 HUD 与按需中枢、对象优先信息层级、规则影响预览、危险操作与异步反馈等决策。后续工作跨越 2D 美术、可编辑源与 Sprite 导入、UGUI Prefab、GF UIForm、客户端状态摘要和验收，若无统一合同将出现视觉 Token 分叉、焦点路径不一致、危险操作绕过确认或异步状态伪造等风险。

本设计以 `Docs/GameDesign/90-设计管理/方案讨论增量归档.md`、`Docs/Development/Dispatch/Active/b03-parallel-art-art004-art006-production-rnd.md` 和 `Docs/Development/GF-UI-Standards/README.md` 及 01–08 为权威输入。适用对象包括 HUD、对象优先右侧面板、任务中枢、规则／自动化页面与影响预览确认弹窗。利益相关方为用户、2D 美术、主美、客户端和验收人员。

## Goals / Non-Goals

**Goals:**

- 使视觉、页面规格、资源交付、Prefab 布局、GF 生命周期与状态摘要接口共享一套可验证合同。
- 将三张代表样张作为后续视觉验收的最低覆盖面，而非本变更内的实际产物。
- 使危险确认、异步执行、长时等待、失败恢复和键鼠手柄焦点具有确定、可访问的行为。
- 使后续实现可在 16:9、16:10、21:9 和减弱动态条件下验收。

**Non-Goals:**

- 不在本变更中生成 UI 样张、PNG/Sprite、可编辑源、Prefab、C#、Unity 场景或任务表更新。
- 不定义 GF 版本、CanvasScaler 数值、资源地址、Form 基类、具体接口字段或最终文案表；这些必须在项目接入阶段填入 GF UI Standards 模板并经对应实现任务确认。
- 不将 ART-006 的视觉合同扩展为世界物体美术、玩法结算或后端任务调度实现。

## Decisions

### 1. 使用语义 Token 而非页面散落数值

后续页面与资源 SHALL 使用 `Surface`、`Text`、`Action`、`Focus`、`Danger`、`Warning`、`Success`、`Disabled` 等语义 Token；Token 的具体色值与资源映射在视觉交付阶段登记。选择语义层可保证同一风险、焦点和禁用语义跨 HUD、面板、弹窗一致，并允许高对比或减弱动态替换。替代方案“每页按视觉稿直接写色值”被拒绝，因为会破坏全局状态一致性。

### 2. 采用三层信息入口与对象优先返回

HUD 只保留实时摘要、严重告警、选中对象和入口；选中对象优先进入右侧轻量面板，无对象时显示告警／近期任务；跨系统分析再进入任务导向中枢。失败详情关闭后恢复到来源卡片的入口，来源失效时降级到最近可用卡片、列表标题或空状态。此选择在不牺牲深度分析的前提下避免 HUD 承载全部信息。替代方案“所有详情一律中枢”会中断现场处理。

### 3. 危险操作以影响说明和可配置文案为安全门禁

需要解释对象、资源、范围或后果的危险操作使用确认弹窗；简单、后果明确且易误触的危险操作可使用 1.2 秒长按。确认描述是可本地化文本资源，按钮通过索引自由绑定，正文可含参数；标题由固定 Text 绘制，最终按钮使用动作文本和 `Danger` 语义。确认弹窗左侧中性取消、右侧 Danger，首次焦点始终在取消。替代方案“统一固定三段文案”被拒绝，因为难以准确表达各操作差异。

### 4. 异步状态以权威结果为准，不伪造进度或失败

提交后关闭确认弹窗并在触发处显示执行中、成功、失败或已取消。只有可安全中断的底层操作显示取消入口；成功反馈约 2 秒后复位，失败驻留并提供重试／详情。客户端的“等待较久”只改变提示，绝不自行判定失败或请求丢失；请求 ID 和底层任务状态才是权威。阶段文字优先，可信 `0～1` 进度才显示细条／百分比；旋转图标始终仅作活动反馈。替代方案“客户端超时转失败”会诱导危险操作重复提交。

### 5. 以 GF UI Standards 的交付顺序约束后续实现

每页先完成目的、入口／出口、数据、操作、异常与状态表，再完成 `prefab-layout.md` 和资源切片说明，然后创建 UGUI／GF UIForm 与代码接入。每个独立页面一个 UIForm；共享组件必须跨两页以上且职责稳定。所有输入经 InputModule，异步回调验证页面和请求版本。替代方案“先做样张或 Prefab 再补合同”会使视觉和生命周期规范相互覆盖。

## Risks / Trade-offs

- [三张代表样张不足以穷尽全部页面] → 后续每个新页面 MUST 复用本合同的页面规格表、状态表和验收清单。
- [Token 名称已冻结而数值尚未最终生产化] → 在资源交付任务中登记唯一色值、对比度与替换规则，不得用临时硬编码绕过。
- [底层未提供阶段／进度／请求 ID] → UI 只能显示诚实等待态；客户端与后端接入任务必须补齐状态摘要合同，不能伪造信息。
- [确认文案资源或参数缺失] → 红色错误框替代正文、Danger 禁用、完整异常写入开发控制台；正式交付验收不得出现该异常态。
- [超宽或长文本导致布局压力] → 使用安全阅读区、Layout Group、可展开详情和本地化预留；不得缩小关键文字或把长文案烘焙到图片。

## Migration Plan

1. 在本变更中审核 proposal、design、能力规格与任务清单，并严格验证。
2. 在后续经授权的视觉任务中产出三张样张、Token 表、字体／图标／面板资源及可编辑源、切片和导入建议。
3. 在后续经授权的 UI 实现任务中，以每页 `prefab-layout.md` 为先决条件创建 UIForm、绑定客户端状态摘要，并执行多比例、输入、可访问性和性能验收。
4. 若发现合同与用户新决策冲突，先追加 OpenSpec delta；不得静默改写已冻结语义。实现回滚为移除未验收页面／资源并恢复上一个验收的 Token、布局和状态合同，不回滚用户已确认的设计归档。

## Open Questions

- 项目最终 GF／Unity 版本、CanvasScaler 参考分辨率、UIGroup、Form 基类、资源地址与本地化服务尚未写入项目接入模板。
- 各操作的真实请求 ID、阶段、可信进度、可安全取消和重试确认标记的具体字段由客户端／后端接入合同确认。
- Token 实际色值、唯一 TMP Font Asset 名称、图标笔画数值、九宫格边界和资源目录需在样张／资源交付任务中填写并验收。
