## ADDED Requirements

### Requirement: 三张代表样张和页面规格
后续视觉交付 SHALL 至少制作三张代表样张：现场 HUD＋对象优先面板＋严重告警、任务中枢总览、规则摘要卡＋影响预览。每个独立页面在制作前 MUST 记录页面目的、入口／出口、数据来源与刷新、可用操作、默认／聚焦／按下／禁用／加载／空／错误／成功／危险状态、长文本与适配策略、异常退出及验收路径；不得以样张替代该规格。

#### Scenario: 开始制作中枢总览
- **WHEN** 后续任务开始制作任务中枢总览
- **THEN** 任务包先提供总览的目的、HUD／面板入口、Esc／返回出口、三张主卡数据与状态表、异常和验收路径

### Requirement: 页面信息层级与状态密度
中枢总览 SHALL 以严重告警／阻塞、当前任务队列、资源／产能摘要为最多三张主卡；无严重告警时 MUST 保留稳定健康卡，避免布局跳变。规则卡 SHALL 显示条件→判定→动作三段摘要，每段最多两行，空间不足时按相同顺序纵向堆叠；启用／停用与影响预览入口必须明确，不得点击整卡直接切换。空、禁用、错误和数据不足状态 MUST 说明原因、下一步或恢复路径。

#### Scenario: 中枢没有严重告警
- **WHEN** 当前没有严重告警
- **THEN** 顶部区域显示紧凑健康卡、最近状态变化和待处理入口，而非移除卡片或留下空白

### Requirement: Prefab 布局、GF UIForm 与客户端状态摘要合同
每个独立页面在创建 Prefab 前 MUST 提供 `prefab-layout.md`，记录节点语义、anchor、pivot、尺寸、布局组件、资源、文本样例、状态、raycast 和导航。每个独立页面 SHALL 对应一个 GF UIForm；所有输入经项目 InputModule，生命周期 MUST 按 OnInit／OnOpen／OnCover／OnResume／OnClose／OnRecycle 清理订阅、请求、Item 和临时状态。客户端状态摘要 MUST 至少提供对象／告警／任务状态、请求 ID、可安全取消、重试确认标记、明确失败／取消／请求丢失、阶段文字和可信进度；UI 不得轮询或伪造这些状态。

#### Scenario: UIForm 收到晚到的异步回调
- **WHEN** 页面关闭或请求版本过期后底层回调到达
- **THEN** UIForm 不更新已关闭页面、不恢复旧焦点，并按生命周期规则清理订阅和临时状态

### Requirement: 多比例、可访问性与性能验收
后续页面验收 MUST 覆盖 1920×1080 主评审、16:9、16:10 和 21:9；21:9 以中央 16:9 安全阅读区承载关键控制，16:10 的额外高度优先给列表和统计。验收 MUST 覆盖鼠标、键盘、手柄、焦点、长文本、非颜色状态区分、减弱动态、加载／空／错误／超时、页面关闭和无障碍说明。性能验收 MUST 检查 Canvas rebuild、UI draw call、GC、列表对象池／虚拟化、布局循环和图片内存。

#### Scenario: 超宽屏验收
- **WHEN** 代表样张或页面在 21:9 下验收
- **THEN** 关键 HUD、主操作和危险确认不贴近物理边缘，不裁切主要内容，额外宽度用于世界视野或留白
