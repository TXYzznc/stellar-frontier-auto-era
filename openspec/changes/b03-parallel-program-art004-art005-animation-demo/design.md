## Context

ART-004／005需要一个连续、可控制的Play Mode验收演示，将分散的机器和建筑机构预览组织成用户可直观看到的七段流程。用户已确认演示目标、段落、控制、相机、叠层和恢复边界；但2026-08-26又判定现有3D模型不可用，因此本变更只能在替代资产通过前置出图、建模路线和模型验收后实施。

## Goals / Non-Goals

**Goals:**

- 在独立验收场景中自动顺播七段机器／建筑程序化表现，每段5～8秒。
- 提供暂停、切段和重置控制，以及三个固定机位间的平滑切换。
- 使用最小开发叠层显示段名、进度和暂停状态。
- 确保重置、停播和退出Play Mode时演示实例恢复确定基线。

**Non-Goals:**

- 不创建正式玩法、正式HUD、宣传片时间线或关键帧动画系统。
- 不修改生产、导航、碰撞、存档或其他玩法权威。
- 不覆盖已验收源资产或正式场景，也不消费被判定不可用的旧模型。
- 不在替代3D资产完成验收前实现或运行演示。

## Decisions

### 1. 使用独立场景与专用演示实例

演示只存在于ArtResource独立验收场景。场景内实例是已验收资产的演示副本，可挂接开发控制器和适配组件，不得把演示状态写回Prefab源或玩法对象。

### 2. 演示控制器编排七个可重置段

控制器按固定顺序管理工坊总览、门、传送带、贴地、转向、支撑机械臂、效应器交换／中断。每段拥有进入、更新和退出边界，并通过窄适配接口调用现有程序化表现能力；控制器不重新实现机构求解，也不拥有玩法状态。

### 3. 自动顺播与人工控制共享同一状态机

默认每段5～8秒后进入下一段。`Space`暂停／继续，左右方向键切换上一／下一段，`R`恢复演示基线并回到第一段。人工切段必须先结束当前段并恢复该段临时状态，禁止叠加多个段的残留。

### 4. 单相机使用三个序列化预设

演示仅使用一台相机，在全景、轮组低机位和机械臂近景三个预设之间平滑插值。每个段引用一个预设；切段时不创建额外运行时相机，也不使用自由相机破坏可复现构图。

### 5. 验收叠层与正式UI隔离

右上角叠层只显示当前段名、段内进度和暂停状态。它是场景内开发视图，不进入正式HUD、GF-UI页面或游戏输入层级。

### 6. 基线恢复是硬门禁

进入播放前记录演示实例的Transform、激活状态和受控预览状态。重置、停播、组件禁用和退出Play Mode均恢复该基线；无法可靠恢复的对象不得接入演示。

## Risks / Trade-offs

- [旧模型被误用] → 首任务核验所有演示引用来自重新验收的替代资产，并拒绝Deprecated证据对象。
- [段落适配器修改玩法状态] → 只调用表现层预览接口，测试重置前后权威状态与源资产无变化。
- [切段残留导致后续画面错误] → 每段具备显式退出和基线恢复，连续循环两遍验证无累积漂移。
- [开发叠层演变为正式HUD] → 限制为独立场景最小信息，不依赖正式UI资源或导航。
