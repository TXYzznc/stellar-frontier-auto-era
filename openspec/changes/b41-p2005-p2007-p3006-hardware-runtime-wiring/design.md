# B41 传感器与效应器生命周期

## Context

机器上下文已拥有传感器集合和行为队列能力，但生产路径未建立传感环境、采样注册和效应器执行绑定。只在测试里接通提供者，会让配置界面有绑定而运行时无数据或无法执行。

原始任务：P2-005、P2-007、P3-006。用户在2026-10-08确认全量详细规划及“复用现有架构、必要时局部重构”，随后确认本批方向；UI运行验收仅1920×1080，但Prefab结构仍考虑适配。当前仅规划，未实施。

## Goals / Non-Goals

**Goals:**

- 建立部署/装配变化到传感器及效应器运行绑定的生产注册链。
- 按真实永久ID、能力和绑定代次验证目标，动态硬件变更幂等对账。
- 结果回传连接到算法与责任事件，动作表现仅消费结果；为生产域提供明确适配接入点。

**Non-Goals:** 不伪造农田湿度、矿产数量或成熟状态；不新增职业机器、传感器等级差异或通信能力；生产行为权威由B44/B43提供。

实现边界见proposal.md的路径清单。新增产品类型只能进入AutoEra目录并使用AutoEra.*命名空间；本批不修改ScriptsBuiltin、asmdef、HybridCLR/FSR设置或用户任务表。场景/Prefab共享文件在实施前核对占用和精确清单，不按目录通配批量改写。

## Decisions

### 路线与取舍

| 候选 | 优点 | 代价 | 选择 |
|---|---|---|---|
| 复用既有服务并局部修正边界 | 保留既有规则与验证投入，可独立回归 | 需处理旧入口兼容 | 采用，符合用户A |
| 统一底座后重写接入 | 全局模式整齐 | 回归面与前期投入更大 | 不采用 |
| 只补调用，不调整责任 | 局部代码少 | 生命周期/状态风险可能残留 | 不作为本批方案 |

### D1 区域与机器职责

区域拥有公开数据提供者目录与目标生命周期，机器运行时拥有装配组件对应的MachineSensor和每效应器队列；机器注册表在部署/硬件Changed时按组件ID对账。保留已有SensorCatalog配置与采样租约，不另建一套采样定时器。

### D2 显式端点注册

用区域对象永久ID定位提供者，使用已存在ISensorEnvironment/ISensorAnchor等边界；只暴露合同允许字段。传感器Bind成功后加入正式采样和算法适配器注册；初始构建失败给出原因且可重试，无提供者不得用零值冒充有效读数。

### D3 效应器执行端

每个真实安装效应器只有一条行为权威队列，多算法命令通过已有任务/优先级仲裁进入该队列；同效应器串行、不同效应器按既有规则并行。为B43资源转移、B44切割/钻探提供类型化命令与结果接入点，未实现类型明确拒绝，不立即返回假完成。

### D4 失效与代次

装卸、目标删除、距离/休眠变化和重绑定产生可辨失效；旧代次样本及迟到结果不可驱动新图。卸载在既有安全点取消行为，归还预留与算力；场景退出一次性释放。只有有效数据变化产生必要算法事件。

### D5 表现单向

复用MotionWorkBridge将已接受/运行/完成状态投影到动作，不以动画播完或碰撞体数量决定资源提交。目标锚点缺失须降级说明或拒绝相关动作，不能反向改变领域余额。

## Risks / Trade-offs

- **硬件Changed触发重复注册** → 以组件ID差异对账，增加重复部署/相同修订无变化用例。
- **提供者尚未实现** → 分能力报告不可用；B44补真实资源提供者后再通过完整生产验收。
- **本次尚无新运行证据** → 本文件定义将来的验证门；历史测试保留时间/版本，不当作本次复跑。
