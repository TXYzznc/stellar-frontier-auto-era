# B48 跨域快照与离线调度

## Context

完整存档需要跨资源、经济、能源、任务成长保持同一提交边界；离线推进必须复用这些领域规则而非按离线时长直接乘收益。已有世界时钟和排序模型可复用，但尚缺持久化事件队列及跨域快照适配。

原始任务：P7-005、P7-006、P7-007。用户在2026-10-08确认全量详细规划及“复用现有架构、必要时局部重构”，随后确认本批方向；UI运行验收仅1920×1080，但Prefab结构仍考虑适配。当前仅规划，未实施。

## Goals / Non-Goals

**Goals:**

- 将生产/余额/能源/任务成长适配到B47不可变快照与恢复事务。
- 建立有效事件优先队列、稳定同刻排序和可恢复离线检查点。
- 明确事件预算、取消续算、UTC目标时刻与奖励/每日补给防重边界，提供领域下一事件接口。

**Non-Goals:** 不实现经济/成长/建筑本身来绕开G5/G6；不离线逐帧跑物理，不用闭式平均收益替代有阻塞的模拟；B49负责完整领域事件和报告。

实现边界见proposal.md的路径清单。新增产品类型只能进入AutoEra目录并使用AutoEra.*命名空间；本批不修改ScriptsBuiltin、asmdef、HybridCLR/FSR设置或用户任务表。场景/Prefab共享文件在实施前核对占用和精确清单，不按目录通配批量改写。

## Decisions

### 路线与取舍

| 候选 | 优点 | 代价 | 选择 |
|---|---|---|---|
| 复用既有服务并局部修正边界 | 保留既有规则与验证投入，可独立回归 | 需处理旧入口兼容 | 采用，符合用户A |
| 统一底座后重写接入 | 全局模式整齐 | 回归面与前期投入更大 | 不采用 |
| 只补调用，不调整责任 | 局部代码少 | 生命周期/状态风险可能残留 | 不作为本批方案 |

### D1 跨域快照契约

各领域提供Capture/Validate/Restore及版本信息，全部在同一worldRevision安全边界取值；保存缓存/预留/归属/余额、能源燃料与储能、生产剩余进度、任务奖励标记和补给日期。适配器不复制一套领域数据库，未知/缺失必需段拒绝完整恢复。

### D2 奖励和日期

以原任务/购买/奖励事务ID保留已提交标记，继续未完结事务不得重复发放。每日补给保存最近领取本地日期和已见最晚本地日期；时间倒退不再次取得资格。离线是否自动发放按原领域规则，调度器不替玩家领取/购买/升级。

### D3 事件表示

事件含dueWorldMilliseconds、领域优先级、主体永久ID、稳定sequence、generation和类型化可序列化负载；使用最小堆或同等稳定优先队列，不持久化闭包、Unity引用或委托。取消通过代次/有效性检查惰性丢弃，并在安全边界整理失效事件。

### D4 同刻事务边界

同刻按能源→世界生产/状态→传感器→算法→任务/行为完成→资源/奖励结算，再按永久ID和事件序号。事件可生成后续同刻工作，但不得递归绕过已处理优先级；结果进入规定的后续批次。每个完整同刻业务批次结束才允许持久化检查点。

### D5 分帧与恢复

每帧处理事件数量/耗时预算，预算用尽可在内存中让出，但不得将半个原子提交作为可恢复检查点。检查点保存已追赶世界时刻、目标UTC、排序序号、领域状态、队列和结算runId；恢复从检查点继续，同样时长和初值不受分帧预算影响。

### D6 时间与高频保护

本次追赶锁定目标UTC与已保存时刻，负离线间隔不倒推世界或生成收益，按既有时间规则处理。相同原因的高频无进展算法单独暂停并记录，不让其无限生成同刻事件阻塞整个世界；阈值继承既有容量/执行规则，新增阈值必须在测试基准后明确而不偷改规则。

## Risks / Trade-offs

- **多领域捕获时刻不一致** → 同一提交修订屏障与守恒测试，禁止各模块各自异步读取活对象。
- **同刻事件重复或顺序随字典变化** → 排序键显式持久化，对不同注册顺序/不同预算重放结果完全一致。
- **外部领域交付不全** → 维护必需领域段清单与依赖门，接口测试不是完整离线交付。
- **本次尚无新运行证据** → 本文件定义将来的验证门；历史测试保留时间/版本，不当作本次复跑。
