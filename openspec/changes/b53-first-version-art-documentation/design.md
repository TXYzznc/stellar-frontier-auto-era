## Context

2026-10-10 用户将视觉方向冻结为原创工业二次元主导、清线赛璐璐，UI 采用深灰蓝底、浅色信息卡、少量橙色焦点。2026-10-10 后续返工决定：参考 Everlight-Tales 的文档目录和逐项内容结构，不能继续使用上一版扁平摘要。

## Goals / Non-Goals

**Goals:** 建立可直接交给 UI 美术、3D 美术、VFX/音频设计和生图 AI 的生产级文档；共用先行、状态独立、页面和世界对象逐项展开；保留实际项目 contract、Form 和第一版边界。

**Non-Goals:** 实际生图、建模、贴图、音频制作、Unity 导入、Prefab 修改、任务表修改、旧资源复用。

## Decisions

1. 目录对齐参考项目：根总纲 → 风格规范 → UI 共用批次/页面族 → 世界共用/独立/效果图。
2. 每个需要绘制的状态是独立编号、独立文件名、独立提示词和验收；程序绘制项单列，避免误交给生图 AI。
3. 页面族文档从当前 `Docs/Development/UI-PrefabLayouts/*.contract.json` 提取 Form、Prefab、脚本和节点骨架；页面文档不能凭空编造布局。
4. UI 效果图固定 1920×1080；世界图使用正交/三分之一轴测；工程尺寸、锚点、碰撞、导航和 KeepOut 只来自技术合同。
5. 参考游戏只提供高层信息层级和节奏观察，禁止复制具体图标、字体、角色、版式、截图或素材。
6. 所有视觉资产从零重做；外部植物、树木和施工装饰同样必须按新提示词重新制作或重新授权。

## Risks / Trade-offs

- 文档数量和维护成本上升 → 通过固定模板、唯一 manifest 和交叉引用控制重复。
- 页面合同和效果图可能失步 → 页面文档记录 contract 路径，验收要求重新扫描。
- 生图 AI 生成伪造文字 → 所有动态文字、数字和连线改为程序项，并将伪造文字列为退回条件。
- 参考风格被误解为复制 → 每份固定负面提示明确禁止现成游戏 UI 和旧素材重绘。
