## Context

项目使用多个长期Codex窗口共享两个Unity实例和同一主仓库工作区。现行流程由制作人独占维护中央占用、审批Git短锁、代写跨职能归档并放行每个阶段；实际运行中，客户端因线程级Git权限限制连续把多个已验证分段交给制作人提交，制作人因此成为无专业决策价值的串行瓶颈。

用户已经通过五轮讨论确认：高自治、用户决定直接生效、窗口点对点同步、Git专门集成窗口、制作人只接收异常与批次完成、合格工作单元立即提交。

约束包括任务表永久只读、只提交不推送、提交标题与正文使用中文、共享工作区不得混入其他窗口现场、每两轮讨论仍须增量归档，以及框架核心／越界修改仍需既有用户授权。

## Goals / Non-Goals

**Goals:**

- 消除制作人对普通专业决策、归档、Unity交接和Git提交的逐项中转。
- 让专业窗口在清晰派发边界内自主完成从讨论到验证的完整闭环。
- 让Git集成窗口成为快速、安全、可审计的执行队列，而不是新的审批中心。
- 保留跨职能冲突、范围变化、破坏性风险和批次交付的制作人治理能力。
- 保持任务表、OpenSpec确认门禁、两轮归档和框架授权边界不变。

**Non-Goals:**

- 不让专业窗口自行扩大任务、OpenSpec或文件授权。
- 不允许Git集成窗口批准框架核心、xlsx或任务表修改。
- 不实现Git推送、自动合并、自动变基、分支重写或远程CI。
- 不引入新的常驻子Agent或扩大Agent SKILL白名单。
- 不为Unity资源另建复杂调度服务；当前采用注册窗口间点对点协调。

## Decisions

### 1. 派发边界即日常自治边界

专业窗口只要仍处于派发任务、可写路径、已确认方案和验收范围内，即可自主讨论、实现、测试、维护局部记录并准备提交。替代方案是继续逐段放行，但真实运行已证明其成本远高于风险收益。

### 2. 用户决定由提问窗口直接落盘和传播

用户在专业窗口作出的决定立即生效。提问窗口写入自身派发单、OpenSpec或专业文档，并直接通知受影响窗口；制作人不做信息复制。只有影响面不明、点对点冲突未解决或需要改变公共范围时升级。

### 3. 增量归档分散所有权，批次结束集中验收

两轮归档门槛保持不变，但归档由当前专业窗口负责，Git集成窗口负责提交。制作人只在整个派发批次完成时统一读取记录、OpenSpec和证据，避免丢失长期上下文，同时消除逐次备案。

### 4. Git使用单一集成窗口

所有专业窗口禁止自行暂存和提交，只向`AutoEra｜Git集成`发送提交请求。请求必须包含派发／OpenSpec ID、精确路径、验证结果、中文标题和正文、排除项以及当前Unity／写锁状态。集成窗口复核暂存区、路径归属、diff检查和排除项后立即提交；结果只回传请求窗口。

采用单窗口而不是分布式Git索引租约，是因为共享工作区的暂存区和HEAD天然全局，且当前客户端存在线程级`.git/index.lock`权限问题。单窗口牺牲少量并行度，换取无交叉暂存和无制作人中转。

### 5. Unity与DCC采用点对点交接

Unity 8090／8091和DCC仍保持单实例独占，但取得与释放不需要制作人批准。请求窗口从本机注册表定位当前职能窗口，直接完成交接并在自身工作记录中留下证据。争抢、失联、目标项目不匹配或破坏性风险才升级制作人。

### 6. 制作人只处理异常和批次完成

强制升级限定为范围／优先级／负责人／排期变化，OpenSpec编号或依赖变化，点对点无法解决的跨职能冲突，共享资源失联或破坏性风险，验收合同冲突，框架核心或新授权需求，Git路径越界／只读文件混入／仓库异常，以及S0～S1事件。普通进度、单项决策、测试通过、增量归档和独立提交不通知制作人。

## Risks / Trade-offs

- [Git集成窗口形成单点队列] → 采用“合格即提交”、最小独立工作单元和精确路径请求；只在冲突时暂停队列。
- [专业窗口漏同步跨职能影响] → 派发模板要求记录受影响窗口，并把影响面不明确列为强制升级条件。
- [分散归档导致信息散落] → 派发单／OpenSpec是局部事实来源，批次完成报告必须列出全部决策与证据入口。
- [Unity点对点交接缺少中央实时状态] → 使用固定窗口注册和明确交接消息；重要操作前仍检查端口、项目、PlayMode和编译状态。
- [集成窗口误提交用户现场] → 禁止通配暂存，提交前比较精确请求路径、暂存区清单和永久排除项，失败即退回请求窗口。

## Migration Plan

1. 更新协作、派发、暂停、角色和开发基线文档，声明新规则优先级。
2. 更新制作人职责，新增Git集成窗口职能说明和请求合同。
3. 更新注册表示例和本机注册表，创建`AutoEra｜Git集成`长期窗口并发送初始化提示。
4. 向客户端、主美、2D美术和测试窗口同步新规则；当前已占用Unity和写范围不变。
5. 由Git集成窗口接管后续提交；制作人停止处理普通提交请求。
6. 若集成窗口不可用，专业窗口保留已验证现场并通知用户，不自动退回制作人代提交；用户可恢复窗口或临时明确指定替代集成者。
