## 目的、判定口径与不重跑理由

本表只重排 B10 基础／初始区域与 B11–B14 已交付能力的证据关系。它不重跑
历史测试、不驱动 Unity、不覆盖原生 XML，也不修改 `tasks.md`、实现或资源。旧矩阵中
“待实现／待测”只表示当时缺少可测入口；本表据后续已交付证据更新覆盖结论，不能据此
自动勾选任务表、更改用户验收范围或宣告整个 P0/G2 完成。

状态定义：

| 状态 | 含义 |
| --- | --- |
| 已覆盖 | 有当前实现边界内的可追溯自动化或原生 XML 证据。 |
| 仅夹具 | 用例验证了服务合同，但刻意不等价于真实硬件输入、完整视觉或完整生产系统。 |
| 缺集成 | 已知需要跨系统／真实入口的验证，但目前没有足以签收的证据。 |
| 待用户 | 技术证据不应替代用户视觉、范围或交付决定。 |
| 范围外 | 已明确不属于本批，不能以“未覆盖”回流成返工。 |

## 最终判定

1. 没有发现需要立即退回客户端的已定位产品缺陷。
2. B10 `1.3` 可按独立基础 QA 证据收口；B10 `2.7` 可按功能性 G1 覆盖收口。二者的
   任务表勾选、整体阶段裁决与用户视觉范围仍不由本窗口修改。
3. G2 的 B11 硬件 UI、B12 身份桥接、B13 导航和 B14 传感器均有各自有效证据；唯一明确的
   技术缺口是“同一用户流程三者联合”的新场景，而非已交付单元的回归失败。
4. 本文不重开 B10 历史准备／验收，也不要求追回声音负例、早期失败夹具或 Physics 升级前快照。
