## ADDED Requirements

### Requirement: 整数世界时间单调推进
为完成原始任务 `P0-005`，世界时钟 MUST 使用非负 `long` 整数毫秒保存世界时间，并 MUST 拒绝负推进或溢出。在线帧驱动 MUST 累积小数余量后只提交完整毫秒；未来离线调用 MUST 能直接推进到指定世界时刻，而不要求逐 Unity 帧重播。

#### Scenario: 不同帧切分得到相同时间
- **WHEN** 两个时钟分别以不同帧间隔推进相同总现实时间
- **THEN** 两者提交的世界毫秒相同，未满一毫秒余量不会被重复或丢失

#### Scenario: 非法倒退
- **WHEN** 调用方请求负数推进或请求跳转到早于当前世界时间的时刻
- **THEN** 时钟明确拒绝该操作且当前时间不改变

### Requirement: 第一版昼夜阶段确定
世界时钟 MUST 支持可校验配置的第一版昼夜规则：完整周期 1,440,000 世界毫秒，有效日照 960,000 毫秒，无日照 480,000 毫秒；新世界 MUST 从配置的白天早期时刻开始。正式 UI 的打开和关闭 MUST NOT 暂停或减速世界时间。

#### Scenario: 日照边界
- **WHEN** 世界时间分别位于日照结束前一毫秒、日照结束时刻和下一个昼夜起点
- **THEN** 阶段依次判定为有日照、无日照和有日照

#### Scenario: 打开界面期间推进
- **WHEN** 世界运行时打开并保持任意普通 UIForm
- **THEN** 世界时钟继续按正常倍率推进，除开发调试入口外不存在玩家暂停或加速控制

### Requirement: 同刻事件具有稳定比较键
系统 MUST 提供由世界时刻、固定事件阶段、永久对象 ID 和单调事件序号组成的稳定比较契约。给定相同输入集合时，比较结果 MUST 与集合插入顺序、帧率和运行次数无关。

#### Scenario: 同刻事件乱序输入
- **WHEN** 同一组同刻事件以不同集合顺序提交排序
- **THEN** 两次结果都按阶段、永久 ID、事件序号得到相同顺序

### Requirement: 现实 UTC 来源可替换
应用上下文 MUST 通过 `IUtcTimeProvider` 获取当前可信 UTC。当前本地实现 MUST 使用 UTC 而不是本地时区时间；未来服务器实现 MUST 能替换 Provider 而不改变世界时钟或离线时长调用方。

#### Scenario: 替换测试时间来源
- **WHEN** 测试向应用上下文注入固定 UTC Provider
- **THEN** 离线时长计算完全使用该 Provider，且不直接读取操作系统时间

### Requirement: TimeUtil 保持无状态并处理时间倒退
`TimeUtil` MUST 只提供无状态的时间换算与差值函数，MUST NOT 保存当前 Provider 或世界状态。离线时长 MUST 等于当前可信 UTC 减去保存 UTC；结果为负时 MUST 返回零。

#### Scenario: 系统时间倒退
- **WHEN** 当前可信 UTC 早于存档记录的 UTC
- **THEN** 计算得到的离线时长为零，世界时间不会倒退
