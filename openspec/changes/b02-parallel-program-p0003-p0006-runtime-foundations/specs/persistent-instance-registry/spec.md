## ADDED Requirements

### Requirement: 世界内统一永久实例 ID
为完成原始任务 `P0-004`，系统 MUST 使用不可变 `PersistentId` 表示机器、建筑、资源点、任务和行为实例。其底层 MUST 为 `ulong`，值 `0` MUST 表示无效；同一世界内所有类别 MUST 共用一个单调递增分配序列，已分配值 MUST 永不复用。

#### Scenario: 不同类别连续分配
- **WHEN** 世界依次创建机器、建筑和任务实例
- **THEN** 三者取得非零且互不相同的 ID，数值按创建顺序单调递增

#### Scenario: 对象注销后再次创建
- **WHEN** 一个对象注销后创建新对象
- **THEN** 新对象不会取得已注销对象的 ID

### Requirement: 恢复 ID 推进高水位
注册表 MUST 支持恢复保存的非零 ID，并 MUST 将后续分配高水位推进到所有已恢复 ID 之后。重复、无效或导致溢出的 ID MUST 明确失败，不能覆盖现有对象或回绕到旧值。

#### Scenario: 乱序恢复对象
- **WHEN** 系统按 20、5、12 的顺序恢复三个对象后请求新 ID
- **THEN** 新 ID 大于 20，且三个已恢复对象仍保持原 ID

#### Scenario: 重复恢复同一 ID
- **WHEN** 第二个对象尝试以已注册 ID 恢复
- **THEN** 注册失败并报告重复 ID，不替换第一个对象

### Requirement: 注册表保持类别和引用一致性
对象注册表 MUST 以 `PersistentId` 为唯一键，并 MUST 同时验证对象类别和受控引用。查询、注册和注销 MUST 返回可区分的成功、缺失、重复、无效和类别不匹配结果；世界会话释放后 MUST 清空全部活动条目。

#### Scenario: 按错误类别查询
- **WHEN** 调用方以“建筑”类别查询一个已登记为“机器”的 ID
- **THEN** 注册表返回类别不匹配且不暴露错误类型的对象引用

#### Scenario: 世界会话释放
- **WHEN** 世界会话被销毁并返回主菜单
- **THEN** 该会话注册表中的所有对象都不可再解析，且新会话不继承其条目

### Requirement: 缺失持久引用不自动重绑
持久对象引用 MUST 保存永久 ID 与预期类别，而不是显示名称或型号。目标不存在时引用 MUST 保持未解析状态，系统 MUST NOT 按名称、型号或后来创建的对象自动替代。

#### Scenario: 引用目标已被移除
- **WHEN** 一个持久引用指向的对象没有在当前世界中注册
- **THEN** 解析结果明确为缺失，并保留原 ID 供诊断或未来恢复，不绑定到其他同名对象
