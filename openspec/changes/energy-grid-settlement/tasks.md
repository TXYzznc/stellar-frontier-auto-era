# 任务

## 1. 结算器：公式与供电顺序

- [x] 1.1 电量变化 ＝（发电功率 − 耗电功率）× 经过秒数 ÷ 60；按**真实经过时间**连续结算，
      **不在 4 分钟标准周期边界跳变**（标准周期只用于数值校准）。
      `PowerToEnergy` / `EnergyToPower` 公开成静态方法，让离线推进与界面估算复用同一换算。
- [x] 1.2 固定供电顺序：**免费环境能源 → 已开启的燃料发电站 → 蓄电池放电 → 按供电优先级停机**。
- [x] 1.3 燃料发电站实际输出 ＝ min（额定功率，电网分配的剩余需求），
      **多台同类按建造顺序**依次承担；开着但没有需求时实际输出与燃料消耗都是 0（待命）。
- [x] 1.4 环境能源盈余自动为储能充电，**储能已满后的盈余直接舍弃并如实计入快照**。
- [x] 1.5 燃料充电：默认不允许；玩家开启许可并设置目标储能比例后，
      **只在实时负载已满足时**才考虑，且只充到目标比例为止，达到后自动回到只满足实时负载。
- [x] 1.6 **同一时刻蓄电池不能同时充放电**：缺口走放电、盈余走充电，二者互斥。
- [x] 1.7 公开 `EnergyGridSnapshot`：发电／耗电／净功率／储电／上限／充电／放电／舍弃盈余／
      因缺电停机的对象／是否缺电／估算耗尽或充满时间。
      净功率非负时「剩余耗尽时间」**如实给 null**（规格：非负时不显示耗尽时间）。

## 2. 缺电停机与恢复

- [x] 2.1 停机顺序：优先级从低到高（可暂停 → 次要生产 → 普通生产 → 关键设备）；
      同级按进入供电队列的时间**后进先停**，于是**先进的先恢复**。
- [x] 2.2 进入队列的顺序由 `AddConsumer` 自动分配，调用方不维护第二份序号。
- [x] 2.3 **缺电结论不延续**：每次结算重新判定，供电恢复后对象自己回来，不必等玩家操作。
- [x] 2.4 被缺电停机的对象耗电归零；**玩家自己关掉的对象不算「因缺电停机」**
      （`IsDemandActive=false` 既不请求用电、也不参与停机判定），界面才能区分这两件事。
- [x] 2.5 停机的最小单位是**对象级**（规格：整台机器或整座建筑），不碰对象内部的组件设置。

## 3. 昼夜与第一版设施数值

- [x] 3.1 `DaylightCycle`：一昼夜 24 分钟、**16 分钟日照 + 8 分钟无日照**；
      周期与世界时间同起点（世界时间 0 即日出），所以不需要任何启动偏移量——
      加偏移只会让「世界时间第 15 分钟」这种直白说法变成夜间。
- [x] 3.2 `FirstVersionEnergy` 收拢设计数值，**全工程只有这一份**：
      太阳能白天 15 功率、生物质发电机额定 60、蓄电池 240 电量、1 生物质 ＝ 60 电量、
      新存档初始 10 生物质（＝600 电量）。
- [x] 3.3 三个设施对象：`EnvironmentGenerator`（可开关、按环境给出可用出力）、
      `FuelGenerator`（按电量记账保存已投入未消耗的燃料、可设置充电许可与目标比例）、
      `BatteryStorage`（容量与当前电量，**没有充放电功率上限与损耗**）、
      `EnergyConsumer`（待机／稳定功率、优先级、是否请求用电）。

## 5. 边界

本变更**不接场景、不接数据表、不做界面**：设施仍是纯领域对象，没有实体、没有建造流程。
「把机器的功率数据接进来」需要先给 `MachineDefinitions`／`ComponentDefinitions` 加功率列
（设计表 13-统一数值模型 已给出数值），属于下一批。

## 6. 一条取舍记录

**`HasShortfall` 的判据是「有没有对象被迫停机」，不是「计划里还剩多少缺口」。**
后者永远为 0——停机之后缺口必然被抹平，于是它会永远报「不缺电」。
这类「字段名说的是 A、实现算的是 B、而 B 恒为假」的错误不会报错，只会让警报永远不响。
