## Context

任务表已登记 `P0-010`、`P0-014`、`P0-015`、`P0-016`，既有决策也已冻结 Motion Core／Editor／AutoEra Adapter 分层、强类型参数、集中执行器、无关键帧主体动作和固定GUID工具包发布。但此前ART-004／005仍按“效果图和技术文档先行、模型完成后再接程序表现”的顺序执行，实际暴露出Pivot、导入轴、可见链、Socket偏置和活动净空在DCC与运行时之间反复漂移的问题。

本变更把结构和动作验证前移：程序先用基础几何构建可运行、可测试的合同级功能原型；原型通过后导出功能合同，美术再据此完成轴测图、三视图、技术说明和正式模型。美术仍拥有外观权威，程序只拥有功能结构权威。

## Goals / Non-Goals

**Goals:**

- 建立可重复生成的合同级基础几何原型，先验证尺寸、层级、Pivot、锚点、净空、碰撞边界和绑定姿态。
- 建立不依赖GF_X或具体玩法的程序化动作核心，并由AutoEra Adapter接入真实状态。
- 用轮式载体、机械臂、效应器、滑动门和传送带覆盖代表性刚性机构与安全中断场景。
- 导出版本化、可机器校验的 `FunctionalRigContract`，让正式模型只替换视觉子对象。
- 建立自动结构校验、动作回归和固定演示场三层门禁，并允许ArtResource预览同一工具与合同。

**Non-Goals:**

- 不在本变更制作正式模型、材质、贴图、VFX、正式UI或产品宣传动画。
- 不实现完整车辆动力学、受力仿真、完整碰撞IK、导航、生产或存档权威。
- 不允许动作图执行任意脚本，不把DOTween、协程或Animator关键帧作为执行核心。
- 首阶段不制作可视化节点编辑器；Inspector与结构化配置足以完成纵向切片。
- 不修改 `Assets/Game/ScriptsBuiltin/`，不把AutoEra Adapter发布到ArtResource。

## Decisions

### 1. 功能结构与视觉外观使用双权威合同

程序原型负责功能结构权威：米制尺寸、部署根、关节层级、稳定ID、局部轴、限制、绑定／安全姿态、Socket、WorkPoint、KeepOut、接地点和碰撞包络。美术负责视觉权威：轮廓、比例观感、支撑结构、材质分区、表面细节和最终网格。

两者通过版本化 `FunctionalRigContract` 连接。合同采用确定性JSON作为跨项目交换格式，至少包含schema版本、资产族ID、坐标约定、整体包络、关节表、锚点表、净空／碰撞体、视觉槽和兼容版本。Prefab上的 `MotionRig` 只保存稳定ID到Transform的绑定；`MotionGraphAsset` 只保存静态动作配置和参数声明，不保存玩法对象或运行状态。

选择JSON而不是只依赖Prefab或人工文档，是为了让ArtResource、DCC说明和主工程能够独立读取、比较和校验，同时避免手抄尺寸与Pivot。美术技术文档必须引用合同ID和版本；若功能结构需要调整，先修改程序原型并生成新合同，再更新美术文档和模型。

### 2. 原型由确定性Builder生成，基础几何不是临时摆件

原型Builder从合同数据生成逻辑根、Rig根、关节、视觉槽、基础几何、锚点、Gizmo和测试代理。重复生成同一版本必须得到相同层级、命名、局部Transform和稳定标识，不允许依赖场景中手工摆放的未记录状态。

每个可见立方体、圆柱或其它基础几何必须位于明确的视觉槽下，并具有可信支撑／连接关系；无特殊合同声明时禁止悬浮和游离对象。逻辑根、导航根和玩法碰撞权威不得随视觉关节移动。正式模型到达后只替换视觉槽内容，不重建关节或移动锚点。

### 3. Motion Core采用受限图与集中式执行器

Motion Core提供旋转、伸缩、瞄准、开合、持续旋转、往复和等待等基础原语，并支持顺序、并行、循环、条件等待和有限分支。节点使用稳定ID和强类型参数；动作图不得嵌入任意脚本、场景对象或玩法组件。

每个Rig只有一个 `MotionExecutor` Tick。执行器拥有准备、运行、完成、取消和恢复生命周期，并通过关节通道所有权阻止多个动作同时写入同一通道。动作切换从当前实际姿态平滑接续；中断策略显式配置为保持、收回、归零或立即停止。运行状态保存在执行器实例中，不回写ScriptableObject。

采用该方案而不是分类控制器或逐对象脚本，是为了让机器、机械臂、门和传送带共享生命周期、中断和恢复语义，同时保留对象级配置差异。

### 4. Adapter只转换权威状态，不控制关节

主工程的AutoEra Adapter将玩法状态、阶段、目标Pose、0～1进度、效率档位和中断状态转换为Motion Core强类型参数。Adapter不得直接写Transform、宣告产出完成或修改存档；动作播放结束也不得反向决定玩法结果。ArtResource使用模拟参数上下文预览相同动作资产。

地面接触、目标Pose和可达性通过窄接口注入。纵向切片可以使用确定性测试Provider和有限运动学求解验证表现，但不把有限表现求解误认为导航或物理权威。

### 5. 第一纵向切片覆盖六类代表结构

首批对象固定为轮式载体、四轮机构、多关节机械臂、可替换效应器、滑动门和传送带。它们共同覆盖：

- 轮转、四轮转向、低速蟹行、接地点与有限悬挂表现；
- Yaw／Pitch／伸缩／腕部对齐、目标Pose、不可达与安全收回；
- 效应器对位、解锁、脱离、接入、锁定、取消、断电和恢复；
- 门的单／双扇开闭、安全占用、暂停与回弹；
- 传送带循环、效率调速、堵塞保位和恢复。

其它第一版对象只有在纵向切片通过后才批量建立合同原型。静态且无关键装配关系的对象可不接MotionRig，但仍必须遵守尺度、根节点和视觉替换边界。

### 5.1 已确认动作合同驱动代表原型返工

首版纵向切片不得再以“根节点轻微位移”或仅变换通用方块代替可见动作。轮式载体必须由四个独立轮组的转向、悬挂与滚动关节表现行驶、反向转向和低速蟹行；移动距离、接地点和轮径共同驱动轮转角。机械臂必须由底座连续回转及四个受限关节形成连续层级，支持休息姿态、安全收回与可配置限位；抓取／放置只表现抓握端与目标之间的受控附着，不在本变更结算货物所有权。

水枪、旋转锯盘和旋转钻头作为三种独立效应器原型，分别表现喷头瞄准与开阀／关阀、锯盘升降／进给／主轴、钻头旋转／压入／收回与固定粉尘。它们只消费经AutoEra Adapter传入的强类型指令状态和参数，动作结束不得决定灌溉量、树木伤害、采矿量、路径、任务或存档。货舱是被动容量效应器，只表现统一容器占用与自动舱门开闭，不创建独立MotionGraph作业。

传送带的本变更验收仍限于带面、滚筒、接料／出料锚点和受控货物占位的表现；货物归属、接管、出料队列、下级拉取、存档与离线逻辑明确属于 b07，不得在b06实现。滑动门继续以门叶实际关节运动、安全区暂停／回弹与恢复作为验收对象。

### 6. 工具代码分层并以固定身份发布

代码逻辑分为无GF_X／玩法依赖的Motion Core、仅Editor运行的Motion Editor和仅主项目拥有的AutoEra Adapter。首阶段先在主工程建立明确程序集边界；是否新增asmdef必须在实施任务中核对现有Hotfix、HybridCLR和FSR边界后决定，不在本方案中预设未经验证的引用图。

Core与Editor以版本化、固定 `.meta`／GUID 的独立工具包发布到ArtResource。ArtResource只消费工具包和合同，不修改工具源码；动作工具包与美术资源交付包保持分离。

### 7. 三层验收决定何时允许正式建模

第一层是自动结构校验：合同schema、稳定ID唯一性、Transform绑定、轴与限制、锚点、视觉槽、支撑关系和版本兼容。第二层是自动动作回归：组合执行、帧步进确定性、通道冲突、中断恢复、重复播放、对象池复用和无持续GC。第三层是可视验收：固定测试面板和独立演示场展示全部代表动作及预期状态。

结构和数值问题由程序／测试窗口自治修复，不为常规通过项请求用户或制作人。三层门禁通过后才允许主美按合同制作正式模型；正式模型替换后必须重跑同一套结构、动作和可视测试。用户只负责最终可视效果验收。

### 8. 旧样机降级为研究输入，不再反向约束新系统

既有ART-004／005 Blender样机、ArtResource预览脚本和失败证据可用于识别风险，但不作为新关节层级、尺寸或运行时API的权威。暂停中的七段动画演示OpenSpec继续保留需求；只有本变更的纵向切片、替代视觉层和恢复门禁通过后才恢复实施。

## Risks / Trade-offs

- [基础几何阶段投入增加] → 只先覆盖六类代表结构，验证通用合同后再批量生成其它对象。
- [程序合同压制美术造型] → 合同只冻结功能尺寸、接口和活动边界；视觉槽内部的轮廓与细节仍由美术决定。
- [JSON、Prefab与文档三份状态漂移] → JSON是交换权威，Prefab和技术文档记录合同ID／版本并由工具校验指纹。
- [通用图系统过度设计] → 首阶段限制原语和组合节点，不做可视化节点编辑器，不允许任意脚本节点。
- [编辑器工具跨项目GUID丢失] → 使用版本化清单、固定meta、干净导入和重复导入验证。
- [测试Provider与真实玩法差异] → P0-016必须通过AutoEra Adapter接入代表性真实状态，演示数据不能替代最终贯通。
- [运行时性能不明] → 单Rig单执行器、距离分级、不可见停更；用Profiler证据冻结最终预算。

## Migration Plan

1. 将现有ART-004／005中“模型先于程序原型”的条款标记为被本变更覆盖，保留历史证据但停止继续量产可动模型。
2. 建立Motion Core／Editor边界、合同schema和确定性Builder，并先用基础几何完成纵向切片。
3. 完成自动结构／动作测试及主工程、ArtResource工具包往返验证。
4. 导出首批 `FunctionalRigContract`，由主美据此更新技术合同和后续建模输入。
5. 正式模型替换视觉槽后重跑相同验收；失败时回滚到最后通过的原型和合同版本。
6. 纵向切片通过后，恢复七段动画演示和第一版其它模型的批量生产。

## Open Questions

- 可视化动作节点编辑器继续保持待定，只有代表性样机证明Inspector配置效率不足时才另建OpenSpec。
- 最终每帧Rig数量、距离分级阈值和CPU预算需在真实密度样机Profile后冻结。
