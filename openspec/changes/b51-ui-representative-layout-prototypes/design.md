## Goals / Non-Goals

**Goals:** 三种明显不同的结构构图；减少说明与重复摘要争抢焦点；真实对象信息和已有动作可达；形成完整合同、原型截图与用户验收记录。

**Non-Goals:** 正式美术/效果图/动效、真实 3D 预览制作、新增经营数据、经济成长功能、其它分辨率验收、框架核心修改、全量重建 UI。

## Decisions

### D1 分阶段推广
本 change 只实现代表原型；b52 的全量结构任务受用户验收门禁约束。正式视觉是后续独立阶段，布局通过不能写成美术完成。曾考虑一次性全量改造，因构图未经过用户体验评审而放弃。

### D2 三种构图
- 机器整备：保留宿主导航和其它两页。主体按左侧载体/就绪信息、中央机器展示占位、右侧可选槽位组织。展示占位明确标为后续资源，不冒充正式机器模型。安装/拆卸和卸载继续走现有确认及事务。
- HUD：五个常驻模块同时呈现，顶部紧凑状态、左上追踪、上部警报、底部导航与保存状态；右侧为机器现场检查，中心留世界。现场概况保留身份/能力与已有操作，未接线动作不因改版变可用。
- 中枢总览：一个主要概况区、一个运行摘要区、一个关注区，非等宽分栏；主要入口靠近所属区域，保留其它页导航。未接入信息显式不可用，不填假数值。

### D3 合同驱动、路径兼容
优先修改已有节点 RectTransform 和模板尺寸，稳定字段路径、UIViews、数据源及回调。新增展示和动效容器只含预制节点；不在运行时拼装整页。HUD 历史合同不完整，先从真实 Prefab 导出；通过现有生成器新增 ApplyExistingLayout(contract) 原位修改四个目标 Prefab，保留组件引用。布局文档从同一合同导出完整节点数据；合同与文档同步。

### D4 交互信息层级
简化面向玩家的长篇实现说明，保留必要操作提示与不可用原因。成功态不得遮住已加载内容。空态/不可用态保留安全返回；列表行模板 inactive、通过现有池生成。装饰不拦截射线，HUD 空白不拦截世界。

### D5 可扩展布局
1920×1080 唯一视觉验收。根 Stretch，边缘模块锚定相应边缘，内容容器按父区伸缩；图形占位保持比例。LayoutGroup 驱动节点不同时手工争夺位置。动画未来作用于独立子容器，避免破坏布局驱动。

## Risks / Trade-offs

- [读模型尚未覆盖部分概况] → 用不可用态评审真实入口，另外提供明确标注的编辑器结构预览；不能宣称完整经营体验通过。
- [全量重建覆盖其它进行中工作] → 只重建目标四份，保留当前工作区备份与非目标子树检查。
- [布局改动导致字段错绑] → 复用路径、合同门禁及导航/整备回归。
- [没有美术时物件区显空] → 占位说明本身是结构交付，不用临时伪成品规避验收。

## Migration Plan

0. 用户审阅本 OpenSpec；收到明确恢复实施指令前仅修改方案文档（已完成）。
1. 留存目标合同/Prefab 与截图基线，记录非目标页面子树摘要。
2. 更新合同、原型布局及最小展示脚本，定向生成四个 Prefab。
3. Unity 编译、合同/交互/导航回归、1080p 结构截图和实机检查。
4. 交用户评审；未通过只修代表工作区。通过记录日期、截图版本、意见关闭和范围，再解锁 b52。
5. 回退时仅从本批基线恢复本批涉及文件，不能 git reset 共享工作区。
