## Context

ART-001 已建立 `ArtResource` 作为美术源权威及跨项目交付合同，ART-002 已冻结“清朗拓荒工程”的明亮风格化中模视觉基线，ART-003 已选择 Terrain＋模块化＋手工英雄点＋编辑器生成视觉环境的混合场景路线。ART-004/005 需要把这些上游结论转化为可重复生产的建筑资产规则和可由程序状态安全驱动的机器／建筑机构表现合同。

本次方案由主美窗口经过多轮用户确认形成；后续前置效果图由独立3D原画窗口直接提交用户验收，主美负责冻结任务包及动态／关键装配对象的技术设计文档。独立美术项目负责结构、外观、Pivot、锚点、净空和表现参数，主工程负责玩法状态、导航、碰撞、IK／地形求解与运行时控制。ART-006 由独立 2D/GF-UI 工作流负责，本变更只约束世界内状态反馈接口。

## Goals / Non-Goals

**Goals:**

- 用一个模块化工坊／处理站建立可复用的 1m 网格、2m/4m/8m 跨距、骨架＋功能接口模块库和混合材质生产路线。
- 用一台四轮机器、滑动门和传送带验证统一程序化表现合同及安全中断。
- 以近中远截图、短动图／视频和性能读数建立可直观验收的纵向样机证据。
- 把未具备真实密度证据的数值保留为暂定预算门，并定义正式量产前的复核条件。

**Non-Goals:**

- 不批量制作第一版正式资源，不制作动物或敌人资产。
- 不实现 Motion Core／Editor、AutoEra Adapter、玩法状态机、完整物理车辆、完整碰撞 IK 或力反馈。
- 不让表现层决定通行、导航、碰撞、生产、存档或离线模拟结果。
- 不创建运行时随机地图，不逐栋雕刻 Terrain，不把 ART-006 UI 页面和 GF-UI Prefab 接入纳入本变更。

## Decisions

### 0. 建模必须经过批次化前置出图与用户分流门

每个生产批次先由主美冻结完整任务包，其中动态／关键装配对象必须包含基础尺寸、运动结构、接口和禁止改动项。3D原画默认按每个对象或资产族一套方案的方式统一生成轴测图并直接提交用户，不增加主美逐稿视觉审核。用户验收轴测图时同时筛选对象：结构复杂、模块化或可动对象进入结构一致的正／侧／俯三视图分支；被用户豁免三视图的对象进入简化生产说明分支，但仍须提供整体尺寸、落地点、朝向、主要材质分区和必要结构说明。

效果图的最低视觉精度以用户批准的`G06-formal-carrier-axonometric-v2-simplified.png`为基准，后续候选必须达到同级形体完成度、材质分区、功能细节可读性、接缝／边缘表达和画面清晰度。该基准不传播G06的具体造型；每个对象仍以自身任务包、功能和冻结结构为准。G01–G05、G07–G11的既有低精度轴测图仅保留为迭代证据，须按此基准重绘后才能作为建模参考。

用户通过轴测方案后，主美只为动态／关键装配对象补齐精确尺寸、关节轴与位置、活动范围、接口、`Socket_*`、`WorkPoint_*`和`KeepOut`。效果图负责轮廓、比例观感、色彩、材质分区和静态结构参考；技术设计文档是活动、装配和接口的生产权威。冲突时按职责分别取权威；若技术合同要求改变已批准轮廓、比例或可见结构，必须回退用户重新批准效果图。

用户批准轴测方案后，主美为每个对象提交技术合同，以及Blender、AI 3D或混合路线的推荐、风险、后处理成本和白模边界；制作人只对照已归档需求、批准效果图、对象清单与冻结任务包验收这两类文件。通过后该对象可直接开始白模，不再为技术合同和路线重复请求用户批准。三视图／简化生产说明可与初始白模并行，但进入中模／细节制作前必须完成一致性核对。若路线或技术合同改变已批准视觉、扩大范围或引入不可逆风险，仍退回用户。建模中若改变轮廓、比例、结构、模块关系或可动部件，回退轴测验收；只改变尺寸、轴点、行程、接口或结构标注，回退生产说明一致性核对；不改变外观和合同的拓扑、UV、LOD技术调整可自治处理并记录。

模型完成后，主美先独立对照该对象的功能需求、批准效果图、技术设计文档、装配关系和动作合同完成
结构自验；常规缺陷由主美直接返修，不请求制作人逐项验收或增加中转对话。除任务包或技术合同明确
批准悬浮、飞行、磁悬浮等特殊表现外，任何无可信支撑／连接／挂接／接触关系的可见对象、脱离主体的
游离散件或因Transform、层级、原点、导出轴错误导致的位置漂移，均为硬性失败，不得提交用户验收。

此前没有经过该门禁制作的3D模型全部退出交付链，只保留为失败迭代与技术研究证据。相关程序化算法和参数合同可复用为设计输入，但必须在替代模型上重新完成视觉与数值验收。

### 1. 工坊采用统一网格与骨架＋功能接口模块库

模块以 `1m` 为基础网格，常用跨距为 `2m/4m/8m`。首套库只覆盖地板、墙、柱、屋顶、转角、门、入口平台、管线接口、操作面板、状态灯和少量围栏。建筑主体保持水平基准，通过基础脚、台阶、坡道、裙边与填充件适配 Terrain。

选择该方案是为了在可组合性、俯视轮廓和首轮工作量之间取得平衡。逐栋定制会造成返修和复用成本过高；只做极少块体又无法验证正式视觉密度。

### 2. 材质采用共享混合路线

结构件与功能件各使用一类主 Trim Sheet，并配合基础平铺材质、顶点色、局部贴花或专属遮罩。英雄／标准／背景三级资产的起始贴图规格分别为 `2K/1K/512` 或共享材质。默认采用“单资产单主材质＋多功能贴图”：每个完整资产在Unity使用一个主材质，可配置BaseColor、Normal、Metallic／Smoothness或Mask、AO和Emission Mask；此前按资产等级提供多个默认材质槽位的表达由本规则覆盖。复用收益明确时允许增加次级贴图页，但不得以每栋完全独立贴图取代共享规则。

状态灯、屏幕和能量窗优先使用同一主材质的Emission Mask，颜色与强度由Unity参数或程序状态控制。只有透明／半透明表面或真正独立动态资产允许拆独立材质，且必须记录职责与理由。Blender负责UV、材质分区和贴图烘焙，Unity负责最终Shader、材质参数和运行时反馈。

细节集中在入口、面板、接口、状态灯和正立面；磨损、积尘、热痕与维修标记按功能位置分布，大面保持清朗。轮廓、倒角高光、材质分区、功能色和贴花承担卡通化可读性，不采用全局描边。

### 3. LOD 与性能采用按资产等级的暂定预算门

英雄资产使用 `LOD0/1/2`，标准模块通常使用 `LOD0/1`，背景资产优先原生轻量。远距同步退出小部件、贴花、次要发光和阴影职责。首轮记录三角面、Renderer、draw call、SetPass、阴影和帧时间，但阈值、压缩、切换距离与 HLOD 只在代表区真实密度复核后冻结。

这避免所有资产机械套用同一 LOD 层数，也避免在缺少真实样本时伪造最终预算。

### 4. 可动资产采用六层统一程序化表现合同

合同分为可动结构、基础运动原语、环境感知、状态阶段、表现编排和细节反馈。美术提供稳定层级、Pivot、局部轴、关节限制、默认／安全姿态、`KeepOut`、`WorkPoint_*`、`Socket_*`、接地点与参数模板；程序提供权威状态、目标、地形／IK 求解、中断裁决和运行时控制。

全部核心姿态由程序化关节、线性／旋转原语和分阶段曲线驱动，不使用关键帧接管主体动作。统一运动语言为“预动作—加速—受控减速—轻微落定”，VFX 只能由阶段事件触发。

### 5. 轮式纵向样机验证贴地、重定位和作业稳定

机器采用四轮独立接地与悬挂、四点平滑车体姿态拟合、四轮独立转向，支持反向转向和低速蟹行。连续坡度暂定上限为 `35°`，台阶高度以轮半径为独立阈值；逻辑层裁决是否可通行。轮子按实际移动距离和接地状态转动，仅明确打滑状态允许空转。

大幅移动前必须收臂；低速蟹行只允许在效应器离开目标且处于净空内时保持有限对位姿态。作业顺序为对位、锁轮、放下独立地面探测的稳定支撑、展开机械臂；收回反向执行。目标不可达或净空不满足时进入“需要重新对位”，不得强伸或穿插。

### 6. 效应器、门和传送带使用可恢复的参数化序列

效应器装卸分为接口对位、解锁、旧件脱离、新件接入、锁定与状态确认，并只在安全阶段边界取消。滑动门支持单／双扇、`2m/4m/8m`、行程、速度、停靠点、状态灯和安全感应区；临时占用时减速、暂停并回弹／重开。传送带由皮带／链板循环、滚轮、装卸锚点、速度和效率共同驱动；堵塞时保留位置并受控减速，恢复后平滑继续。

### 7. 状态反馈采用动作、世界内标识和 HUD 摘要三层合同

绿／黄／红分别表达正常作业、对位／收回／等待、故障或中断，并始终配合图标、形状或闪烁节奏提供色弱冗余。状态灯仅位于局部功能区，日夜只调整亮度和可视距离，不改变语义。世界内反馈说明局部组件，HUD 只接收设施与问题类型摘要；ART-006 负责最终 UI 表现。

### 8. 样机证据先验证生产合同，再进入量产

固定机位覆盖近中远、平地／坡地／台阶、反向转向／蟹行／重定位、支撑／机械臂／装卸／中断、门／传送带及三层反馈。每项同时提供截图、短动图／视频和基础性能读数。代表性合同未通过前不展开正式批量资源。

### 9. G06允许使用独立、可回退的Play Mode验收预览层

已通过静态结构与材质导入自验的G06候选，可以在其独立验证场使用专用演示实例和仅Play Mode运行的
控制脚本，分段驱动四轮`Steer/Roll Pivot`与`CargoDoorMotionPivot`。预览默认自动顺序播放，
`Space`暂停／继续、左右方向键切换段落、`R`重置；停止播放、禁用组件或退出Play Mode必须恢复
绑定态。该控制器只拥有表现预览状态，不得修改V17/V18源FBX、正式玩法、导航、碰撞、存档、
旧验证对象或其它资产。

该预览层属于本ART-005生产OpenSpec的单资产结构／动作验收工具，不代表
`b03-parallel-program-art004-art005-animation-demo`已经开始或完成，也不得替代后者的七段内容、
三机位、验收叠层、全部替代资产依赖门和完整恢复证据。

## Risks / Trade-offs

- [前置出图增加首轮耗时] → 以生产批次统一出图，并允许用户对简单对象豁免三视图；用较低的概念阶段成本换取更低的模型返工成本。
- [取消主美逐稿审核导致视觉漂移] → 3D原画使用主美一次性冻结任务包并直接由用户批准；默认单方案批量出图控制成本。若后续持续出现漂移，再升级为主美审核链，而不是预先增加每张图的中转。
- [效果图与程序化结构冲突] → 动态／关键装配对象在出图前具备基础技术骨架，用户选图后由主美补齐精确合同；活动、装配和接口始终以技术文档为准。
- [模型外观完成但功能结构遗漏] → 主美在提交前独立逐项核对功能、装配和动作合同，自行返修常规缺陷；不把专业自检转交制作人。
- [位置错误产生悬浮散件] → 默认把无支撑悬浮、游离对象和明显脱离视为硬失败；只有任务包或技术合同明确批准的特殊悬浮设计可以例外。
- [旧模型研究结果被误认为仍已完成] → 保留证据但重开模型依赖任务，旧模型、截图和视频禁止进入正式交付与动画演示。
- [模块复用导致画面重复] → 通过功能性不对称、局部贴花／遮罩、英雄细节和实例轻微变化打破重复，同时保持共享骨架。
- [单主材质限制导致状态反馈复制材质] → 使用多功能贴图与Emission Mask划分反馈区域，由Unity参数或程序状态驱动；只有透明或独立动态职责允许拆材质。
- [程序合同过度依赖尚未实现的运行时] → 在 `ArtResource` 以参数化预览驱动器验证结构与阶段，不伪造玩法权威；后续由独立程序 OpenSpec 接入。
- [四轮贴地或机械臂 IK 视觉稳定但逻辑不可通行] → 明确逻辑层裁决优先，表现层只做有限平滑与姿态求解。
- [暂定性能门过松或过严] → 记录测试条件与观察线，正式量产前使用真实密度代表区重新 Profile 并允许调整。
- [世界内状态与 ART-006 UI 语义漂移] → 共享绿／黄／红和冗余线索合同；ART-006 只消费摘要，不重新定义机器状态。
- [单资产预览被误认为完整动画演示] → G06控制器只归入ART-005验收证据；七段完整演示继续受独立OpenSpec的替代资产依赖和全量验收约束。
