# Segment 14：G02–G11长周期生产合同

日期：2026-08-27

## 覆盖范围

按固定顺序处理九个组：`G02 → G03 → G04 → G05 → G07 → G08 → G09 → G10 → G11`。
G06白模已完成，材质／UV另行延期；G01白模已在V07收口。

每个G组对应一套“技术合同＋Blender路线”。组内有多个独立资产时，在同一套文档内分别列出
尺寸、结构、Pivot、接口、活动范围、正式／R&D边界、源文件、导出和Unity验证要求，不拆成数十套文档。

## 文档阶段

1. 主美按固定顺序编写九套文档。
2. 每完成一套即交制作人验收；制作人可依据已归档需求和批准参考图直接修正文档中的普通问题。
3. 文档阶段不得启动Blender建模、FBX导出或Unity验证。
4. 九套文档全部通过后，制作人才发出建模阶段放行。

## 建模阶段

1. 建模顺序与文档顺序一致。
2. 正式候选与R&D验证对象都制作白模；R&D对象只需满足结构和程序化验证，不取得正式视觉权威。
3. Blender源内按批准参考图为组件添加清晰的预览颜色，帮助检查部件职责、装配和可动关系；这些颜色不构成正式材质交付。
4. FBX只导出模型、层级、Pivot和必要非渲染锚点，不把Blender预览材质作为Unity正式材质导入。
5. 每组必须验证1 Unity单位=1m、权威根identity、轴向转换、父子层级、Pivot／接口、无意外悬浮和无游离散件。
6. 每组完成后主美暂停并提交制作人验收；制作人通过后才放行下一组，不连续跨组抢跑。

## 暂停与升级

普通结构、命名、尺寸、轴向、导出和证据问题由制作人直接裁决或修订，不要求用户参与。只有必须
改变用户批准的轮廓／比例／可见结构、任务范围或正式与R&D边界，或出现无法恢复的工具／数据风险时，
才升级用户决策。
