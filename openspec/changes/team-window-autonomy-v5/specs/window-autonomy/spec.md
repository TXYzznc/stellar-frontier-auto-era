# 窗口自治与协作

## ADDED Requirements

### Requirement: 自助恢复优先
窗口 MUST 在授权范围内自行排查和恢复暂时失败，并由窗口自行判断何时已无法完成。

#### Scenario: 工具暂时失败
- **WHEN** 编译、端点或测试暂时失败且仍有安全诊断步骤
- **THEN** 窗口继续自助恢复，不通知制作人等待已阅

### Requirement: 协作优先于制作人
窗口判断无法独立完成且存在明确专业目标时 MUST 先向目标窗口申请协作；目标不明或目标失联时 MUST 请求任务调度窗口路由。

#### Scenario: 已知协作目标
- **WHEN** 另一个专业角色明确能够处理剩余问题
- **THEN** 发起窗口直接申请协作并继续其它安全工作

### Requirement: 决策升级
仅当需要方向取舍、范围／优先级／负责人变化、新授权、无法解除的合同冲突或协作失败时，窗口 MUST 通知制作人并说明依据。

#### Scenario: 方案存在明显取舍
- **WHEN** 两个方案方向不同且无法由窗口依据既有合同裁定
- **THEN** 窗口暂停受影响部分并向制作人提交决策请求

### Requirement: 完成验收
窗口完成任务 MUST 登记 `result-ready` 并发送证据；制作人负责验收，窗口 MUST NOT 自行标记 `Accepted`。

#### Scenario: 任务完成
- **WHEN** 所有派发范围和验收证据已具备
- **THEN** 窗口登记 `result-ready` 并发送一次完整回传

### Requirement: 持续执行
任务未完成且仍有安全工作时窗口 MUST 保持 Active、租约和心跳，不因阶段边界、普通进度或等待已阅而停止。

#### Scenario: 阶段产物完成
- **WHEN** 当前阶段已写出产物但派发范围仍有后续安全步骤
- **THEN** 窗口继续保持 Active 并执行后续步骤
