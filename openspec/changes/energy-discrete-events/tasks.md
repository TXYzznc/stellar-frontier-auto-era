# 任务

## 1. 能源域与词汇表

- [x] 1.1 `EventDomain` 追加 `Energy = 5`。**追加在末尾**：取值会写进日志记录并可能落盘，
      插在中间会让旧存档里的记录改变含义。
- [x] 1.2 新增 `EnergyEventText`：事件种类的日志动作名、界面标签、原因与影响。
      生产侧与读取侧共用同一批常量——日志记录没有「事件种类」字段，读取侧只能靠动作名认回种类，
      两边各写一份字面量，改一处就会让「活跃／已恢复」与「持续时长」的配对悄悄失效。
- [x] 1.3 `EnergyEventKind` 六种：缺电停机／恢复、电量耗尽／恢复、燃料耗尽、负载首次超过供给。
      `RecoveryOf` / `StopOf` 给出配对关系（燃料耗尽与供电缺口没有恢复事件，如实返回 null）。
- [x] 1.4 `电量过低` 明确**不做**：文档没有给出「过低」的判据（无百分比阈值、无续航口径），
      自造一个数字会让这条记录变成实现侧规则。等设计给判据后再补。

## 2. 离散事件识别

- [x] 2.1 新增 `EnergyEventRecorder`（纯领域对象，不依赖 Unity、不写日志）：`Capture(快照, 设施, 列表)`。
      不放进 `EnergyGrid`——结算每帧都跑，记账不该成为结算的一部分。
- [x] 2.2 缺电停机／恢复：以「被停机集合」的进出为判据（与停机顺序无关）。
      **同一次停机只记一条**：每帧记一条会让环形缓冲几分钟内被冲干净，历史变成噪声。
- [x] 2.3 电量耗尽／恢复：0 与非 0 之间的跨越。**第一次结算不算跨越**——
      没有储能设施的区域不记这类事件，「一直没有电」不是「刚刚耗尽」。
- [x] 2.4 燃料耗尽：每台燃料设施各自只在「从有到无」的那一次记一条；补上燃料后重新武装。
      燃料只存在于设施实例里（快照没有它），所以这一类事件必须读设施当前状态。
- [x] 2.5 负载首次超过供给：以 `HasShortfall`（缺口没能被任何可停机对象吸收）由假变真为判据，
      而**不是**「负载 > 发电」——后者在夜里只要储能补上就天天发生，记成事件等于把正常供电说成故障。
- [x] 2.6 `Reset()`：区域重建后清空上一次的状态，避免跨场景沿用。

## 3. 记账

- [x] 3.1 `AutoEraEventService.PublishNotice(domain, source, action)`：记录**自发事实**。
      没有命令触发、没有关联链（电网停机不是某条命令的结果，硬造关联 Id 会污染追溯链），
      也不经过事件总线（第一版没有订阅者）。追溯查询会如实回答「没有可追溯的关联链」。
- [x] 3.2 `InitialRegionScene.AdvanceEnergy` 顺序固定为「先对账 → 再结算 → 再落结论 → 再记账」：
      记录描述的是这一次结算的结论。没有事件服务的世界（单元测试、离线推演）照常推进电网，只是不记账。
- [x] 3.3 `Release` 时清空识别器状态。
