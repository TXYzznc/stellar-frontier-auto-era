# Agent 协作指南

主对话是 orchestrator；agent 是受本次授权与职责约束的专业执行角色，技能清单仅为推荐。

## 是否拆分

只有任务包含可独立交付的职责边界、明确依赖或显著并行收益时才拆分。单文件
修改、局部诊断、线性任务和高度内聚的实现保持单 agent。

## 编排规则

1. 每个子任务必须有明确输入、输出、文件所有权和验收标准。
2. 有依赖时先产出契约或骨架，再启动下游实现。
3. 并行任务不得修改同一文件或共享可变状态。
4. 主对话负责合并、冲突处理和最终验证。
5. 用户未明确要求子 agent、委派或并行时，不启动 sub-agent。

## 交回主对话

agent 仅在下列问题使下一步无法安全执行时暂停受影响部分：

- 缺少必要授权或输入，或共享资源存在无法解决的冲突；
- 需要未授权的范围扩大、公共合同修改或不可逆决策。

技能推荐之外的能力可以使用，不因此停止；缺少MCP先检查可用等价路径。
讨论不设最低轮数。实际发送所需的外部请求并检查结果，继续其他已授权安全工作。

## 共享状态

多 agent 共享工作区，因此每个 agent 必须保留他人改动，不得回滚、覆盖或
重新格式化无关文件。实现型 agent 必须声明文件所有权。
