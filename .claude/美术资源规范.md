# 美术资源技术规范

本规范只描述入库和运行时技术约束，不定义题材、角色、场景或视觉内容。

## 交付信息

每项资源必须声明：

- 文件格式和色彩空间；
- 尺寸、透明度与通道用途；
- pivot、网格、边距或切片规则；
- 目标平台与压缩策略；
- 导入设置和运行时用途；
- 来源、许可和可修改范围。

## 2D

- 避免无意义透明边界。
- 图集必须记录 padding、extrude、旋转和裁切策略。
- 像素资源使用与目标一致的过滤方式。
- 法线、遮罩和其它辅助纹理必须在名称或索引中声明用途。

## 3D

- 坐标系、单位、朝向和缩放必须统一。
- 模型必须声明拓扑、UV、材质槽、LOD、碰撞和骨骼约束。
- 导出前清理隐藏对象、无效材质、重复网格和未使用数据。
- 模型完成后由3D执行／主美窗口先独立对照功能需求、技术设计和装配／动作合同完成结构自验；
  常规自验失败项由该窗口直接返修，不请求制作人逐项验收。
- 除技术合同明确批准的悬浮、飞行、磁悬浮或等价特殊表现外，所有可见部件必须具有可信支撑、
  连接、挂接或接触关系；无支撑悬浮、游离散件和位置漂移属于硬性失败。
- 默认采用“单资产单主材质＋多功能贴图”：每个完整资产在Unity中使用一个主材质，可配置
  BaseColor、Normal、Metallic／Smoothness或Mask、AO、Emission Mask等贴图。
- 状态灯、屏幕、能量窗优先复用同一主材质的Emission Mask；发光颜色与强度由Unity材质参数或
  程序状态控制，不为每种状态复制材质。
- 只有透明／半透明表面或真正独立动态资产允许拆分独立材质；每个例外必须声明职责和原因。
- Blender负责UV、材质分区和贴图烘焙；Unity负责最终Shader、运行时参数与状态反馈。

## UI 与字体

- UI 资源必须声明九宫格、状态变体、最小尺寸和安全区约束。
- 字体必须记录许可、字符覆盖、fallback、atlas 生成参数和裁剪策略。
- 不在框架基线提交页面效果图、内容图集或预生成文本样例。

## 验收

- Unity 导入无错误；
- 引用完整且无重复 GUID；
- 压缩和内存预算满足目标平台配置；
- 资源在目标材质、渲染管线或 UI 系统中行为一致；
- 源文件与生成物边界清晰。
- 3D资源已通过功能结构自验，且不存在未获批准的悬浮、游离或错误脱离对象。
- 3D资源默认只有一个Unity主材质；所有额外材质均属于已记录的透明或独立动态职责例外。
