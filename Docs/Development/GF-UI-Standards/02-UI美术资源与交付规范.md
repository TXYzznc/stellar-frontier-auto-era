# UI 美术资源与交付规范

## 视觉系统

**原型阶段不使用正式视觉系统。** 界面先从原型出效果图（见 [03](./03-Prefab与RectTransform规范.md)
的「原型阶段与效果图阶段」）：AI 用结构期中性 token 配色、命名明确的占位 Image 和零假数据交付
结构/功能/布局正确的原型；用户再以该原型为基准制作效果图，此时才定义正式视觉系统。

正式视觉系统必须在美术替换阶段开始前定义色板、字号层级、间距单位、圆角/描边/阴影规则、
图标网格、状态色和危险色。它们应以 token 命名，而不是把颜色值散落在 Prefab。

- 主/次/危险/成功/警告/禁用色都有文本对比度和非颜色区分方式。
- 标题、正文、说明、数字和按钮至少定义五级字号；同一项目字体来源与 TMP Font Asset 唯一。
- 图标在最小显示尺寸仍可区分；不把文字缩小到不可读来迁就图标。
- 九宫格面板和按钮需保留明确的非拉伸边框区，中心区域可扩展。

## 源文件与导出

- 源文件保留可编辑图层、命名、导出切片与版本记录；运行时只引用导出的 PNG/Sprite。
- 透明资源使用正确 Alpha，避免把底色烘焙进透明边缘。
- 不导出含本地化文字、按键名称或动态数值的图片。
- 图集只作为生产源；切片完成前不得把整张图集当正式组件背景。
- 每个资源登记用途、尺寸、状态、九宫格边界、导入设置、资源键和替代规则。

## Unity 导入要求

- UI 纹理类型为 Sprite (2D and UI)，Clamp、无 Mipmap；压缩与最大尺寸以视觉验收为准。
- 面板/按钮使用 Sliced，图标通常使用 Simple；是否 Preserve Aspect 必须在 layout 中明确。
- 不同状态资源的画布、透明边和九宫格边界必须一致。
- 资源路径和运行时键由项目 Asset Catalog/资源系统提供，Prefab 不硬编码磁盘路径。

## 交付包

每批美术交付包含：资源清单、源文件位置、导出资源、切片说明、导入建议、视觉稿、已知缺口和验收截图。缺失资源使用可替换 Image 占位，不能伪装为已完成资源。
