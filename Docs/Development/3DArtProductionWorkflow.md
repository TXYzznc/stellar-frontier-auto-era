# 3D美术前置出图与建模工作流

本工作流适用于项目内所有新建、重制或发生结构级返修的3D资产。它约束Blender、AI 3D建模工具和
两者混合生产；任何专业窗口不得以灰盒、技术样机或赶进度为由绕过用户视觉验收门。

## 核心原则

- 3D生产按美术OpenSpec或明确生产批次推进，不要求第一版所有资产一次性完成设计。
- 同一批次必须先冻结完整对象清单，再统一完成清单内全部对象的轴测视图。
- 轴测与生产图由`AutoEra｜3D原画`制作并直接交用户验收；主美提供冻结任务包和关键技术设计文档，
  不承担常规逐稿视觉审核。
- 用户决定哪些对象需要三视图、哪些进入简化生产说明，并批准轴测视觉方案；主美随后提交技术合同
  与建模路线，由制作人对照已归档需求和批准效果图验收，不再为这两类文件重复请求用户批准。
- 未完成对应前置门的对象不得启动Blender、AI 3D或混合建模。
- 用户维护的`第一版开发任务表.xlsx`始终由用户手动修改，AI只提供状态更新建议。
- 当前项目效果图的最低视觉精度以用户批准的
  `G06-formal-carrier-axonometric-v2-simplified.png`为基准：形体完成度、材质分区、功能细节可读性、
  边缘与接缝表达、画面清晰度不得明显低于该图。该基准只约束表现精度，不要求其它对象复制G06造型。

## 强制流程

1. **冻结任务包**：主美记录对象ID、名称、职责、尺度基准、所属资产族、结构依赖、是否可动、
   预期交付和禁止改动项；动态／关键装配对象同时提供基础尺寸、运动结构和接口约束。
2. **统一轴测出图**：3D原画为清单内全部对象生成结构可读的轴测视图；同一资产族必须使用一致的
   风格、比例和结构语言，并达到当前冻结的效果图视觉精度基准。默认每个对象或资产族只提交一套
   方案，只有用户要求时才追加候选。
3. **用户轴测验收与分支筛选**：用户确认造型、比例、模块关系和可动部件，并逐项标记“三视图”或“简化生产说明”。
4. **技术合同补齐**：主美依据用户通过的方案，为动态／关键装配对象补齐精确尺寸、关节轴与位置、
   活动范围、接口、`Socket_*`、`WorkPoint_*`和`KeepOut`；静态对象只保留最低尺寸与落地信息。
5. **建模路线建议**：主美或建模执行窗口为该对象推荐`Blender`、`AI 3D`或`混合`，说明理由、
   风险、后处理成本、首个白模边界和禁止改动项。
6. **制作人合同验收**：制作人只对照已归档需求、批准效果图、对象清单和冻结任务包，核对技术
   合同与建模路线是否覆盖功能、尺度、结构、接口、边界和DoD；通过后该对象可直接进入白模，
   不再把这两类文件送用户重复审批。只有路线改变已批准视觉、扩大范围或引入不可逆风险时才回退用户。
7. **生产说明并行出图**：
   - 三视图分支：制作结构一致的正视、侧视、俯视和基础尺寸。
   - 简化分支：补充整体尺寸、落地点、朝向、主要材质分区和必要结构说明。
   生产说明可与初始白模并行，但必须在进入中模／细节制作前完成一致性核对；若它改变轮廓、比例、
   可见结构或技术合同，立即暂停受影响对象并按回退规则处理。

三视图／生产说明不得在步骤6通过前提前下发或生成。主美完成技术文档只表示可提交制作人验收，
不构成3D原画开工授权；制作人通过后，下发方才可把对应生产图任务写入3D原画Pending队列。
8. **建模与技术交付**：只对制作人验收通过的对象使用指定路线；完成拓扑、UV、材质、LOD、Pivot、锚点、导出和Unity验证。
9. **主美独立结构自验**：模型完成后，主美必须先逐项对照对象功能需求、批准效果图、技术设计文档、
   装配关系和动作合同，确认当前结构能够承载全部预期功能。该步骤属于主美常规专业职责，自行检查、
   自行返修和记录，不请求制作人逐项验收，也不额外增加制作人对话。
10. **直观验收**：只有通过主美结构自验的模型才能提交。提供固定机位截图或短视频、预期效果和必要
   性能／合同证据；未通过则按回退规则返修。

预览相机、固定取证机位及仅用于构图的 `CameraAnchor` 不属于运行时资产合同，默认不作为模型、
锚点或资源交付的硬性验收门。除非任务包或技术合同明确声明其参与运行时玩法、镜头系统、程序接口
或必须复现的自动化取证，验收只要求它能产出可读证据，不检查其精确位置、旋转或朝向。

## 默认禁止无支撑悬浮

- 除非批准效果图、任务包或技术合同明确要求悬浮、飞行、磁悬浮、全息投影等特殊表现，所有可见
  对象和部件都必须具备可辨识且可信的支撑、连接、挂接、嵌入或接触关系。
- 无任何支撑而悬在空间中的对象、脱离主体的游离散件、应相接却存在可见缝隙的装配件，以及因
  `Transform`、父子层级、原点或导出轴错误导致的位置漂移，均属于硬性验收失败，不得以构图、
  临时摆放或“后续再调”为由提交。
- 合法悬浮必须在任务包或技术合同中明确说明其功能原理和视觉反馈；仅凭外观猜测不构成例外。

## 效果图与技术文档的权威边界

- 效果图负责轮廓、比例观感、色彩、材质分区和静态结构参考，不作为精确工程数据来源。
- 主美技术设计文档负责动态／关键装配对象的尺寸、关节、活动范围、接口和空间合同。
- 两者冲突时，活动、装配和接口以技术文档为准；纯静态外观以用户批准的效果图为准。
- 技术合同若要求改变已批准轮廓、比例或可见结构，必须回退轴测图重新取得用户批准。

## 分层生产图要求

- 机器与活动机构：部件拆分、旋转／移动轴、行程、极限姿态、默认／安全姿态、`Socket_*`、
  `WorkPoint_*`、`KeepOut`和接地点。
- 模块化建筑：基础网格、规范尺寸、拼接边界、入口、门窗、功能接口和可替换模块位置。
- 静态自然物与装饰：轮廓尺寸、落地点、朝向和主要材质分区。
- 遮挡严重或结构复杂：追加局部剖视图、爆炸图或结构放大图。

## 建模路线建议边界

- **Blender优先**：严格尺寸、模块拼接、机械关节、精确Pivot、可替换接口、可复用套件、严格拓扑／UV／LOD合同。
- **AI 3D优先**：结构约束较弱的静态不规则物、自然散件和装饰候选，且允许后续清理拓扑。
- **混合优先**：AI用于基础形体或候选探索，Blender负责结构校准、重拓扑、尺寸、Pivot、UV、LOD和导出合同。

这些只是执行窗口的推荐依据，不能替代用户逐资产批准。

## 材质制作与运行时职责

- 默认采用“单资产单主材质＋多功能贴图”。每个完整资产在Unity中只使用一个主材质，按需要配置
  BaseColor、Normal、Metallic／Smoothness或打包Mask、AO、Emission Mask等贴图。
- 状态灯、屏幕、能量窗和类似反馈区优先通过同一主材质的Emission Mask划分；颜色、强度、闪烁或
  状态切换由Unity材质参数、MaterialPropertyBlock或程序状态控制，不为每种状态复制材质。
- 只有透明／半透明表面，或在层级、运动和生命周期上确属独立资产的动态部件，允许拆分独立材质；
  例外必须在资产合同中说明职责，不得仅因制作方便增加材质槽。
- 共享Trim Sheet、平铺材质和材质模板仍可被多个资产复用；“单资产单主材质”约束的是单个完整资产
  的默认Unity渲染材质职责，不要求每个资产创建唯一材质副本。
- Blender负责UV、材质分区、贴图烘焙与导出数据；Unity负责最终Shader选择、材质参数、透明排序和
  运行时反馈。Blender中的预览节点只用于制作校对，不是最终Shader权威。

## 返修回退规则

- 改变轮廓、比例、结构、模块关系或可动部件：回退轴测图并重新取得用户验收。
- 只改变尺寸、轴点、行程、接口或结构标注：回退三视图／简化生产说明并重新验收。
- 仅拓扑、布线、UV、LOD等不改变已批准外观和技术合同的调整：执行窗口可自主处理，但必须记录。

## 旧资产与失败迭代

- 被用户判定不可用的模型不得继续作为正式交付、量产基线、宣传图或动画演示输入。
- 默认不立即删除旧文件；保留为失败迭代、问题复盘和程序化技术研究证据，并明确标识`Deprecated`或等价状态。
- 可复用的算法、参数和安全合同只能作为重制输入，必须在替代模型上重新完成视觉与数值验收。

## Definition of Done

一个3D对象只有同时满足以下条件才可标记完成：

- 属于已冻结批次清单；
- 轴测图通过用户验收；
- 用户已批准轴测视觉方案并选择三视图或简化生产说明分支；
- 技术合同与建模路线已由制作人对照归档需求验收，生产说明与白模不存在未解决冲突；
- 主美已独立对照全部功能需求和技术合同完成结构自验，发现的问题已经返修；
- 除明确批准的特殊悬浮设计外，不存在无支撑悬浮、游离散件、错误脱离或明显位置漂移；
- 默认使用一个Unity主材质并具备完整功能贴图清单；额外材质均有透明或独立动态职责证明；
- 模型、材质、Pivot／轴向、锚点、LOD和导出合同通过技术检查；
- Unity目标观察条件下的直观验收通过；
- 证据、已知限制和返修记录已归档。
