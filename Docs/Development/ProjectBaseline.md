## 第一版范围边界

第一版只实施任务表和第一版规格索引明确纳入的能力。战斗、实际探索、通信调度、维修、跨区域能源和高级调度不在第一版提前实现；完整表述和最终入口隐藏要求以[第一版开发路线总览](../GameDesign/05-开发计划/第一版开发路线总览.md)为准。

需求、范围和依赖已经确认不代表实现方案已经确认。每个 OpenSpec 必须先讨论实现方式和大方向设计，提交目标、方案、边界、验收和约束的决策摘要，并在用户明确确认后才能创建 artifacts。并行 OpenSpec 使用相同的 `b<两位序号>` 批次号，但必须分别确认。

## 任务表权限

`Docs/GameDesign/05-开发计划/第一版开发任务表.xlsx` 只能由用户本人修改。AI、Agent、SKILL、脚本和自动化工具永久只读，不得编辑、覆盖、另存替换、重算回写或更新其中的状态、实际工时、依赖和备注。开发产生的调整只能作为建议交给用户手动处理。

## 框架与产品代码边界

- `Assets/Game/ScriptsBuiltin/` 是 GF_X 框架核心，禁止写入或依赖自动纪元产品业务。
- `Assets/Game/Scripts/` 的既有内容是框架通用扩展、热更新程序集入口和项目接入边界。
- `Assets/Game/Scripts/AutoEra/` 是自动纪元产品代码根；产品类型必须使用 `AutoEra` 或 `AutoEra.*` 命名空间。
- 产品代码按业务领域组织，只有对应任务进入实施时才创建目录；不预建完整空骨架，不创建无功能占位类型，不预设杂物型 `Common` 目录。
- 产品代码继续编译进现有 `Hotfix` 程序集。新增或重命名 asmdef、调整 HybridCLR/Obfuz/FSR 配置必须另行讨论并建立变更。

## 资源与 GameData 边界

当前仓库只承载一个游戏产品。模型、材质、贴图、Prefab、场景、动画、VFX、音频和 GameData 沿用现有资源类型根目录及框架接入规则，并在其下按业务类别组织；除产品代码根外，不机械增加名为 `AutoEra` 的项目目录层。

独立美术项目的坐标、比例、命名、锚点、材质、贴图、动画、VFX 和导出包合同由对应美术 OpenSpec 单独确认，不由本基线提前定义。

## 开发与验证

```powershell
python tools/audit_framework_purity.py
python tools/audit_project_boundaries.py
```

- 框架纯度审计负责领域无关框架、Agent/SKILL、禁止内容、构建场景和生成物边界。
- 项目边界审计负责 `AutoEra.*` 目录/命名空间、`ScriptsBuiltin` 反向依赖、冗余资源目录和本基线入口。
- Editor Play Mode 内仅有小范围方法体迭代可以使用 FSR；字段、序列化、泛型、依赖、目录和程序集等结构变更必须退出 Play Mode 后通过普通 Unity 编译验证。
- 每个 OpenSpec 的完成证据以其 specs、tasks、自动化测试、Unity 状态和审计结果为准；不得仅凭实现意图或无报错推定完成。
