# 固定窗口注册与自动派发

本协议把Codex任务通信作为派发单的传输和状态监控层。派发单、OpenSpec、提交与验收证据
仍是正式事实来源；窗口消息不替代项目文档，也不改变用户维护的任务表。

## 工作模式

采用“首次注册，后续自动派发”的模式：

1. 用户创建长期职能窗口，或明确要求制作人创建指定窗口。
2. 窗口使用固定标题`AutoEra｜<职能>`，并建议置顶。
3. 制作人把窗口的`threadId`、`hostId`和项目绑定写入本机注册表。
4. 制作人创建派发单并登记批次边界后，先写入`TaskQueue.md`定义的目标职能队列。只有目标窗口
   空闲且没有Active任务时才发送简短启动消息；窗口运行中时不得发送普通新任务消息。
5. 专业窗口在派发边界内自治，直接询问用户并点对点同步受影响窗口；只有命中强制升级事件
   或整个派发批次完成时才联系制作人。
6. 所有Git提交请求直接发送给`git-integration`窗口；普通提交不发送制作人。
7. 制作人在协调回合存续期间通过窗口等待能力接收回传；回合结束后的事件由专业窗口的
   主动跨窗口消息重新唤醒制作人任务。
8. 窗口失效或无法定位时自动降级为手动派发，不阻塞项目文档流程。
9. 通知与执行解耦：普通状态无需专门通知用户；非决策型消息即使发送给制作人或协作窗口，也不得
   触发暂停或等待。只有缺少决定、授权、资源交接或冲突裁决会阻止下一安全步骤时才进入等待。
10. 自然阶段边界或单次回复结束不代表派发任务暂停；任务未完成且下一步安全、已授权、无真实资源
    冲突时，窗口必须自动续接下一执行段，不能只报告“下一步”后进入空闲。
11. 执行状态必须与界面一致：仍在工作的窗口保持回合运行，不得先结束回合再声称后台工作。长耗时
    工具、编译、渲染和短时跨窗口协调在同一回合内等待并定期报告进度；仅派发完成或真实阻塞时结束。
12. 每个窗口只保留一个Active任务。新独立任务进入持久Pending队列，按优先级＋同级FIFO等待；
    完成收尾后自动领取下一项。只有`TaskQueue.md`列出的合法抢占事件可在安全检查点切换Active。

推荐固定标题：

| 职能键 | 窗口标题 | 默认项目／环境 |
|---|---|---|
| `producer` | `AutoEra｜制作人` | `stellar-frontier-auto-era` |
| `git-integration` | `AutoEra｜Git集成` | `stellar-frontier-auto-era` |
| `art-3d` | `AutoEra｜主美（3D）` | `ArtResource`，并可访问Blender |
| `art-concept-3d` | `AutoEra｜3D原画` | `ArtResource`，只进行前置视觉设计，不占用Unity／Blender |
| `art-2d` | `AutoEra｜美术（2D）` | 按任务使用主项目、美术项目或无仓库窗口 |
| `client` | `AutoEra｜程序（客户端）` | `stellar-frontier-auto-era` |
| `backend` | `AutoEra｜程序（后端）` | `stellar-frontier-auto-era`，后续可迁移到独立服务仓库 |
| `design` | `AutoEra｜策划（专项）` | `stellar-frontier-auto-era` |
| `qa` | `AutoEra｜测试` | `stellar-frontier-auto-era` |

## 注册表

- 结构模板：`WindowRegistry.example.json`。
- 本机实际文件：`.ai/dispatch/window-registry.local.json`。
- 实际文件被Git忽略，因为Codex窗口ID、主机ID和项目ID属于本机／账户状态。
- 制作人可以使用窗口列表修复失效ID，但只有标题、项目路径和职能都匹配时才能自动重绑；
  存在重名或歧义时必须让用户确认。
- 不把注册表写入`ActiveAssignments.md`，避免把临时平台标识混入持久化协作文档。

## 自动派发消息

自动消息只用于唤醒没有Active任务的空闲窗口。目标窗口运行中时，下发方只写持久队列，不发送
以下消息；窗口在当前任务收尾后自行领取下一项。

自动消息只携带启动所需的最小信息：

```text
你是 AutoEra 的<职能>窗口。请处理派发 <派发ID>。
先阅读 Docs/Development/Dispatch/Active/<派发ID>.md，执行其中启动检查；
正式事实以派发单和项目文档为准。不要自行扩大范围，不要修改任务表，只提交不推送；
Git提交标题、概要和正文描述必须使用中文。
在派发边界内自主推进，用户决定直接记录并同步相关窗口；每两轮讨论自行增量归档。
提交时向AutoEra｜Git集成发送精确请求。只有范围／依赖变化、未解决冲突、新授权、
共享资源异常、S0～S1或整个批次完成时才联系制作人。
非决策型通知发送后继续执行，不等待用户或制作人确认已阅；只有下一步确实依赖回复时才暂停。
```

制作人发送前必须确认：

- 派发单已经写入并登记到`ActiveAssignments.md`；
- 目标窗口注册有效且绑定到正确项目；
- 目录和高冲突单文件没有未交接冲突；
- 消息中的派发ID和文件路径完全一致；
- 需要驱动Unity时已定位当前使用窗口，并由相关窗口点对点完成交接。

## 主动回传与唤醒

专业窗口开始派发前，应从`.ai/dispatch/window-registry.local.json`读取`producer`、
`git-integration`和相关协作窗口的`threadId`／`hostId`。提交请求发送Git集成窗口；用户决定
影响其他职能时直接发送相关窗口。只有发生下列需要制作人采取动作的事件时才联系制作人：

- 任务范围、优先级、负责人、排期、OpenSpec编号／边界／依赖需要变化；
- 点对点沟通后仍无法消除的设计、文件、交付或验收冲突；
- Unity／DCC失联占用、目标项目异常或破坏性操作风险；
- 需要新增写权限、框架核心授权或任务表手动调整；
- Git集成窗口发现路径归属不明、只读文件混入或仓库异常；
- 发生S0～S1暂停事件；
- 整个派发批次完成，需要制作人组织验收与归档。

以下情况通常不向制作人发送消息，也不专门通知用户：

- 正常方案讨论仍在继续，且用户选择属于本窗口已获派发范围；
- 普通讨论检查点、单项用户决策，以及已经由本窗口自行完成的两轮增量归档；
- 开始工作、一般进度、阶段内测试结果、独立提交，以及无需制作人动作即可继续的分段完成；
- 仅希望制作人“知悉”，但没有明确请求动作、阻塞或中央状态需要更新。

制作人请求至少包含派发ID、事件类型、请求动作、当前验证结果和所占用资源。若没有明确的
制作人动作，应保留在专业窗口，不发送。发送成功后，专业窗口仍可在本窗口展示完整报告，但不得
把本窗口中的普通最终回复当作跨窗口请求。

中央占用登记、跨窗口资源知会、风险留痕等消息可以不要求决策。此类消息必须明确标记为
“非阻塞通知／登记”，发送后窗口继续执行所有不依赖回复的安全工作，不等待制作人确认。普通进度
无需通过这种例外上报。只有请求决定、授权、资源释放或冲突裁决，且缺少回复确实无法安全继续时，
才标记为阻塞并暂停受影响部分；未受影响的工作仍继续。

Git提交请求必须使用`GitIntegration.md`规定的合同。集成窗口成功后只通知原请求窗口；原窗口
在整个派发批次完成报告中统一列出提交号。

制作人在执行协调工作时可以保留目标窗口的等待游标，监听真正需要处理的请求；不持续收集普通
进度广播。等待只覆盖当前仍在运行的制作人回合；专业窗口的必要请求负责跨越空闲期重新触发
制作人。若跨窗口发送失败，专业窗口应明确告知用户需要手动通知制作人，不得静默等待。

周期性任务巡检只能作为低频兜底，不能替代上述主动回传，因为它存在轮询延迟，也不适合审批锁
这类即时协调事件。

## Unity项目绑定

| Unity项目 | 固定端口 | 使用窗口 | 路由要求 |
|---|---:|---|---|
| `stellar-frontier-auto-era` | `8090` | 客户端、测试；制作人只读核验时临时使用 | 优先使用cwd／项目名路由，跨项目时显式指定`--port=8090`或目标名 |
| `ArtResource` | `8091` | 主美（3D）、必要的2D／TA资源验证；3D原画不使用 | 跨项目时显式指定`--port=8091`或目标名 |

端口固定不取消工具独占。同一Unity实例在同一时段仍只能由一个窗口驱动；相关窗口点对点
确认交接，不要求制作人逐次登记。每次重要操作前应使用Unity Skills `health`或
`project_get_info`确认目标工程，发现端口与项目不匹配时立即停止。

## 自动化边界与降级

- 未经用户明确要求，制作人不自动创建新的用户可见窗口；只向已注册窗口自动派发。
- 用户明确要求创建窗口后，制作人应创建长期本地项目任务。需要共享当前Unity和工作区的
  窗口使用保存项目的本地环境，不使用隔离worktree来驱动已打开的Unity。
- `ArtResource`必须先由用户添加为Codex保存项目，才能自动创建以该目录为根的主美或3D原画窗口。
- 方案选择、视觉评审、用户验收和权限扩张继续等待用户决定，不自动代替用户批准。
- 自动发送失败、窗口正在处理不相关任务、注册表失效或目标项目不匹配时，制作人记录原因
  并降级为手动派发；不得把任务发送到“看起来相近”的其他项目窗口。
- 状态监控只用于收集完成、阻塞和待决信息，不以轮询结果自动修改任务表。
