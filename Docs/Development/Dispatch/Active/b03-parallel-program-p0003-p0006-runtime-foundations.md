## 2. 目标与范围

### 目标

收敛阶段0运行时基础的实现方案，使启动Procedure、永久实例ID、确定性世界时钟和项目
DataTable／Config／Language接入形成可共同实施、测试和验收的边界，再建立对应OpenSpec。

### 玩家或开发价值

为后续UI、实体、任务、离线推进和全部领域配置提供稳定启动顺序、身份、时间与静态数据基础，
避免各系统分别发明生命周期和数据来源。

### 范围

- `P0-003`：业务启动Procedure、Launch／FrameworkReady衔接、主菜单与第一版场景入口。
- `P0-004`：永久实例ID格式、生成策略、对象注册表契约、注册／回收／重载生命周期。
- `P0-005`：`TimeUtil`时间源抽象、世界时钟、同刻稳定排序、在线／离线共用推进接口。
- `P0-006`：项目DataTable／Config／Language目录、生成、加载登记、校验与错误语义。
- 四项基础之间的初始化顺序、依赖方向、程序集边界、测试替身和验收入口。

### 明确排除

- 不实现具体机器、建筑、资源、任务、经济或存档业务。
- 不建立发布后热更新或服务器权威时间服务；只保留未来替换时间源的接口边界。
- 不拆分、重命名现有`Hotfix.asmdef`，不修改HybridCLR／Obfuz发布策略。
- 不修改`Assets/Game/ScriptsBuiltin/`或任务表。

### 任务表完成定义

- `P0-003`：始终从Launch进入，AppConfigs只注册一个业务启动Procedure，重复进出不残留状态。
- `P0-004`：对象生成、回收和重新载入后引用不会串到其他实例。
- `P0-005`：世界时间持续推进且不受界面打开影响，同刻事件可稳定排序。
- `P0-006`：GF.DataTable／Config／Localization可读取项目数据，缺字段、重复ID和非法引用明确报错。

## 5. 待讨论问题

### 启动与生命周期

- 单一业务启动Procedure的状态边界、重复进入／退出语义和主菜单／第一版场景装配方式。
- 启动阶段如何等待项目配置、语言、对象注册表和世界时钟就绪，失败如何回退和诊断。

### 永久实例ID与注册表

- ID类型与序列化形式、生成位置、跨存档／对象池／场景重载稳定性以及测试可注入策略。
- 注册表是否按对象类别分区、重复注册／悬空引用／销毁后的错误语义和查询接口。

### 时间与离线

- `TimeUtil`的本地UTC、单调计时和未来服务器时间源职责划分。
- 世界时钟的精度、Tick／批量推进方式、同刻排序键、暂停语义、离线跨度校验与异常回拨处理。
- 哪些状态属于可持久化世界时间，哪些属于只在当前会话使用的表现时间。

### 配置与语言

- 项目表、Config和Language的物理目录、命名、生成代码边界和AppConfigs加载顺序。
- 缺字段、重复ID、非法引用、缺少语言键的启动失败／警告策略，以及EditMode校验入口。

### 公共质量边界

- 纯C#服务、MonoBehaviour／Procedure适配层和ScriptableObject配置各自职责。
- EditMode、PlayMode、功能验证中心与人工验收如何覆盖四项DoD。

专业窗口不得把需求已确认推定为实现方式已确认。每累计两轮讨论至少增量归档一次；
完整决策摘要取得用户确认后，才可创建或填写OpenSpec artifacts。
