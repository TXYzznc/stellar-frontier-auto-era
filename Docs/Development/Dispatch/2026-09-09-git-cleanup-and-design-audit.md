## Git执行边界

- 先逐类核对差异、所属批次及验证证据；本次用户授权审查整个主仓库，不限旧单条精确提交清单，但实际暂存必须逐路径明确。
- 保守清理：只移除能确认临时、重复、废弃且无引用依赖的过程文件；不能仅因文件名含Preview／Prototype／Evidence就认定垃圾。运行时依赖、正式源、关键验收证据及决策记录必须保留。
- 不确定归属／依赖的文件保留并回传疑问，继续处理其它安全变更，不因一项疑问挂起全部审查。
- 清理前列出精确绝对路径及原因，保存可恢复差异或移至仓库外的明确隔离目录；对新文件必须保留恢复副本后再移除。递归操作先校验绝对目标不越出具体文件／目录范围，禁止git clean、全局reset／restore及广泛递归删除。
- Unity资源保持.meta/GUID与引用一致；不得为获得干净状态而恢复已授权的正式资产迁移／退役。
- 框架核心改动必须核对已有精确授权，未找到则单独保留报告，不擅改实现。任务表及未授权xlsx不修改、不删除、不暂存；不能误撤用户手工表格变更。
- 不修复专业代码、不驱动Unity／DCC、不扩展功能。只提交已有证据支持且归属清楚的变更；缺验证则明确保留限制，不编造通过。
- 分逻辑批次精确暂存，检查cached diff及差异空白，中文提交，不推送、不切分支、不合并／变基／重写历史。
- 索引若有他人改动先辨明归属，不擅自清空。检测同路径正在被修改时仅暂停该范围并协调。
