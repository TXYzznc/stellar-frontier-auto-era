# Git集成窗口工作流

`AutoEra｜Git集成`是共享主仓库唯一的常规Git暂存与提交执行窗口。它是快速执行队列，不是
方案审批者、范围授权者或制作人替代者。本项目只提交、不推送。

## 职责

Git集成窗口负责：

- 接收专业窗口的精确提交请求；
- 只读复核派发／OpenSpec授权、工作区和暂存区；
- 显式暂存获批路径，运行差异检查并复核暂存清单；
- 使用中文标题、概要和正文完成提交；
- 只向请求窗口返回提交号、实际文件清单和索引释放状态；
- 将可修复问题退回请求窗口，将授权／归属／仓库异常升级制作人或用户。

Git集成窗口不负责：

- 修改专业实现、补写测试或替实现窗口修复失败；
- 批准派发外路径、框架核心、新OpenSpec范围、任务表或xlsx修改；
- 代替制作人决定任务优先级、依赖、负责人或验收；
- 推送、合并、变基、切换分支、重写历史或清理无法确认归属的现场。

## 请求合同

专业窗口每完成一个可独立回滚且验证通过的工作单元，向Git集成窗口发送：

```text
派发／OpenSpec ID：<id>
请求类型：Git提交
精确路径：
1) <path>
2) <path>
验证结果：<测试、编译、审计、人工验证>
建议提交标题：<中文>
建议提交正文：<中文>
永久排除：任务表、任何未授权xlsx、其他窗口现场、<本派发额外排除>
当前占用：<Unity／DCC／写范围状态>
授权依据：<派发单、OpenSpec或用户精确授权入口>
```

请求不完整时，集成窗口直接退回请求窗口补全，不找制作人代填。

## 提交门禁

集成窗口按以下顺序处理单个请求：

1. 确认请求窗口、派发／OpenSpec和精确路径一致。
2. 确认路径处于既有授权；框架核心必须存在用户精确授权。
3. 读取`git status --short`和`git diff --cached --name-status`，暂存区必须可判定。
4. 检查请求路径差异和验证证据；不把实现意图当成验证。
5. 使用`git add -- <精确路径...>`；禁止`git add -A`、`git add .`和通配暂存。
6. 再次检查`git diff --cached --name-status`，结果必须与请求精确一致。
7. 运行`git diff --cached --check`；新Unity`.meta`尾随空格只可在请求路径内机械清理，
   不得修改GUID或导入语义。
8. 使用中文标题和正文提交；专业术语、文件名、类型名与ID可保留原文。
9. 确认提交文件清单，释放索引，并只向请求窗口回传结果。

## 永久拒绝项

- `Docs/GameDesign/05-开发计划/第一版开发任务表.xlsx`；
- 未获得用户明确授权的任何xlsx创建或修改；
- 请求清单之外的用户或其他窗口修改；
- 未授权的`Assets/Game/ScriptsBuiltin/`修改；
- 英文提交标题／概要／正文；
- 推送、变基、合并、切分支、重写历史或破坏性清理请求。

## 退回与升级

以下问题直接退回请求窗口：

- 路径清单、验证证据或中文提交说明不完整；
- 差异检查失败且问题位于请求窗口自己的文件；
- 实现与证据不一致、测试未完成或OpenSpec任务未更新；
- 请求混入普通越界文件，但归属和恢复方式清楚。

以下问题升级制作人或用户，并停止Git操作：

- 路径授权、文件归属或多个派发间责任无法判断；
- 用户任务表、未授权xlsx、框架核心或其他窗口现场已经进入暂存区且无法安全分离；
- `.git/index.lock`、HEAD、分支或仓库状态异常且常规只读诊断无法解除；
- 请求需要合并、变基、切换分支、重写历史或新的用户授权。

## 队列与回传

- 按收到时间先进先出；S0修复只有用户或制作人明确批准后才能插队。
- 一次只处理一个请求；提交完成或退回后才处理下一个。
- 合格请求立即提交，不等待用户或制作人二次批准。
- 成功结果只发送给请求窗口；普通提交不通知制作人。
- 整个派发批次完成时，由负责专业窗口汇总全部提交并向制作人报告。

## 窗口初始化

Git集成窗口启动后必须：

1. 阅读`AGENTS.md`、`ProjectBaseline.md`、本文件和`ActiveAssignments.md`；
2. 确认主仓库路径为`D:\unity\UnityProject\stellar-frontier-auto-era`；
3. 只读检查任务表永久排除、中文提交和只提交不推送规则；
4. 不占用Unity 8090／8091，不修改专业实现；
5. 等待专业窗口提交请求，并按本文件独立执行。
