### 1.1 不再讨论的已确认原则

- 同一游戏版本的全局节点、运算和连接语言固定；硬件只实例化带类型的能力端点，不为农田/树木/效应器另建语言。
- MotionGraph 是动作表现图，不能充当玩家算法模型、求值器或存档。
- 世界不暂停。编辑草稿不影响已应用版本；应用失败不修改旧运行状态。状态、绑定、参数与模板版本分离。
- 持续数据和瞬时事件分离；输入至多一线、输出可扇出。强类型、单位、枚举家族与对象能力必须兼容；不做任意隐式转换。
- 不提供任意循环、递归、脚本、自定义类型、隐藏领域大节点、自动目标选择/重试/去重。受限格网运算继承DEC-176，不扩成通用集合编程。
- 机器任务、效应器队列、算力池各自有权威；行为改变世界，求值器只提交指令。货舱无主动动作端口。
- 算法有效性只有红/绿；正常忙碌、资源不足、超距、等待、取消、队列拒绝不自动变红。
- 第一版不做中枢跨机器算法、实际通信、断点、单步、伪造传感器事件、历史快照重放、模板外部导入导出。

### 图身份与存储

- 算法实例ID与可追踪节点ID使用既有永久ID体系；模板内节点局部键在创建实例时分配稳定节点ID，复制实例不共享运行状态/ID。重命名/移动节点不改ID。
- 连线以节点ID＋稳定端口键引用；绑定另存实际组件永久引用与目标引用，不靠槽序号或名称保存。槽位只是显示和候选过滤信息。
- 节点删除后保留被引用端点的失效描述/墓碑及红线，验证阻止应用；显式删除连线才移除它。不以清理孤儿线隐藏问题。
- 文档布局独立字段，节点坐标/排序不参与执行计划；保存/加载须有往返与规范化校验。未知版本明确拒绝运行，保留原始草稿供诊断，不静默降级。
- 推荐玩家图/模板用现有存档JSON序列化设施的专用DTO；系统模板以后从项目数据管线加载只读定义。这里不创建数据目录，不开放外部导入导出功能。

### 类型与单位

- 数值内部建议统一规范单位并显式校验：米、秒、资源单位、米/秒、资源单位/秒、湿度0–100等，湿度百分比不能直接与0–1生长进度互连。乘除使用固定获准量纲规则，不由玩家生成无限单位表达式。
- 常量对一个目标继承单位；同一常量多路连到不同单位时报告冲突，不随最后一次连线改写其它消费者。
- 枚举必须同域；对象引用到上位能力可兼容，反向需明确判断；无效动态目标作为值有效性和事件呈现。
- Soil/Crop/Tree只读结构经固定字段描述适配；按稳定ID关联，不按数组下标。受限选择单次只得一个元素，顺序/最小/最大/距离并列时使用稳定ID打破平局。具体类型清单与成本在规范收敛后编码。

## 5. 执行与服务接入

```text
传感器/恢复/参数/结果事件
 → 输入快照＋实例版本/绑定代次门禁
 → 受影响路径的纯执行计划与成本
 → MachineComputePool 等待/取得完整算力
 → 执行批次（状态写集＋行为指令待提交表）
 → 一次状态提交＋依序任务/行为入队
 → 释放瞬时租约＋诊断记录＋后续事件入队
```

1. 同一根批次锁定触发输入；等待期间新采样不可篡改它。仅允许持续值同源待处理合并；瞬时事件保序，32条上限，满队列产生明确拒绝/警告，不覆写旧事件。
2. 规划阶段只读快照、纯运算与影子状态，不能碰世界或占效应器；取得完整实际成本后一次执行。不得把计划预计算当已发生世界行为；稳定顺序按世界事件键/入队序号与节点稳定键，非屏幕坐标。分支依赖非法值则记录失败，零提交。
3. 验证数据依赖环和无异步边界事件环，输出完整路径；通过计时器、下一次采样或结果的循环在新批次推进，不递归调用自身。
4. 结果提交成功与否分别记录：队列Full是拒绝结果，不撤销成功求值；该拒绝后续入队而非同栈再次求值。默认任务上下文仅在第一世界行为时创建；继承事件链、延迟/冷却的任务ID，独立根事件不自动合并任务。
5. B14只从Sampled/Changed/TryRead接受有效读数，保存Generation/Sequence/目标与WorldTime；卸载/重绑/退出后丢弃旧代次回调。无效样本有Reason，不输出0湿度或假库存。传感器已持有的监测10算力不在算法层重复计费。
6. B13导航端点先通过MachineTaskQueue建立上下文，再调用Start；Ended转为不可变结果并下一批次发布。导航10/5成本由B13所有，算法只计自己的调用/计算节点成本。成功保留的作业点租约须明确交给后续行为或在链结束释放，不能只看到Completed就遗忘占用。
7. 生产效应器以后通过`EffectorBehaviorQueue<T>`与实际执行器适配；不能把MotionGraph播完当作产矿/浇水完成。固定旋转定位缺专门适配时报告未接入，不把它偷偷调用轮式导航。
8. 热路径采用已编译索引数组、复用写集/待提交缓冲、有限队列，不做每帧全图LINQ/装箱/字符串日志。性能验收测无事件时零求值、稳态每步分配、队列上限压力；预算需实测，不承诺未测毫秒值。

## 6. 草稿、安全应用和异常

- GraphDocument、AppliedPlan和RuntimeState三个所有者分离。编辑/保存草稿不会改变有效性灯、旧任务或机器运行状态。
- 应用请求固定DraftRevision与基线AppliedRevision、绑定/硬件版本；先全验证，再等待真实安全边界。等待时旧版本不能和新节点混用，重复点击返回同请求状态；后来的编辑保持新草稿，不能悄悄进入已接受请求。
- 安全点前再次验证硬件/固定引用/总逻辑成本，失败保留旧生效版本与新草稿。全份发布后，结构/连线/绑定改变只重置修改实例状态，其它实例保留；公开参数整组应用保留状态，并产生相关数据变化。
- 机器级重启/暂停与算法级禁用不要混成一个灯或一份队列。休眠/断电保留状态与计时剩余量，恢复按现行规则一次恢复事件，不补历史每次采样。
- 运行除零/非法数值/动态成本超上限等致命失败：丢弃本批次状态/指令，算法红色、停止新触发，取消本算法未开始请求并要求运行行为安全收束；保留货物责任与已发生变化，同机其它算法不受影响。
- 普通无路径/动态目标无效/忙碌/取消/资源不足保持绿，显示具体结果。客户端计时只显示等待较久，不自行宣布失败或重试。
- UI关闭仅解绑观察者，不取消已接受应用；明确取消操作只在允许取消的阶段接受，结果由服务报告。窗口重开读取当前请求/版本，不靠本地bool猜完成。
- 保存只在完整批次边界生成不可变DTO，记录草稿/生效修订、状态节点、计时、待应用请求、结果去重标记；先做内存往返与边界测试，正式磁盘/离线仍与相应阶段联合验收。

| 检查器 | BindingSlotId、候选永久ID/槽名、参数类型单位默认值、优先级、ExposeParameter | 不自动绑定；休眠与永久缺失分开 |
| 问题栏 | IssueCode、Severity、NodeId/PortId/BindingSlotId、MessageKey＋强类型参数、Revision | 点击定位；过期验证不覆盖新草稿 |
| 模板 | Id/Version、来源、用途、成本、能力/环境缺项；Instantiate/Copy/Save/Rename/Delete | 系统只复制；玩家删除不销毁既有实例；模板无灯 |
| 诊断 | RunId/AppliedRevision、TriggerTime/根因、节点路径、ThenValues、CurrentValues、Wait/Result/RequestId | 当时/当前明确标注；缺历史图修订不能拿新图错配旧节点；无断点单步 |

ApplyState建议：Editing、Validating、AwaitingWarningConfirmation、WaitingSafePoint、Applying、Succeeded、Rejected；算法Validity/RunState、编辑Dirty、服务请求State彼此独立。所有编辑命令携带ExpectedDraftRevision；长时应用另带RequestId。参数/文案不得退化为可执行任意字典。

保存模板只清除实例绑定和状态，不清除结构需求；缺必要具体绑定的模板可做结构验证，但实例应用仍必须完整绑定。模板选择后集中待绑定→画布检查→验证应用，第一版没有自动同步旧实例。
