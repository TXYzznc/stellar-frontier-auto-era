| 效应器组成 | 效应器定义固有动作与物理边界；目标、时机和参数由指令配置，兼容资源可变 | 效应器、指令、资源、UI |
| 主控中枢定位 | 作为不可攻击的抽象管理系统存在；汇总机器状态，并使用自身计算核心处理跨机器传感与效应器调度 | 自动化、UI、通讯、成长 |
| 机器激活与连接 | 机器必须在现场激活；激活后自动连接主控中枢；机器被破坏时断开连接 | 机器状态、现场交互、主控中枢 |
| 机器物理规则 | 机器差异由确定性配置约束；默认不模拟推动、倾倒、堆叠或受力姿态变化，只选择性使用具有玩法价值的物理计算 | 机器、移动、战斗、离线结算、性能 |
| 硬件修改与激活 | 硬件只能在机器停止后现场修改；修改完成后机器保持已激活，不要求重新进行现场激活 | 现场交互、机器状态、硬件配置 |
| 算法编辑形式 | 玩家使用节点连接图配置算法；节点端口具有明确类型 | 自动化、算法、UI、教学 |
| 节点连接语义 | 节点图同时支持持续数值连接和瞬时事件连接 | 算法、时序、算力、调试 |
| 自动行为归属 | 自动换弹等行为由节点算法实现；系统可提供使用相同规则构成的默认模板 | 效应器、算法、教学、模板 |
| 算法库 | 算法库保存不绑定具体设备的算法模板；应用到机器或中枢后由玩家手动绑定实际输入和效应器能力 | 算法、UI、机器、中枢 |
| 算法模板版本 | 修改模板不自动改变运行实例；玩家确认后可单台、分组或批量更新 | 算法、版本、批量管理、时序 |
| 算法有效性指示 | 算法库只保存结构有效模板且不显示指示灯；只有已创建的算法实例使用绿色/红色指示灯表示有效或异常 | 算法、UI、诊断 |
| 算法执行模型 | 采用响应式执行；数据变化或事件发生时只唤醒受影响节点路径，不每帧重算整张节点图 | 算法、算力、时序、性能、调试 |
| 硬件变更后的算法错误 | 保留失效算法并标红、停止其执行；不自动删除或绑定，也不阻止机器及其他有效算法运行 | 硬件、算法、机器状态、诊断 |
| 拓荒空间尺度 | 游戏主要发生在同一颗星球，玩家从前哨逐区域开辟不同生态环境 | 世界、区域、成长、内容规模 |
| 拓荒长期方向 | 前期以环境改造为目标，中后期通过实际机制形成继续改造、生态共生或折中路线 | 世界观、生态、成长、结局 |
| 冲突结构 | 采用环境、生态、系统三层压力；本土生物反应受到玩家拓荒行为影响，而非仅作为固定波次敌人 | 挑战、生态、自动化、区域 |
| 失败尺度 | 常规失败造成局部且可恢复的损失，不采用基地全灭或存档重置 | 长期经营、离线、公平性、维修 |
| 成长反馈 | 通过空间、系统算力、资源存量与净增速、玩家认知四个维度表现成长 | 中枢、HUD、经济、成长 |
| 探索连接权限 | 探索机器拥有完整中枢连接，中枢算法可以直接调用其效应器；代价是通讯接收与发送分别占用一个传感器槽位和一个效应器槽位 | 探索、通讯、中枢、算法、槽位 |
| 拓荒期连接 | 已探索但未拓荒区域的普通机器无法连接中枢，只能运行本地算法 | 区域、机器、中枢、挑战 |
| 信号塔持续职责 | 拓荒成功后信号塔继续维持区域网络；损毁不会取消区域归属，但普通机器断开中枢，重建后恢复 | 区域、建筑、中枢、维修 |
| 经营解锁 | 未拓荒区域禁止种植、采集和长期生产，只允许探索、前线建设和冲突处理；拓荒成功后解锁经营 | 区域、农业、资源、成长 |
| 拓荒狂化节奏 | 信号塔运行越久，狂化压力分阶段增强；拓荒完成前出现一次有明确预警的高峰，具体挑战内容和强度节奏另行设计 | 区域、生态、战斗、节奏 |
| 拓荒进度保护 | 进度条设置4个存档点；信号塔被摧毁时立即退回上一存档点，主动停止或断电时极慢回退至上一存档点 | 区域、信号塔、失败、UI |

## 优先讨论队列

### P0：决定第一版原型

1. 核心目标玩家与体验强度：轻度经营、自动化创造、策略危机何者优先？
2. 第一版指令交互形式：节点、积木、规则卡或行为列表。
3. 最小循环中的资源限制与冲突规则。
4. 原型成功的可观察验收标准。
5. 现场交互与主控中枢的操作权限、职责边界和状态同步规则。

### P1：决定完整循环

1. 在线玩法的主轴与离线公平性。
2. 作物、能源、防御和扩张之间的经济关系。
3. 本土生物采用波次威胁还是生态行为。
4. 成长解锁如何同时增加能力并降低管理负担。
5. 默认算力分配策略的具体规则，以及高级调度策略的解锁和教学时机。

### P2：决定包装与长线内容

1. 玩家身份与叙事视角。
2. 征服、共生或选择型主题。
3. NPC、贸易、社交和联网是否进入范围。
4. 终局、持续沙盒与更新结构。

## 尚未确认的关键约束
