## 增量归档规则

- 连续方案讨论每累计两轮，必须至少完成一次增量归档；重大边界、不可逆选择或
  跨项目契约确认后立即归档，不等待整组讨论结束。
- 每次归档至少记录覆盖范围、已确认结论、明确排除、待决事项和影响的任务／文档。
- 稳定结论同时同步到对应系统文档和[决策记录](决策记录.md)；当前完成度同步到
  [设计状态总表](设计状态总表.md)；未决事项同步到
  [开放问题与讨论顺序](开放问题与讨论顺序.md)。
- 增量归档只保存阶段性共识，不构成 OpenSpec artifact 创建授权。每个 OpenSpec
  仍须完成最终决策摘要并取得用户明确确认。

## 2026-08-20～2026-08-21：程序化动作管线检查点

### 已确认架构

- 第一版机器主体动作采用程序化刚性关节路线。机器从 Blockout 阶段即按可动部件、
  正确 Pivot／轴向、关节范围、Socket、作业点和安全姿态制作；不先做整机成品再切件。
- 管线核心抽象为“运动原语＋受控动作组合”。基础原语覆盖旋转、伸缩、瞄准、开合、
  持续旋转、往复和等待；组合支持顺序、并行、循环、条件等待和有限分支，不允许
  在动作资产中嵌入任意脚本。
- 玩法逻辑是唯一权威。动作管线只读取状态、阶段、目标与归一化进度并负责表现，
  不以动作播放结束决定产出、任务完成或存档结果；离线返回不补播历史动画。
- 机器主体使用运动学刚性关节：独立 Transform、局部轴、范围、默认姿态、速度和
  加速度限制。物理关节不负责主体驱动，逻辑根、导航和碰撞权威不随视觉关节移动。
- 动作具有准备、运行、完成、取消和恢复生命周期；同一关节通道独占，切换从当前
  实际姿态平滑进入新动作。中断策略按动作配置为保持、收回、归零或立即停止。
- 配置分为两层：Prefab 上的 `MotionRig` 绑定稳定关节 ID 与 Transform；独立
  `MotionGraphAsset` 保存动作定义。ScriptableObject 只保存静态配置，不保存运行状态。
- `MotionGraphAsset` 使用带版本号、稳定节点 ID、强类型参数声明、显式节点表与连接表
  的结构；不直接序列化场景 Transform、玩法组件或运行时状态。
- 动作参数通过强类型上下文注入；主项目 `AutoEra Adapter` 把真实玩法状态转换为
  参数，美术项目使用模拟上下文预览。动态目标传递 Pose 或目标提供接口，不在动作
  资产中保存业务场景引用。
- 每个 Rig 使用一个集中式 `MotionExecutor` Tick，不为每个关节建立 Update，不以
  协程或 DOTween Sequence 作为执行核心，运行热路径避免持续 GC 分配。
- 作业动作使用玩法状态／进度，待机、轮转、扫描和状态灯等纯表现循环使用本地表现
  时间；重进场景、对象池复用或离线返回时从当前玩法状态重建姿态。
- 表现按可见性与距离分级：近景完整求解，中景降频插值，远景保留关键姿态，不可见
  或卸载时停止表现 Tick；降级不得影响玩法、碰撞、产出和存档。

### 跨项目与首阶段范围

## 2026-08-21：项目功能验证中心第一检查点

### 已确认

- 建立一个长期使用的 AutoEra 项目级功能验证中心。以后每完成一个适合人工触发与
  观察的功能，都为其增加对应的按钮、配置项、执行结果和必要的重置入口。
- 验证中心采用单一 EditorWindow，同时服务 EditMode 与 PlayMode；每个验证模块声明
  自己允许或要求的运行模式，窗口根据当前 Editor 状态控制可用性。
- 各功能以独立验证模块接入，不把所有按钮和业务代码持续堆积到窗口主类中。
- 窗口使用 Unity Editor 的 `TypeCache` 自动发现验证模块，并按稳定元数据分类、排序；
  新功能只需新增模块，不需要同步修改中央注册表。
- 验证模块的临时／上次使用参数保存在开发者本地，不提交 Git；需要稳定复现与团队
  共享的标准配置可由用户主动保存为具名项目预设并纳入版本管理。
- 各模块自行声明验证环境：纯逻辑功能可直接执行，场景相关功能可使用当前场景或要求
  专用验证场景；运行条件不满足时，窗口必须禁用执行并说明缺失条件。
- 对当前场景的修改必须接入 Unity Undo；模块创建的临时对象必须提供明确的重置或
  清理路径，避免污染正在制作的正式场景。
- 验证中心属于 AutoEra 产品工具，只能进入 `Assets/Game/Scripts/AutoEra/Editor/`，
  不修改框架核心，也不进入 Player 构建。
- 验证中心用于快速人工验收，不替代 EditMode／PlayMode 自动化测试；面板调用正式业务
  接口或测试适配器，不复制一套业务实现。
- 验证中心只强制覆盖适合反复配置、主动触发并观察运行效果的程序功能；文档、纯资源、
  一次性交付管线、底层重构和不适合交互触发的任务不为满足形式而增加面板入口。
- ART-001 的资源交付合同、导入往返与 GUID／引用一致性属于一次性交付管线验证，保留
  现有验证场景、报告和证据，不迁入功能验证中心。
- 无论是否接入验证中心，每个完成的开发任务都必须向用户提供直观、可复核的验收结果：
  可视效果优先提供固定条件截图；适合用户在 Unity 中操作的结果必须给出查看入口、操作
  步骤和预期效果；不可视的底层结果提供测试、日志、报告或前后对比证据。
- 完成自动化检查不等于用户验收。交付时必须明确说明用户应看到什么，以及结果与任务
  验收标准的对应关系。

## 2026-08-24：GameData AI中间层纠偏第一检查点

- 新数据允许由AI先创建合法JSON，再由工具首次生成xlsx；随后继续沿正式GameData生成链产生

- 用户确认水枪正常完成后，关阀并待余下水流表现结束，再受限回到配置化休息姿态；取消、断电、抢占、缺水、目标失效和弹道受阻只关阀并保持当前受控姿态，后续请求重新预演。

### 已确认

- 人工林使用实际树木集合汇总资源状态，而非纯视觉代理；资源点只显示成熟树数量、可采集量和缓存，不显示逐棵生命值。
- 每棵树的`MaxHP`即当前站立高度，`HP/MaxHP`为砍伐值，不另设当前高度。高度按绝对高度的慢—快—慢曲线增长；未砍伐受伤树的`HP`以最大高度增长速度两倍恢复，最高不超过`MaxHP`。
- 所有效应器都有通用伤害数据，伤害为0时不能造成伤害。旋转锯盘可精确在设定的0%～25%砍伐值触发砍伐；其他效应器在该区间每次命中按稳定随机概率砍伐，25%为10%、0%为100%。
- 断裂高度与砍伐值线性相关，木材按倒下上半段长度结算。
- 用户确认第一版不为全效应器伤害增加命中方向数据。树的倾倒方向由稳定ID和砍伐序号可复现随机产生；锯盘只需在释放树干前退出接触净空，不控制倒向。
- 用户确认倒下上半段结算后保留对应高度树桩；树桩经内容配置恢复期原位转为幼树，`HP=MaxHP`重新生长。第一版不消耗种子或要求机械臂补种。
- 用户确认砍伐时使用真实上半段模型，以断裂截面为枢轴受稳定随机方向水平力倒下；刚体只做地面表现，不伤机器、不改导航、不作权威。落稳或安全超时替换为按通用木材数量分档的木材堆。
- 用户确认对象状态传感器绑定人工林时公开逐树`TreeGrid`；它是人工林资源点的结构化状态，不从属于锯盘。固定算法语言的受限格网运算从中选出`TreeRef`和工作面，再由本机已安装锯盘的切割动作消费该目标；不为锯盘或人工林另做节点语言。算法自动取得本机已安装传感器、效应器和中枢输入的强类型端口，只能调用本机已安装效应器的动作；玩家游玩过程中底层不变，后续版本才可正式演进语言。这保留硬件组合与节点连接的玩家自由度，不强制资源点界面逐棵展示或自动作出砍伐选择。
