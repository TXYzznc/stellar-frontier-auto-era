## 增量归档规则

- 连续方案讨论每累计两轮，必须至少完成一次增量归档；重大边界、不可逆选择或
  跨项目契约确认后立即归档，不等待整组讨论结束。
- 每次归档至少记录覆盖范围、已确认结论、明确排除、待决事项和影响的任务／文档。
- 稳定结论同时同步到对应系统文档和[决策记录](决策记录.md)；当前完成度同步到
  [设计状态总表](设计状态总表.md)；未决事项同步到
  [开放问题与讨论顺序](开放问题与讨论顺序.md)。
- 增量归档只保存阶段性共识，不构成 OpenSpec artifact 创建授权。每个 OpenSpec
  仍须完成最终决策摘要并取得用户明确确认。

## 2026-08-20：ART-001～ART-003 视觉与场景方案检查点

### 已确认

- `ArtResource` 是美术源文件与美术产出的唯一来源；主项目只接收可用资源并完成
  业务绑定，修改必须回流美术项目。
- 视觉预研先制作三组维度完整的候选方向，统一覆盖环境、机器、建筑、色彩与材质，
  经统一标准比较后选定或融合为一套正式视觉基线。
- `ArtResource` 建立独立 LookDev 场景，统一相机、灯光、后处理、尺度参照和资源
  展示方式；主项目只做最终接入验证。
- 本批次使用最小 `.unitypackage` 验证交付合同；正式量产阶段的长期同步方案另行设计。
- 场景路线使用同一代表性测试区轻量比较 Terrain、模块化、手工布景及混合方案，
  统一评估视觉、制作效率、复用、性能和运行扩展，再深化胜出方案。
- 总体风格确定为明亮、偏卡通化的风格化中模 3D：使用简化 PBR、清晰轮廓与
  功能色块，有必要细节但不追求写实微表面，不使用明显漫画描边作为默认方案。
- 第一版采用“人工固定玩法骨架＋编辑器程序化生成视觉环境＋烘焙后人工修整”。
  地表分区、植被、碎石和非交互装饰可程序生成；基地、道路、资源点和通行空间
  由设计确定。第一版不做每存档随机地图或无限区块。
- 美术生产采用模块化资产库与共享材质体系；DCC 可编辑源文件和 Unity 交付资源
  分离；单个资源按“概念／轮廓—Blockout—动作与接口验证—中模材质—LookDev—
  Prefab／LOD／导入”的阶段门禁制作。

- 精确环境密度、材质预算和生成工具参数在 ART-003 样片与 Profile 后确定。

## 2026-08-20～2026-08-21：程序化动作管线检查点

### 已确认架构

- 第一版机器主体动作采用程序化刚性关节路线。机器从 Blockout 阶段即按可动部件、
  正确 Pivot／轴向、关节范围、Socket、作业点和安全姿态制作；不先做整机成品再切件。
- 管线核心抽象为“运动原语＋受控动作组合”。基础原语覆盖旋转、伸缩、瞄准、开合、
  持续旋转、往复和等待；组合支持顺序、并行、循环、条件等待和有限分支，不允许
  在动作资产中嵌入任意脚本。
- 玩法逻辑是唯一权威。动作管线只读取状态、阶段、目标与归一化进度并负责表现，
  不以动作播放结束决定产出、任务完成或存档结果；离线返回不补播历史动画。
- 机器主体使用运动学刚性关节：独立 Transform、局部轴、范围、默认姿态、速度和
  加速度限制。物理关节不负责主体驱动，逻辑根、导航和碰撞权威不随视觉关节移动。
- 动作具有准备、运行、完成、取消和恢复生命周期；同一关节通道独占，切换从当前
  实际姿态平滑进入新动作。中断策略按动作配置为保持、收回、归零或立即停止。
- 配置分为两层：Prefab 上的 `MotionRig` 绑定稳定关节 ID 与 Transform；独立
  `MotionGraphAsset` 保存动作定义。ScriptableObject 只保存静态配置，不保存运行状态。
- `MotionGraphAsset` 使用带版本号、稳定节点 ID、强类型参数声明、显式节点表与连接表
  的结构；不直接序列化场景 Transform、玩法组件或运行时状态。
- 动作参数通过强类型上下文注入；主项目 `AutoEra Adapter` 把真实玩法状态转换为
  参数，美术项目使用模拟上下文预览。动态目标传递 Pose 或目标提供接口，不在动作
  资产中保存业务场景引用。
- 每个 Rig 使用一个集中式 `MotionExecutor` Tick，不为每个关节建立 Update，不以
  协程或 DOTween Sequence 作为执行核心，运行热路径避免持续 GC 分配。
- 作业动作使用玩法状态／进度，待机、轮转、扫描和状态灯等纯表现循环使用本地表现
  时间；重进场景、对象池复用或离线返回时从当前玩法状态重建姿态。
- 表现按可见性与距离分级：近景完整求解，中景降频插值，远景保留关键姿态，不可见
  或卸载时停止表现 Tick；降级不得影响玩法、碰撞、产出和存档。

### 跨项目与首阶段范围

- 主项目是动作管线唯一代码源。逻辑上分为无 GF_X／玩法依赖的 Motion Core、只在
  Editor 运行的 Motion Editor，以及仅主项目拥有的 AutoEra Adapter。
- Core 与 Editor 通过固定 `.meta`／GUID 的版本化 `.unitypackage` 发布到 `ArtResource`；
  美术项目只读使用，不修改工具源码。动作工具包与美术资源交付包分开发布。
- 首阶段以一台轮式载体、一个多关节机械臂和一个可替换效应器完成纵向贯通，覆盖
  待机、移动、转向、作业、取消、断电、安全收回、恢复、对象池复用和重进场景。
- 验收分为静态校验、EditMode 执行器测试、PlayMode 代表性样机、跨项目 GUID／引用
  验证和性能冒烟；精确并发数量与毫秒预算在真实样机 Profile 后确定。
