## 0. 背景与目标

- 将第一版场景从「混合路线＋单一确定场景」（ART-003 已冻结）改为「全场景程序化生成」方向。
- 三条动机：① 更贴合「持续拓荒」玩法的地图复用诉求；② 减少人工摆放工作量；③ 沉淀程序化生成知识。
- 设计推导：俯视角 3D、玩家不操作角色、核心是观察机器作业、上帝视角缩放 → 画面重「可读性、平面布局、地形为舞台非主角」→ 地形表现以「连续地表高度场」为主，不做需要立体纵深的地下结构。

## 1. 确定性与存档

核心性质：**程序化 ≠ 随机**，输出 = `f(seed, rules, module_library)`，可复现、可变化。

- **生成时物化**：已探索区域生成一次、固化，运行时只加载不重算，规避运行时重算对「种子＋算法版本＋资产版本」逐字节一致的高要求。
- **未探索区域 = 确定但未物化**：seed 全域确定其内容，探索时才生成＋固化＋建档，迷雾覆盖且不占资源；探索时机／顺序不影响结果，保证确定性离线结算。
- **物化分两类**：
  - 玩法层对象（资源点、建筑、道路约束）逐个物化为带**永久 ID** 的权威数据；
  - 装饰层对象（植被、碎石、远景）只存「种子＋参数快照」确定性重放或烘焙。
- **永久 ID 内容寻址**：`hash(seed＋类别＋区域坐标)`，不用生成顺序，避免生成变化导致 ID 整体漂移；玩家动态创建对象（机器、建筑）仍用运行时 GUID／自增。
- **存档三层分离**：种子（底座身份）＋生成器版本＋玩家增量（建造／状态）；世界＝不可变生成底座＋可变玩家增量层。
- **范式对齐《我的世界》**：确定性重放＋差异覆盖，未动区域靠确定性重算补全，玩家修改靠差异持久化；本项目在 MC 懒生成基础上叠加「已探索区域物化」。

## 2. 程序化边界（五层）

| 层 | 内容 | 程序化程度 |
|---|---|---|
| ① 地形起伏 | 连续地表高度 | 程序化（噪声高度图） |
| ② 地表分区 | 水域／农田用地／林地／矿脉区等语义分区 | 程序化＋硬约束（初始区域必含农田、人工林、矿脉、水域四类） |
| ③ 资源点落位 | 资源点位置 | 落位规则固定、坐标落到程序化地形 |
| ④ 建筑／基地落位 | 基地、建筑位置 | 落位规则固定、坐标落到程序化地形 |
| ⑤ 任务内容 | 引导、任务、算法 | 固定，不程序化 |

- 「功能对象固定」＝**落位规则固定**（相对格局稳定），绝对坐标 = `f(程序化地形, 固定规则)`，不硬编码坐标。
- **黄金原则**：引导／任务／算法通过对象**永久 ID** 引用定位，从不硬编码坐标；对象位置因此成为生成器的自由变量，玩法逻辑不随布局变化改写。

## 3. 美术实现方式

- 玩家可控机器为**地表操控**，不涉及钻洞／地下探索 → 体素（方块或 Marching Cubes）从第一版排除，作为未来地下玩法的预留项后置。
- 地表采用「**高度场 Terrain + 模块化程序化布景**」：Terrain 承接连续地表起伏与纹理分区／植被散布，模块化资产承接道路、平台、资源点硬边与可建造结构。
- 选型依据：俯视角下体素 3D 优势不可见而代价实付，高度场的「平」恰是俯视角所需；「程序化管合法，人工管好看」。

## 4. 算法选型

| 用途 | 算法 | 备注 |
|---|---|---|
| 地形起伏 | 噪声（OpenSimplex2 默认）＋ FBm 分形 ＋ 重映射 | 重映射＝高度曲线／排名归一化，解决 FBm 值向均值收敛 |
| 地表分区 | 阈值分带 ＋ 多通道噪声（高程／湿度／矿脉） | 多语义场叠加 |
| 资源点落位 | 泊松盘采样 ＋ 硬约束 | 最小间距 r 即资源点间距约束 |
| 模块化布景 | 波函数坍缩 WFC | 装饰性拼装，不承担玩法关键结构 |
| 矿脉／岸线 | Marching Squares | 连续场 → 干净边界（三维版 Marching Cubes 后置） |
| 植被 | L-system | 装饰层，正式作物／树木由用户提供 |

- **噪声库已探索**：项目内 `FastNoiseLite`（MIT，6 噪声类型＋4 分形＋细胞噪声＋域扭曲）＋ `NoiseGeneratorPanel`（编辑器工具箱面板，9 预设）。教学可视化脚本与噪声图位于 `_noise_explore/`（非项目资产）。
- 噪声演进理解：Value（标量插值，方向性伪影）→ Perlin（梯度抵消轴对齐）→ Simplex（单形，顶点最少）→ OpenSimplex2（无专利改进，默认）。

## 5. 玩法约束表达

约束必须翻译成生成器能算的**布尔判断**：

| 玩法约束 | 可计算判断 | 实现手段 |
|---|---|---|
| 可达性 | 从基地到每个资源点存在可通行路径 | 通行性网格＋洪泛填充(BFS) |
| 坡度 ≤ 35° | 相邻格高度差在阈值内 | 梯度计算，超限格子标记不可建 |
| 占地不重叠 | 两对象包围盒／占地形状不相交 | AABB 相交测试 |
| 资源点间距 | 任意两点距离 ≥ 下限 | 泊松盘最小间距 r |
| 水域临岸可达 | 候选格邻居含水域且自身是平地 | 邻域检查 |

- **生成顺序**（底层先满足）：① 地形（坡度／分区）→ ② 资源点（泊松盘候选＋占地＋间距＋临岸）→ ③ 道路／基地（连通性＋可达）→ ④ 装饰（泊松盘植被，避开玩法区）。
- **约束三层级**：① 后验过滤（生成后检查，不合格换种子）；② 硬约束（生成中排除非法候选）；③ 引导式生成（先长满足约束的骨架再填细节）。第一版用 ①＋② 就够。
- **「任何种子都能玩」＝ 确定性种子 ＋ 约束检查 ＋ 受控重试**：换种子是安全的（只是换一个确定的世界，不产生随机漂移）。
- 反直觉结论：玩法约束（可达、坡度、不重叠）天然可规则化，比美学约束更易程序化——这正是「固定内容靠规则实现」能成立的根本原因。

## 6. 模块化资产配合

- 复用模块化资产库与共享材质体系；单个资源按「概念／轮廓—Blockout—动作与接口验证—中模材质—LookDev—Prefab／LOD／导入」阶段门禁制作。
- 装饰实例（无玩法身份）与玩法对象（永久 ID＋权威数据）两套策略分离，装饰实例不逐实例建 ID。
- 单资产单主材质、Renderer 合并与实例化为性能前提（承接 ART-003 性能样片结论）。

## 7. 工具链与工作流

> **分工总纲：ArtResource 是「制作资源＋探索」的工厂，正式项目（主工程）直接使用资源。**

- 生成器走 Editor 工具：种子管理＋参数面板＋预览＋烘焙固化（生成一次，运行时只加载）。
- 噪声图工具：`NoiseGeneratorPanel`（工具箱 → 纹理工具）可直接生成预览；正式地形高度图用 FastNoiseLite 在生成器中调用。
- 美术分工：ArtResource 承担模块化资产制作与交付；主工程承担生成器实现与运行时接入；编辑器视觉生成按 `VISREG_*` 授权区与 `EXCL_*` 净空工作。
- 资源 PCG 制作归 ArtResource：地表材质（MaterialMaker）、岩石／矿石簇／晶体（Blender Geometry Nodes）、水体（shader）各自在 DCC／渲染管线制作，各自内置噪声，不依赖主工程 FastNoiseLite。
- 噪声图生成工具（FastNoiseLite＋NoiseGeneratorPanel）属主工程地形生成器，不迁移到 ArtResource；需共享的是「规则参数」（分带阈值、密度、净空 VISREG／EXCL、噪声参数）经文档／配置同步，非代码。
- 若未来需美术项目逐字节复现正式生成，按 ART-003 动作包先例将工具打包 `.unitypackage` 发布（美术项目只读使用），第一版不预做。

## 8. 性能与规模

- 承接 ART-003 样片结论：790 draw calls、390 阴影投射、无批处理 → 正式资产须 Renderer 合并、实例化（GPU Instancing）、LOD、阴影分级。
- 高度场用 Terrain LOD；装饰用实例化＋按密度分级；以独立 Player 在目标密度下重 Profile 为最终预算依据。
- 未探索区域不物化、不占运行时资源；已探索区域固化后按静态批处理／实例化优化。

## 9. 已确认 vs 待决

**已确认**：第 1～5 块核心结论（确定性、五层边界、Terrain＋模块化、算法选型、约束表达）；第 6～8 块为已触达但待细化的方向。

**待决／待细化**：

- 各层算法具体参数（噪声频率、octaves、lacunarity、gain、分带阈值、泊松盘 r 等）需原型调优。
- WFC 模块库与邻接表设计；泊松盘与 WFC 的工程落地方式。
- 生成器工具具体实现（Editor 生成器＋种子管理＋烘焙流程）。
- 引导／教学系统对「程序化布局」的适配细节（永久 ID 引用的具体接入点）。
- 正式 OpenSpec 的拆分与命名（本归档不构成创建授权，创建前仍须完成最终决策摘要并取得用户明确确认）。
