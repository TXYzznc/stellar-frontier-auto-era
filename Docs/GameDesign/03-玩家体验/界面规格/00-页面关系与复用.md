# 页面关系、复用与实现差异

状态：2026-09-19评审稿。具体页面的完整规格由[总索引](00-界面总索引.md)进入。

## 主要入口与返回

| 来源 | 动作 | 目标 | 返回时恢复 |
|---|---|---|---|
| 主菜单 | 继续 | 加载→离线结算→首次回归报告→世界HUD | 加载失败回原槽位；不静默恢复备份 |
| 主菜单 | 新游戏／选择进度 | 存档槽→新建／详情→创建或读取 | 原选槽位 |
| 主菜单／系统菜单 | 设置 | 同一个SettingsForm的三个分页 | 原来源和按钮焦点 |
| HUD | 中枢 | BaseCommandHubForm五页 | 世界选择；仍满足现场条件才恢复侧栏 |
| 中枢总览 | 运行／能源／待办／指标 | 对象与系统／能源二级页／待处理任务／统计 | 原卡片及筛选 |
| 对象索引 | 机器详情 | 中枢内远程机器详情 | 原对象列表 |
| 对象索引 | 定位 | 世界聚焦→有效现场侧栏 | 再开中枢保留原对象 |

| 仓库 | 出售 | ShopForm出售分页 | 原仓库与物品 |
| 任意页面 | 规则／确认／选择 | 模态Form或所属预制Overlay | 原输入、分页、滚动、选择及焦点 |

状态栏能源→能源系统详情；算力→对象列表过滤；警报→活跃警报列表；主线追踪→任务详情。上述按钮共享目标页面，不复制第二套业务。
日常补给入口建议放总览关注栏；作物知识入口建议放农田详情。这两个入口的具体位置属于本次集中验收方案。

## 中枢待处理任务与统计

已确认大方向：需要玩家处理的活跃警报、阻塞、主线目标、待领和安全等待归待处理任务；只读历史与长期汇总归统计。
主线进行中／可领取／已完成统一使用Quest阅读组件；中枢待办链接它，不重复保存任务状态。已完成主线保持在主线页面“已完成”，不挪到统计。奖励只在任务领取服务结算。
机器执行队列≠玩家主线任务≠待办聚合；它们有不同数据源和操作权限，禁止统一成可拖拽调度列表。

## 同一个Prefab内的页面

- BaseCommandHubForm：04六份页面规格（五一级页＋能源二级详情）、05远程机器详情，以及预制记录阅读子页。
- FieldHudForm：03五个常驻模块、05四个机器现场分页、06五个资源观察页、07八个建筑类型页；现场页互斥，HUD常驻。
- MachineLibraryForm：09两分页＋05整备。ComponentLibraryForm：09两分页＋详情。
- SettingsForm：声音／操作／显示性能；ShopForm：购买／出售／商品详情。
- WorkshopForm：三栏工作台与配方／队列／缓存详情。
- AlgorithmEditorForm：同一图画布支持编辑／诊断，公开参数为精简内容页。
- ProgressReportForm、OperationDialogForm用于职责一致的参数化阅读／确认；不是把所有业务放进Form，业务由调用方服务执行。

## 共享阅读组件的结构归属

RecordReadingView复用于独立RecordReaderForm、中枢统计、机器记录入口；QuestReadingView复用于QuestForm及中枢主线详情；ReportReadingView复用于ProgressReportForm及中枢回归历史；AlertReadingView复用于AlertForm及中枢待办。
这些稳定阅读子树可以抽为子Prefab，复用者均超过两页。每个宿主预先放入必要实例，不能运行时动态拼装页面。
其具体节点集合取对应15／18页面的Panel_Page*子树，子树内部名称保持不变，每宿主最多放一个同Key实例；宿主参数明确只读或可领取权限。
中枢通过Grp_PageHost切换预制阅读子树，不同时打开独立阅读Form。返回上下文由中枢保留，记录对象失效不关闭整座中枢。
通用操作确认由OperationDialogForm拥有；若现有中枢Overlay继续使用，必须映射17同一确认合同，且一次只有一个决策焦点，不并列打开Overlay和确认Form。

## 算法共用画布的模式映射

诊断文档的字段使用编辑器同一子树，具体映射：

| 诊断语义 | 复用节点 | 行为 |
|---|---|---|
| 历史运行列表 | List_AlgorithmEditorNodes | 节点库内容切为真实运行记录，不能添加节点 |
| 当时执行图 | List_AlgorithmGraph | 绑定历史版本图；同一图Item模板，禁止编辑 |
| 当时参数／结果 | List_AlgorithmEditorInspector | 只读，带记录时间 |
| 异常与原因 | List_AlgorithmEditorProblems | 定位当时节点／端口 |
| 模式与版本 | Panel_AlgorithmEditorToolbar | 只读历史标志；不显示假当前值 |
| 切换记录Record | Btn_AlgorithmEditorNodesRow | 行选择切换记录 |
| 前后步骤Step | 诊断模式控件（见13布局补充） | 只切换高亮和快照 |
| 定位Locate | 诊断模式控件（见13布局补充） | 失效对象只说明 |
| 回编辑Edit | Btn_AlgorithmEditorDiagnose | 标签变为“返回编辑”，恢复原草稿 |

诊断时Add／Edit／Bind／Validate／Apply／Template动作禁用或隐藏；Diagnose改为返回编辑。顶部编辑／诊断导航同样触发模式意图。图模型布局由单一GraphLayoutGroup负责；草稿图坐标与视图位置分开，撤销仅改变草稿。GraphLayoutGroup是设计提出的实现组件，不是声称仓库已有。

## 表单与控件状态细化

- 分类／筛选动作打开同一区域的预制选项列表模式，选择后回结果列表；选项由已有Item模板渲染，不新增运行时节点。返回先退出选项模式。
- Settings各档位采用布局补充的命名按钮组；声音滑条立即生效，恢复默认按当前分页。
- 参数行按类型切换预制数值输入／Toggle／枚举选项；无对应类型时禁用并报开发配置错误，不把未知类型当字符串写入。
- 页面读错／无权限态可以覆盖内容但保留关闭；单一分区为空不应抹掉其它有效分区，区域态同构组件绑定具体区域。页级状态组仅用于整个页面不可读取时。
- 按钮条件失效在当前焦点旁解释；确认窗口打开期间世界仍运行，最终提交必须重新检查对象和报价。

## 文档与未来原型的验收区别

用户本次验收可直接按页面ID提出修改；具体尺寸与新增布局暂不视作已冻结。随后实际原型应同步到实现契约文件，再做GF标准的L1—L4与1920×1080截图验证。
