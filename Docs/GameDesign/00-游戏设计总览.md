# 《星际拓荒：自动纪元》游戏设计总览

> 状态：核心框架已完成，等待第一版原型验证  
> 文档职责：说明游戏是什么、玩家做什么，以及主要系统如何形成闭环。

## 一句话概念

一款以单颗星球拓荒为背景的俯视角 3D 自动化经营游戏。玩家不直接扮演场景中的角色，而是通过组装机器、配置传感器与效应器、编写节点算法，让机器在持续变化的环境中自主生产、应对威胁并扩张基地。

## 核心体验

玩家面对的不是固定职业机器，而是一组受到物理结构、槽位、算力、环境和资源约束的通用机器。玩家需要理解问题、设计自动化方案、观察实际运行、诊断失败并持续优化。

游戏希望产生的核心感受是：

- “这是我设计出来的系统。”
- “机器能够运行，是因为我理解并解决了问题。”
- “同一个目标存在多种可行方案。”
- “基地的成长能够在空间、资源和自动化规模上被直接看见。”

## 核心差异化

游戏不以建筑布局、传送带连接或大型工业产线作为主要自动化表达。建筑物与资源点负责提供固定功能、资源、状态和问题；机器负责行动；算法决定机器如何观察、判断、协作和行动。

所有后续系统必须服务于机器组装、算法设计、调度和诊断。物流不再扩展新的独立概念，加工链维持当前方向，能源保持区域级简化模型，通信系统重点服务机器间及机器与中枢之间的信息与任务协作。详细边界见[核心差异化与基建边界](01-核心框架/05-核心差异化与基建边界.md)，通信规则见[通信与机器协作](02-系统设计/11-通信与机器协作.md)。

## 游戏形态

- 代号：《星际拓荒：自动纪元》。
- 空间尺度：一颗可持续探索和拓荒的星球。
- 表现形式：俯视角 3D。
- 玩家载体：没有必须在场景中移动的玩家角色。
- 玩家身份：亲自降临星球的星际拓荒者，职业背景为工程师；具体存在形式与降临原因待定。
- 时间形态：世界持续运行，玩家主要进行观察、配置、建设和干预。
- 时间规则：世界与现实时间关联，玩家不能暂停或减速；界面打开时继续运行。
- 开发条件：个人开发，策划、美术和程序由一人完成；每周约 20 小时开发时间，美术资源制作时间另计。

## 宏观核心循环

```text
观察基地与资源状态
→ 发现需求、瓶颈或外部威胁
→ 制造并部署机器与设施
→ 配置硬件、算法和算力策略
→ 机器自主执行与生产
→ 玩家观察、诊断和优化
→ 积累资源与能力
→ 探索未知区域
→ 建立信号塔并完成拓荒
→ 新区域接入基地，扩大经营范围
→ 遇到更复杂的问题
```

生产经营已经形成基础资源规则：木材、矿石、水和生物质必须由机器送入仓库后转换为全局余额，金币直接全局结算；农产品、专有材料、燃料和战利品等继续作为需要实体仓储与运输的物品。第一版配方、产量、成本、容量和动作数值已经完成并通过纸面联合审计。

## 核心系统

### 机器与自动化

所有能够被玩家下达指令进行控制的实体都属于机器。机器是具有实际空间形态、运动方式、结构能力、生存能力和槽位限制的物理载体，不是单纯的主板，也不按农业、战斗或工程职业分类。

机器通过传感器获取信息，通过计算核心提供逻辑容量和运行算力，通过效应器改变世界。玩家使用节点图编写算法，将信息、条件与行为连接起来。

游戏中的友方可交互世界对象只分为机器、建筑物和资源点三个互斥大类。玩家建造的农田仍属于资源点，不同时归为建筑物。

### 中枢与现场交互

现场交互负责激活机器、安装和替换硬件、调整实体配置、维修及超限改装。中枢负责查看已连接机器、编辑和下发算法、设置算力策略、查看警报与历史状态，并运行跨机器的中枢算法。

### 区域探索与拓荒

星球由多个区域组成。未知区域首先处于灰雾覆盖的未探索状态；完成探索后，玩家可以进入区域并建设前线设施，但不能进行正式生产经营。玩家启动信号塔并承受逐步增强的环境和原生生物压力，达到要求后区域拓荒成功并接入基地。

### 经营与成长

拓荒成功的区域解锁种植、采集和长期生产。玩家的成长通过可用区域、自动化规模、已使用算力与算力上限、资源存量与净增长速度，以及玩家对系统的理解共同体现。

玩家亲自完成商店购买、组件与载体养成、图纸和配方选择以及算法设计；机器负责持续生产、运输、维护和防御等重复世界作业。资源与解锁的核心边界已定，具体内容表和数值尚未完成。

## 冲突与失败原则

- 冲突主要来自环境、原生生物、资源限制和自动化系统自身的复杂性。
- 玩家扩张会改变原有生态，并产生需要处理的反馈。
- 失败应当可观察、可解释、可预防、可恢复。
- 失败以局部损失和阶段性退步为主，不以清空存档或不可恢复惩罚为核心。
- 拓荒信号塔会主动提高区域压力，并形成有预警的阶段性高峰。

## 长期方向

玩家早期以生存、建设和改造环境为主。随着能力增长，长期可能在继续大规模改造、与原生生态共存或采用混合路线之间作出选择。路线的具体系统表现和最终结局暂未完成。

勒米拉（星拓联目录编号XTL-061 b）是早期与中期的主要成长舞台。长期能力允许玩家冲出勒米拉并探索更多星球，但跨星球内容不进入第一版设计和开发范围。

## 第一阶段目标

第一阶段不是制作完整游戏，而是验证以下核心假设：

> 玩家配置简单节点算法，让机器自主解决生产问题，并通过观察、诊断和优化获得乐趣。

第一版体验从基础引导开始，经过自由经营、稳定能源、基础制造与探索准备，截止于探索机器通过能力检查并解锁首次探索。早期6～8周、120～160小时设想已经被冻结范围下的正式估算替代：程序1194～1866小时、美术资源468～730小时，合计1662～2596小时。具体范围见[第一版目标与范围](04-第一版/00-版本目标与范围.md)，执行路线见[第一版开发路线总览](05-开发计划/第一版开发路线总览.md)。

## 当前阶段

第一版设计基线已经闭合：内容、数值、算法、行为、容量、界面、存档、文案和灰盒规格均已有正式来源，并完成经济、能源、物流、成长与流程的纸面联合审计。

第一版166项开发任务、依赖、工时区间、程序与美术并行路线及阶段验收门已经建立。当前进入正式开发阶段：每批从任务表选择2～5项目标一致、依赖连续的任务建立OpenSpec，在OpenSpec中完成开发规格、测试场景、实现分解和重新估算后再实施。任务表只能由用户本人修改。状态与执行约束见[设计状态总表](90-设计管理/设计状态总表.md)和[开发执行约束](05-开发计划/开发执行约束.md)。
