# 系统关系总图

> 状态：核心关系已完成，等待第一版原型验证  
> 文档职责：定义主要系统的职责、边界与依赖关系。

## 核心实体

| 概念 | 定义 | 主要作用 |
|---|---|---|
| 玩家 | 进行观察、规划、配置和决策的主体，不对应必须在场景中移动的角色 | 建设基地、设计自动化、处理危机、推动拓荒 |
| 机器 | 由玩家配置并通过算法控制的物理载体 | 装配传感器、计算核心和效应器，执行本地算法 |
| 建筑物 | 具有固定基础功能、不装配机器三类槽位的基础设施 | 提供加工、连接、防护、储存、供能等固定能力 |
| 资源点 | 按生产模型保存或产生原料，并提出通用作业需求的生产对象 | 提供原料、生产状态和有限资源缓存 |
| 中枢 | 玩家全局管理界面与跨机器计算系统 | 汇总状态、编辑算法、管理策略、运行中枢算法 |
| 区域 | 星球空间和拓荒进度的基本单位 | 限制探索、建设、连接和生产权限 |
| 算法 | 由节点与连线组成的可执行规则 | 把传感器信息转换为条件、状态和效应器行为 |

## 系统关系

```text
环境 / 原生生物 / 资源
        ↓ 产生信息与压力
      传感器 ──→ 本地算法 ──→ 效应器
                      ↑
                  计算核心
                      ↑
玩家现场配置 ──→ 机器物理载体

已连接机器 ←── 信号塔 / 远程通信部件 ──→ 中枢
                                              ↓
                                  状态汇总 / 中枢算法 / 调度

建筑物 / 资源点公开状态 ──→ 对象状态传感器 ──→ 机器算法 / 中枢
本地机器通信请求 ──→ 范围广播与能力筛选 ──→ 机器任务队列

机器与建筑消耗资源并完成生产
        ↓
资源与技术能力支持探索和拓荒
        ↓
新区域接入基地并扩大生产空间
```

## 必须保持的边界

- 友方可交互世界对象只分为机器、建筑物和资源点三个互斥大类；建造来源不改变分类。
- 机器的用途来自物理结构和玩家配置，不来自职业标签。
- 建筑物不通过传感器、效应器和计算核心获得通用自动化能力。
- 资源点不属于建筑物；农田和人工林即使由玩家建造，也按照资源点规则运行。
- 防御塔属于机器，不属于固定功能防御建筑。
- 组件安装、拆卸和实体结构改装必须在机器停止后现场进行；已连接机器的组件与载体升级可以从设备管理界面发起，机器仍需先安全停止。
- 普通机器只有在已激活、未损坏且区域信号塔正常时自动连接中枢。
- 未拓荒区域中的普通机器只能运行本地算法；完整远程连接需要额外占用传感器和效应器槽位。
- 未拓荒区域不能进行种植、采集和长期生产。
- 算法库保存结构有效的模板，应用时必须重新绑定当前机器的传感器与效应器。
- 建筑物和资源点提供问题与固定功能，生产、运输、维护、防御和环境处理的主要行动由机器完成。
- 不将物流、能源和通信扩展为以传送带、管道、铺线或复杂网络拓扑为核心的独立基建玩法。
- 建筑物和资源点不直接连接中枢；机器通过对象状态传感器读取其公开状态，并通过中枢连接上传信息。
- 对象状态传感器只能读取对象明确公开的数据；土壤湿度、环境温度、敌人位置等环境或隐藏信息必须由相应传感器获取。
- 本地通信采用范围广播、能力筛选和任务优先队列，不要求玩家维护订阅表。
- 玩家不能直接命令机器执行播种、浇水、采集、运输、维修或防御等世界作业；正式作业由本地算法、中枢算法或通信请求产生。
- 世界进程与现实时间关联，不向玩家提供全局暂停或减速；界面和算法编辑期间世界继续运行。

## 已闭合但待后续细化的关系

以下关系的上位边界已经确认，具体内容、数值或长期规则在第一版或后续阶段细化：

- 能源、储存和物流的具体数值及第一版保留深度。
- 第一版资源、种植、生产、购买和制造的具体内容链。
- 原生生态如何对生产和拓荒产生持续影响。
- 长期改造、共存和混合路线如何改变系统规则。
