# 挑战、压力与涌现

> 状态：压力类别已明确，具体规则待设计

## 挑战来源

游戏采用“环境—生态—系统”三层冲突结构。三层压力随拓荒进度相互影响，而不是把挑战简化为固定波次敌人。

### 环境压力

- 温度、日照、水分、辐射、风暴或极夜。
- 某些条件会改变正常操作规则，例如高温时浇水效率降低或产生副作用。

环境压力主要通过新区域的温度、水分、辐射、光照、地形和特殊天气引入新的生产与生存规则。

### 本土生物压力

- 常规侵扰可由自动防御应对。
- 数量、类型、路线或行为变化会打破既有方案。
- 生物最好拥有生态动机，而不只是定期刷新的敌人。

本土生物压力由玩家的采集、农业扩张和环境改造行为动态影响。玩家可以通过驱赶、防御、研究、调整生产或尝试共生解决问题，为中后期的改造/共生方向分歧提供机制基础。

### 资源与效率压力

- 土地、能源、算力、机器人数量、维护材料和通讯能力有限。
- 玩家必须在生产、扩张、防御与冗余之间取舍。

### 内部复杂性压力

- 多条规则争抢同一单位或资源。
- 支援行为导致原负责区域无人防守。
- 局部优化引发全局拥堵、断供或能源崩溃。
- 这类由玩家方案产生的连锁后果，是目前最具差异化潜力的挑战。

系统压力随基地规模增加，重点表现为局部算力过载、供给中断、算法竞争、跨区域调度问题和机器损坏导致的连锁反应。

## 失败尺度

- 失败主要造成局部且可恢复的损失，例如作物减产、资源短缺、机器损坏、生产停摆或区域暂时失守。
- 常规失败不导致基地全灭、存档重置或长期成果全部清空。
- 玩家应能通过中枢报告、现场状态和算法执行记录理解损失原因，并通过维修、重新激活、调整硬件或修改算法恢复运行。
- 恢复过程应产生新的设计决策，但不能演变为重复、强制性的维护劳动。

## 涌现设计原则

- 由少量通用规则交互产生结果，避免为每个剧情专门写死脚本。
- 后果应可观察、可解释，并与玩家选择存在清晰因果关系。
- 意外结果既可以有损失，也应产生故事、信息或新策略价值。
- 系统需要允许冗余、保险和降级方案，让成熟玩家能主动管理风险。

## 示例事件链

```text
东区发现大量生物
→ 巡逻机器人发出支援请求
→ 西区机器人离岗支援
→ 西区防御出现空缺
→ 小股生物破坏灌溉设施
→ 作物缺水、产量下降
→ 玩家通过日志定位到“支援规则缺少最低驻防条件”
→ 增加驻防阈值或分级支援规则
```

## 需要避免

- 没有预兆、无法预防的随机灾难。
- 只靠提高敌人数值制造难度。
- 强制玩家频繁上线救火。
- 单一万能配置长期统治所有内容。
- 日志不完整，玩家无法判断损失原因。

## 开放问题

- 已确认失败以局部、可解释和可恢复的损失为主；第一版具体允许损失哪些资源、机器或设施，最低保护线是什么？
- 已确认信号塔拓荒具有分阶段增强与最终高峰；常态生态压力采用持续模拟、事件触发还是两者结合？
- 如何在“真实连锁后果”和“离线玩家公平”之间取舍？
