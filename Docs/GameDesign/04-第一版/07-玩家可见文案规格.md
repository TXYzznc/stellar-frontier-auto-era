# 第一版玩家可见文案规格

> 状态：核心文案与配置结构已完成；配图、最终润色和本地化不属于当前阶段  
> 文档职责：规定第一版教学、任务、规则按钮、警报和对象说明的玩家可见表达，避免程序临时拼接出互相矛盾的提示。

## 表达原则

- 先说明发生了什么，再说明造成的影响，最后给出玩家能采取的动作。
- 使用游戏内正式名词，不用“脚本、Bug、AI自己想办法”等开发或拟人化表述。
- 不把算法错误和世界阻塞混为一类：结构无效使用“算法异常”，资源、容量、路径和供电问题使用对应世界状态。
- 不替玩家给出唯一解。教学说明操作方法与观察入口，规则弹窗说明系统边界，算法优化仍由玩家完成。
- 同一警告只显示一个主要原因；详情页可以继续列出责任链和历史值。
- 数值必须带单位或对象，例如“矿石 5”“功率 60”“电量 240”，不能只显示孤立数字。

## 配置结构

通用规则按钮只绑定一个描述ID，并显示该ID对应的一段完整规则说明，不在运行时拼接多条规则。

```text
描述ID
标题
正文
关联界面
首次阅读标记
版本标签
```

警报与行为结果可以带运行参数，但只允许替换预先定义的占位符，例如对象名、当前值、上限、目标和持续时间。物品说明、规则说明和教学正文不读取其他界面的显示状态。

## 基础引导文案

### 引导一：认识现场操作

**标题：唤醒第一台机器**

你的初始农田已经具备一台待激活机器。将镜头移动到机器附近并选中它，打开现场面板。机器必须在现场完成首次激活；激活后会自动接入中枢。

**完成提示：**机器已激活。它现在可以运行本地算法，并在中枢中显示状态。

### 引导二：检查机器配置

**标题：机器由能力组成**

查看机器上已安装的传感器、效应器和计算核心。传感器取得信息，算法进行判断，效应器改变世界；计算核心提供算法所需的逻辑容量和运行算力。

**完成提示：**硬件检查完成。下一步为机器绑定可运行的算法。

### 引导三：应用基础算法

**标题：让机器照料农田**

从算法库应用“基础灌溉”和“农田基础作业”模板，并将模板端点绑定到这台机器的传感器、效应器和目标农田。模板保存结构，不保存具体机器和对象绑定。

修改节点结构后需要等待安全时机重启算法；只修改参数时，点击“应用”后将在当前行为安全结束时生效。

**完成提示：**算法运行正常。机器将根据农田状态自行播种、浇水、收获和清理。

### 引导四：观察一次完整生产

**标题：观察，而不是代替机器工作**

玩家不能直接播种、浇水或收获。观察农田阶段、实时生长速度、机器任务和算法诊断记录；需要调整时，修改算法参数并再次应用。

**完成提示：**第一批农产品已经收获。产物仍在资源点缓存中，需要机器运入仓库后才能出售或分类。

### 引导五：完成首次入库

**标题：把产物送入仓库**

为具有移动、货舱和机械臂能力的机器应用“固定路线运输”模板，绑定来源农田、目标仓库和运输物品。通用资源入库后转为全局余额，其他物品保留在仓库中。

**完成提示：**物资已入库。你已经完成一条生产与运输链，接下来需要把同一套思路应用到新的资源点。

### 引导六：建立第二条生产线

**标题：组装一台用途不同的机器**

在商店中选择人工林作业礼包或矿山作业礼包。礼包会把载体与组件分别送入机器库和组件库，但不会自动组装。安装计算核心、对象状态传感器、机械臂和对应采集效应器，部署后前往现场激活。

从算法库应用兼容的采集模板和固定路线运输模板，完成必要绑定。第二台机器需要对人工林或矿山产生有效采集贡献，并把本次产物送入仓库。

**完成提示：**第二种资源已完成首次入库。基础引导结束；后续学习目标将通过主线任务逐步开放。

基础引导不能跳过、不暂停世界、不提供重置。HUD常驻引导图标，点击后重新显示当前阶段的文字与配图。完成条件必须追踪第二台机器的实际采集贡献与对应产物入库，不能用已有库存绕过。

## 规则按钮描述

| 描述ID | 标题 | 正文 |
|---|---|---|
| RULE_MACHINE_ACTIVATION | 激活与运行 | 机器只能在现场完成首次激活。激活与通电是独立状态：休眠和断电不会取消激活；完全损坏会使激活失效，修复后需要重新现场激活。第一版正常玩法不会造成机器损坏。 |
| RULE_HARDWARE_SOFTWARE | 硬件与软件修改 | 安装、拆卸和超限改装属于现场硬件操作，机器必须先停止。算法结构与参数可以在现场或中枢编辑；运行中的机器继续使用旧配置，直到玩家点击应用并到达安全切换时机。 |
| RULE_COMPUTE | 算力与逻辑容量 | 逻辑容量限制能够保存和应用的算法结构，算力限制运行时能够同时处理的采样、判断和导航工作。效应器持续物理动作主要占用电能与硬件，不会仅因持续运行而持续占用算力。 |
| RULE_ALGORITHM_STATUS | 算法状态 | 绿色表示算法结构有效并可运行；红色表示算法存在不能继续执行的结构或运行错误。缺电、资源不足、效应器忙碌、缓存已满和等待算力都是正常世界状态，不会把算法变红。 |
| RULE_RESOURCE_VISIBILITY | 资源点信息 | 玩家在现场查看资源点时可以直接读取公开状态。机器算法要取得同一信息，必须安装并运行兼容传感器。作物最佳区间和完整作业资料只有在对应资料解锁后显示。 |
| RULE_RESOURCE_CACHE | 资源点缓存 | 产物先进入资源点临时缓存，不会直接成为基地库存。主动采集在空间不足时不会开始；被动产出在缓存满后仍会继续，超出部分直接损失。 |
| RULE_TRANSPORT | 运输与入库 | 运输能力由移动和货舱组成；安装机械臂后可以自主装卸。木材、矿石、水和生物质入库后转为全局余额，其他实体物品保留在当地仓库。 |
| RULE_WAREHOUSE | 仓库容量 | 仓库容量只计算仍作为实体保存的种子、农产品和材料。通用资源、组件和机器载体在入库时自动分类，不占用实体仓库容量。 |
| RULE_POWER | 功率与电量 | 功率表示当前发电或耗电速度，电量表示蓄电池中已经储存的电能。1功率持续1分钟产生或消耗1电量。中枢使用独立能源，不参与区域电网。 |
| RULE_GENERATION | 发电调度 | 免费环境能源优先供电，其次是已开启的燃料发电机，仍有缺口时由蓄电池放电。燃料发电机在额定范围内按真实需求输出；只有允许充电时才会额外为蓄电池发电。 |
| RULE_WORKSHOP | 制造队列 | 工坊同一时间制造一个配方。配方进入队首并实际开始时扣除资源；缺电、资源不足或输出缓存已满会暂停并保留进度。取消时按剩余进度返还可返还投入。 |
| RULE_UPGRADE | 升级 | 第一版升级立即完成，但需要等待机器当前行为安全结束并停止。中枢1至3级期间，基础升级的金币和通用资源成本享受50%扶持；升级投入不会提高回收价。 |
| RULE_DAILY_SUPPLY | 星拓联日常补给 | 每个存档每个现实自然日可以主动领取一次800金币。补给不累积、不补发、不提供经验；系统日期回拨不会产生额外领取次数。 |
| RULE_OFFLINE | 离线推进 | 世界在玩家离开后继续按实际离线时间推进，不设置8小时收益上限。系统只推进能够持续成立的工作，并在资源、容量、供电或其他条件阻塞时自然停止。 |

## 核心警报文案

| 代码 | 标题 | 正文模板 | 建议入口 |
|---|---|---|---|
| ALERT_POWER_SHORTAGE | 区域供电不足 | {区域名}当前需要{需求功率}功率，仅能提供{可用功率}。部分负载已按优先级停机。 | 打开能源界面 |
| ALERT_FUEL_LOW | 生物质不足 | 已开启发电机的剩余燃料预计只能维持{预计时间}。 | 打开能源界面 |
| ALERT_RESOURCE_OVERFLOW | 被动产物正在损失 | {对象名}缓存已满，新增的{物品名}无法保存。 | 聚焦对象 |
| ALERT_ACTIVE_CACHE_FULL | 作业等待缓存空间 | {对象名}没有足够空间保存下一次{行为名}产物，作业尚未开始。 | 聚焦对象 |
| ALERT_WAREHOUSE_FULL | 仓库实体容量已满 | {仓库名}无法接收{物品名}。通用资源、组件和机器载体不受此容量限制。 | 打开仓库 |
| ALERT_PATH_BLOCKED | 路径受阻 | {机器名}无法抵达{目标名}，已停止本次移动任务。 | 聚焦机器并查看路径 |
| ALERT_WORKPOINT_WAIT | 作业点正在使用 | {机器名}正在等待{对象名}的作业点。任务不会自动取消。 | 聚焦等待队列 |
| ALERT_MISSING_TRANSFER | 缺少资源转移能力 | {机器名}已抵达{对象名}，但自身和附近机器都没有可用机械臂。 | 打开机器配置 |
| ALERT_ALGORITHM_ERROR | 算法异常 | {算法名}已停止：{主要错误}。其他有效算法不受影响。 | 打开诊断模式 |
| ALERT_COMPUTE_WAIT | 正在等待算力 | {机器名}当前使用{已用算力}／{总算力}算力，{工作名}已进入队列。 | 打开算力队列 |
| ALERT_EFFECTOR_BUSY | 效应器忙碌 | {效应器名}正在执行{当前行为}，新请求已按优先级排队。 | 打开机器任务 |
| ALERT_TARGET_INVALID | 目标已失效 | {机器名}的任务目标{目标名}已经失效，任务已停止并保留责任记录。 | 打开任务记录 |

| ALERT_OFFLINE_BLOCKED | 离线期间发生阻塞 | {对象名}从{时间点}起因{原因}停止，未继续生成虚拟收益。 | 打开离线报告 |

同一对象、同一原因的警报在持续期间合并为一条并更新数值，不重复弹出。原因消失时标记“已恢复”，保留在历史记录中。

## 离线报告文本结构

报告标题使用“离线运行报告”，依次显示：离线时长、主要产出与消耗、完成的任务／制造／施工、首次阻塞、仍未解决的严重问题。重复生产按物品合并，不逐次列出。

空报告文案：**离线期间系统保持稳定，没有新的完成事项或未解决阻塞。**

结算失败文案：**离线推进未能安全完成。存档尚未写入本次结算结果，请重新进入或载入最近的安全备份。**

## 第一版范围外文案

第一版不编写实际探索、拓荒、战斗、损坏维修、动态通信请求、跨区域能源和高级调度的正式玩家文案。相关界面不得以“即将推出”占位进入正常流程；未开放入口直接隐藏，必要的版本终点只显示“区域探索已解锁，第一版内容到此结束”。
