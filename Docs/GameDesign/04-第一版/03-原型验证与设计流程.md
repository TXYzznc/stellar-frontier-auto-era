# 原型验证与设计流程

> 状态：作为后续设计工作的共同方法

## 推荐流程

### 1. 锁定核心

每次新增系统前回答：

- 它服务哪一种核心体验？
- 玩家通过什么行为使用它？
- 没有它，游戏会失去什么？
- 它与已有系统产生什么新互动？

### 2. 构建最小可玩循环

先验证一个小问题能否产生完整的“目标—行动—反馈—调整”循环，不要一开始构建完整科技树和内容量。

### 3. 五视角查漏

| 视角 | 核心检查 |
|---|---|
| 玩家能力 | 玩家能做什么、不能做什么？ |
| 系统反馈 | 玩家如何知道动作、状态和因果？ |
| 挑战压力 | 为什么需要使用和优化这些能力？ |
| 目标奖励 | 短、中、长期为何继续？ |
| 情感曲线 | 一次 Session 的情绪如何起伏？ |

### 4. 压力测试

- 查找万能解和无脑最优策略。
- 枚举规则同时触发、资源归零、单位不可达等边缘情况。
- 写出至少三个玩家可能分享的涌现故事。
- 检查失败是否可解释、可预防、可恢复。

### 5. 原型、观察、删改

- 先做灰盒和最小数据集。
- 观察玩家是否自然理解因果，而不只听取口头评价。
- 核心乐趣不成立时先改规则，不用美术和内容量掩盖。
- 每轮只验证少量明确假设。

## 第一阶段原型建议

### 验证目标

“配置简单规则并观察机器人自主解决问题”本身是否有趣、清晰且值得反复优化。

### 最小内容

- 单个小地图。
- 农田、作物、水源和一个环境变量。
- 一种机器人或自动设施。
- 少量传感器、计算核心、效应器和指令条件。
- 一种资源限制和一种规则冲突。
- 状态检查、简单事件日志和可回看的运行记录；世界不提供暂停或减速。

### 暂不加入

- 完整星球、复杂剧情、多人社交。
- 大型科技树和大量机器设备。
- 正式经济数值与长期离线结算。
- 大量敌人和完整生态模拟。

### 初步验收问题

- 玩家能否在无长篇教学下建立第一条有效规则？
- 玩家能否从画面判断规则是否生效？
- 当规则失败时，玩家能否定位原因并主动修改？
- 同一个问题是否至少存在两种有意义的解法？
- 系统稳定运行后，玩家是否会主动尝试优化或扩展？
