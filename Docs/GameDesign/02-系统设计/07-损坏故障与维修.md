# 损坏、故障与维修系统

> 状态：总体结构完整度与归零结果已确认；第一版只保留最小状态基础，不提供玩家损坏与维修流程

## 结构完整度

机器和可受损建筑统一具有“结构完整度”，作用类似传统HP。结构完整度用于判断实体是否仍能工作，以及归零后进入何种恢复流程。

第一版采用清晰的临界值规则：

- 结构完整度大于0：实体仍然存在，功能不因剩余比例直接衰减。
- 结构完整度归零：实体进入完全损坏或被摧毁状态。
- 低完整度可以产生外观变化、状态警告和维修提醒，但不添加隐藏性能惩罚。

### 第一版实现边界

- 机器与建筑配置保留结构完整度上限；机器实例保存当前结构完整度，存档和公开状态接口支持正常、受损与完全损坏。
- 完全损坏时仍按总体规则停止运行、断开连接并使机器激活失效，但第一版正常玩家流程没有任何伤害来源，因此不会自然进入该状态。
- 第一版不实现敌人、战斗伤害、环境伤害、随机故障、维修资源、维修时间、维修工具、玩家维修、建筑重建和损坏教学。
- 第一版不实现结构完整度比例影响性能。开发测试工具可以修改完整度，用于验证状态切换、存档和完全损坏结果。
- 普通玩家界面不长期显示永远满值的结构完整度条；只有对象实际受损或开发调试时才显示。以后加入威胁系统后再纳入中枢常规状态信息。
- 一级通用轮式载体结构完整度上限为100，二级为120；第一版建筑统一为100。开发测试下低于上限为受损，低于或等于50%显示黄色警告，归零进入红色完全损坏／被摧毁状态，但非零受损不降低性能。

## 机器损坏与恢复

```text
结构完整度大于0
→ 机器保持激活
→ 可以运行或现场维修

结构完整度归零
→ 完全损坏
→ 强制停止并断电
→ 断开中枢
→ 激活失效

现场维修完成
→ 需要重新激活
→ 玩家现场激活
→ 恢复正常使用
```

- 完全损坏不会立刻删除机器实体。
- 机器的硬件配置、算法与玩家配置原则上保留。
- 维修的资源、时间、工具和现场操作流程暂未完成。

## 建筑损坏与恢复

```text
结构完整度大于0
→ 建筑继续存在
→ 可以维修

结构完整度归零
→ 建筑被摧毁
→ 固定功能停止
→ 必须重新建造
```

- 建筑不具有激活状态，因此不存在重新激活。
- 重建成本、施工时间及是否保留原配置暂未完成。

## 暂缓的扩展

以下内容可能增加系统深度，但不进入当前核心规则：

- 单个传感器、计算核心或效应器分别受损。
- 受损导致效率、精度、算力或能耗变化。
- 温度、磨损和超载产生实体故障。
- 随机故障、部件寿命和预防性维护。
- 不同伤害类型对结构和组件产生不同结果。

## 暂未完成

- 机器维修与建筑维修的资源、时间和工具需求。
- 完全损坏机器是否存在无法维修的极端情况。
- 建筑重建后是否恢复原设置。
- 后续探索／拓荒版本的伤害来源、伤害结算和维修交互；明确不进入第一版。
- 结构完整度的界面表现、警告阈值和受损外观。
