# 在线与离线玩法

> 状态：第一版在线边界、完整离线时间、确定性事件范围与报告已完成

## 分工原则

离线系统负责执行玩家已经设计好的稳定流程；在线玩家负责决定方向、创造新流程、理解异常和处理尚未被自动化覆盖的问题。

| 离线/自动运行 | 在线/主动操作 |
|---|---|
| 重复性生产与照料 | 规划、建造与重构 |
| 常规巡逻与防御 | 应对异常和重大危机 |
| 执行既有规则 | 创造、测试和优化规则 |
| 积累资源 | 决定资源投向与扩张方向 |
| 记录异常 | 诊断原因并制定预防方案 |

## 在线玩法候选

### 探索与拓荒

- 派遣并管理侦察单位揭开迷雾。
- 评估资源点、风险和扩张路线。
- 调查遗迹，获取新机器、设备或世界信息。

### 系统设计与优化

- 建造、连接、测试和重构自动化网络。
- 分析瓶颈、拥堵、能耗和任务冲突。
- 创建区域策略、单位模板与应急预案。

### 危机处理

- 面对异常天气、大型生物或连锁故障。
- 暂时重分配资源、关闭节点或发布全局命令。
- 危机后复盘并修补系统漏洞。

### 创造与表达

- 基地布局、美化、涂装与机器人命名。
- 挑战更少设备、更低能耗或更高稳定性的方案。
- 若未来支持联网，可展示或分享设计。

### 叙事与关系

- 处理通讯、委托、遗迹记录和阶段事件。
- 与 NPC、组织或本土生态建立关系（尚未确认是否采用）。

## 公平性原则

- 离线收益应有清晰结算依据。
- 离线期间的严重损失应可预测、可防范，并设合理下限。
- 在线奖励应主要提供决策、内容或效率机会，避免强迫长时间在线。
- 玩家回归时先呈现摘要和可处理事项，不制造“欠作业”感。

## 第一版施工与制造离线规则

- 已确认施工的建筑按照世界时间继续推进，不需要施工机器、算法、电能或玩家在线。
- 制造工坊按照实际供电、资源和缓存状态推进。离线期间发生缺电、队首资源不足或输出缓存已满时，只推进到阻塞时刻并停止。
- 回归摘要需要显示完成的建筑、制造完成的组件、当前阻塞配方及阻塞原因；不得把整段离线时间直接换算为无条件完成数量。

## 第一版离线时长原则

- 第一版不设置8小时或其他离线收益时长上限，按照实际离线时间完整推进玩家已经建立的自动化流程。
- 长期稳定运行本身是玩家成功设计自动化系统的成果，不通过强制上线频率截断收益。
- 长时间离线采用内部分段和事件驱动结算；分段只用于控制计算量，不减少有效结算时间或产出。
- 缓存、仓库、种子、燃料、储量、能源、算法错误和任务阻塞等现有规则自然限制收益，离线系统不替玩家绕过这些限制。
- 使用UTC时间记录退出与重新进入时间。检测到系统时间倒退时，本次离线时长按0处理；第一版不投入复杂防作弊系统。
- 结算按事件预算分帧执行并显示进度，避免长时间离线造成界面假死。单个算法出现异常高频事件时停止该算法并报警，不阻塞整个世界结算。
- 离线结算进度必须能够继续保存；结算中途退出后从已确认进度继续，不重复发放收益。

## 第一版确定性事件顺序

- 离线结算不逐帧重播，而是跳到下一次具有玩法意义的状态变化、行为完成或阻塞时刻。
- 同时刻事件固定按照能源、世界生产／状态、传感器、算法、机器任务／行为、资源与奖励的顺序结算；同层使用永久对象ID和事件序号保证结果可复现。
- 结算按帧使用事件预算并持久化阶段进度，完成前不允许玩家进入世界修改状态。

## 第一版离线内容边界与报告

- 离线推进已实现的确定性世界时间、能源、农业、资源点、缓存、五套算法、机器行为与导航、固定运输、施工制造和任务经验。
- 离线不替玩家产生购买、升级、硬件配置、算法设计、配方选择、建造部署和奖励选择等新决策；未实现的探索、拓荒、通信、战斗和维修不参与结算。
- 回归报告聚合资源净变化、物资消耗、施工制造、任务结果、电网停机、缓存损失、算法异常与未解决责任，并允许在中枢历史中重新查看。

## 后续版本问题

- 实际探索、拓荒和危机处理加入后，在线决策与长期自动化之间的时间分配。
- 玩家始终不直接驾驶或操纵机器；未来危机仍通过算法、配置、任务和全局策略处理，具体工具随战斗版本设计。
- 第一版事件驱动范围已冻结；后续系统只有在形成确定性结算规则后才能加入离线白名单。
