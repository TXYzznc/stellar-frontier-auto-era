# 建筑与建造系统

> 状态：核心生命周期、第一版施工与制造规则已确认；后续建筑内容仍待扩展

## 已确认定义

- 机器、建筑物和资源点是三个互斥的友方可交互对象大类。
- 建筑物具有固定基础功能，不安装传感器、计算核心和效应器。
- 墙体、地基、道路、仓储及信号塔等可以属于建筑物。
- 防御塔不是建筑，而是配置了攻击能力的机器。
- 农田、人工林、生物培养池等即使由玩家建造，也属于资源点，不属于建筑物。
- 前线建筑可以损坏和被摧毁，完全损坏后需要重建。

建筑物的职责是提供固定加工、储存、供能、防护、连接或区域功能。建筑物不通过内部组件、节点算法或复杂产线布局承担游戏的核心自动化决策；供料、取货、维护、协作和异常处理由机器完成。

## 建筑生命周期

建筑不使用机器的“激活”概念。激活表示机器完成初始化、注册并获得运行算法的资格，而建筑不安装机器组件，也不运行本地节点算法。

建筑使用以下生命周期：

```text
建造中
→ 已建成
→ 正常／停止／断电
→ 受损
→ 被摧毁
```

- 部分建筑建成后自动工作，部分建筑需要玩家主动启动。
- 建筑使用“启动／停止”，不使用“激活／取消激活”。
- 需要能源的建筑只有在通电并满足自身运行条件时才能工作。

## 结构完整度

- 建筑具有结构完整度，作用类似传统HP。
- 结构完整度大于0时，建筑仍然存在并可以维修。
- 结构完整度降低但尚未归零时，第一版不直接降低建筑功能，只显示受损状态和维修警告。
- 结构完整度归零后建筑被摧毁，固定功能立即停止。
- 被摧毁的建筑不能通过普通维修恢复，需要重新建造。
- 重建所需的资源比例在经济系统与第一版数值阶段确定。

## 制造工坊

制造工坊是普通建筑物的一种，不形成新的友方对象类别。

- 工坊提供固定制造功能，不安装传感器、计算核心和效应器，也不运行节点算法。
- 工坊当前只负责制造，不承担组件、机器载体或其他物品的升级功能。
- 玩家负责选择图纸和制造配方，并决定是否消耗稀有材料。
- 工坊公开输入缓存、输出缓存、制造队列、当前进度、供电状态和阻塞原因等状态，并提供开始、暂停或取消等公开操作。
- 玩家可以在现场直接操作工坊；外部机器可以使用对象状态传感器读取公开状态，并通过兼容效应器调用公开操作。自动供料、启动生产、收取产物和异常处理的算法运行在机器上。
- 配方中的金币、木材、矿石、水和生物质直接扣除全局余额；专有原料和其他实体物品必须运入工坊输入缓存。产出的实体成品先进入输出缓存，再由机器转移。

第一版只实现一座基础制造工坊、单一制造队列、少量必要配方和最小阻塞反馈，不实现复杂并行产线。

第一版制造工坊在蓄电基础任务完成后通过确定性图纸解锁。玩家手动选择配方并开始制造；工坊首次启动并形成真实负载缺口后派发第二台生物质发电机的供电扩张任务。断电、资源不足或输出缓存已满时暂停并显示原因，断电不清空进度。成品进入输出缓存，由机器搬运至仓库后按类别自动进入组件库、机器库或实体库存。

蓄电基础任务完成时一并解锁基础计算核心制造图纸。第一轮制造教学固定生产一个基础计算核心，配方消耗200金币和2矿石，制造时间1分钟；成品必须由机器从工坊输出缓存搬运入库并进入组件库，之后用于探索机器准备。

## 第一版施工规则

- 玩家通过HUD进入建造模式，选择图纸、放置预览并确认。有效位置确认后生成施工状态建筑，自动按现实时间推进，不要求施工机器、效应器或算法，也不消耗电能。
- 施工中的建筑占据实际空间但不能提供功能、不能移动。施工进度写入存档并参与离线世界推进。
- 第一版不设置全局施工队列，资源、空间和解锁条件允许时可以同时施工多个建筑；不实现工人、施工加速道具、多机器协作或付费立即完成。
- 位置预览与合法性检查不扣资源。玩家确认施工后原子扣除全部金币和通用资源并立即开始。
- 建造模式从HUD进入，先选择建筑图纸，再在世界中选择位置和朝向。图纸条目显示功能摘要、完整成本、施工时间、资源满足状态、解锁条件和规则按钮。
- 放置预览必须显示建筑轮廓与占地范围：合法位置为绿色，非法位置为红色并给出主要原因，例如与资源点重叠、超出可建造区域或地形不合法。
- 第一版每次确认建造后退出当前放置状态，不支持连续批量放置；再次建造需要重新选择图纸。
- 主动取消施工时，各项返还量为“向下取整（原始投入×剩余施工比例）”；不额外收取手续费。建成后不能取消，只能走拆除或回收。被摧毁建筑的80%重建成本属于独立规则。
- 施工现场面板显示进度、剩余时间、尚未提供功能的说明和取消按钮。取消确认弹窗必须按成本项列出实际返还量。

| 第一版建筑 | 施工时间 |
|---|---:|
| 基础蓄电池 | 2分钟 |
| 基础制造工坊 | 3分钟 |
| 第二台生物质发电机 | 4分钟 |

## 第一版制造队列与取消

- 配方加入单一队列时不扣资源；轮到队首开始执行时，原子检查并扣除全部成本。资源不足时停在队首并明确显示缺少内容。
- 断电、资源不足或输出缓存已满时只暂停，不清空已经完成的进度。实时负载和阻塞按世界模拟持续结算。
- 未开始配方取消时无须返还；正在制造的配方取消时，各项返还量为“向下取整（原始投入×剩余制造比例）”。取消不产生成品。
- 第一版基础计算核心、基础探索扫描器、通信接收器和通信发射器的制造时间均为1分钟。配方时间独立配置，不按照经济价值自动换算。
- 离线制造只能推进到真实阻塞时刻；发生缺电、资源不足或输出缓存已满后，不得越过阻塞继续完成后续队列。
- 工坊界面分为配方列表、当前制造与队列、输出缓存三部分。配方显示产物、时间、完整成本、资源满足状态、图纸状态和当前拥有数量。
- 加入队列时必须提示资源尚未预留，将在项目实际开始时检查并扣除。当前制造显示进度、剩余时间、功率、运行／暂停／阻塞状态及全部阻塞原因。
- 输出缓存不提供玩家直接领取按钮，成品仍须由机器运入仓库后自动分类。
- 第一版当前项目固定在队首，等待项目不支持拖动重排；改变顺序需要取消未开始项目并重新加入。每次只加入一个制造项目，不提供批量数量输入、效率曲线或预计全部完成时间。

轮式载体、基础计算核心和两种种子在第一版可以通过商店以金币购买；基础计算核心也可以在取得图纸后制造。应急生物质包同样以金币购买，但价格明显高于正常生产生物质的等价成本。

由于第一版配方只使用已结算的通用资源，启动建造或配方时直接扣除全局余额，不实现工坊实体原料供给。制造完成的组件仍先成为工坊输出缓存中的封装实体，必须由机器搬运并入库。

第一版建筑占地、状态、锚点和交互见[第一版灰盒对象与交互规格](../04-第一版/06-灰盒对象与交互规格.md)。第一版工坊由玩家选择图纸和配方，机器只负责输出产物运输，不开放外部效应器触发制造。

## 后续版本问题

- 建筑维修、维护、拆除、回收和重建成本。
- 未拓荒区域的前线建筑边界与信号塔完整规格。
- 更多建筑的施工、地形与功能验收规则。
- 需要实体专有材料时的工坊输入缓存和外部机器自动化接口。
