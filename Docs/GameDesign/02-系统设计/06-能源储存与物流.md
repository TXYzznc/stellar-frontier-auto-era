# 能源、储存与物流系统

> 状态：第一版能源、容量、固定路线物流与异常规则已完成；动态通信运输属于后续版本

## 系统目的

能源用于限制机器与建筑的持续运行规模、制造供需高峰，并为前线建设形成独立约束。电能属于能源而不是资源，不进入通用资源余额；它由实时供电能力与储能共同组成运行系统。

## 能源模型

能源同时存在两个核心数值：

- **功率**：当前单位时间内能够产生或消耗电能的速度。
- **电量**：储能设施中已经保存、可以在供电不足时释放的电能总量。

第一版使用游戏抽象单位，不套用现实中的千瓦和千瓦时：

```text
1功率持续运行1分钟 = 产生或消耗1电量

电量变化
=（当前发电功率－当前耗电功率）× 经过秒数 ÷ 60

一个4分钟标准作业周期的电量
= 功率 × 4
```

- 电网按照实际经过时间持续结算，不在4分钟标准周期边界集中跳变。标准周期只用于设计表校准和比较设备。
- 界面至少显示当前发电功率、当前耗电功率、净功率、当前储存电量／储能上限，以及按照当前净消耗估算的剩余运行时间。
- 当净功率大于等于0时，不显示剩余耗尽时间；可以改为显示当前充电速度或预计充满时间。

```text
当前发电功率 > 当前耗电功率
→ 所有获准供电的设备正常运行
→ 剩余功率为储能设施充电

当前发电功率 < 当前耗电功率
→ 储能设施补充供电缺口

储能不足以补充缺口
→ 按供电优先级停止低优先级设备
```

目前可被机器和建筑直接使用的能源只有统一电能。煤炭、石油、生物质和核燃料等属于发电原料，不形成彼此独立的终端能源网络。

区域没有储能设施时，实时发电仍可直接供设备使用；储能只负责吸收剩余功率和弥补发电缺口，不是设备接入电网的必要前提。

### 第一版默认电源调度

第一版采用固定、可预测的实时供电顺序：

```text
免费环境能源
→ 已开启的燃料发电站
→ 蓄电池放电
→ 按供电优先级停止低优先级负载
```

- 太阳能等免费环境能源优先直接满足当前负载；剩余免费电力自动为蓄电池充电，储能已满后的盈余直接舍弃。
- 已开启的燃料发电站只补足免费能源未满足的当前负载。多台同类燃料发电站按照建造顺序依次承担剩余需求；第一版不向玩家开放发电调度顺序编辑。
- 所有已开启发电站达到额定功率后仍有实时缺口时，蓄电池自动放电补足；蓄电池不足后才进入确定性的负载停机流程。
- 燃料发电默认不主动提高输出为储能充电。玩家开启“允许燃料充电”并设置目标储能比例后，未达到目标的储能空间才会形成额外电网需求；达到目标后发电站自动恢复为只满足实时负载。
- 同一个结算时刻中，蓄电池不能同时充电和放电；实时负载始终优先于任何充电需求。
- 第一版不实现最低储能保护、储能充放电功率限制和玩家可编辑的发电优先级。玩家与算法只控制发电站启停、燃料充电许可和燃料充电目标比例。

## 发电设施

发电设施具有多种变体，例如：

- 燃料发电机：消耗煤炭、石油等燃料；不同燃料具有不同的总供能量和发电表现。
- 风力发电机：依赖风力环境，发电功率可能波动。
- 水力发电机：依赖适合建设的水体与地形条件。
- 生物发电机：消耗农业产物、生物质或相关废料。
- 太阳能发电机：依赖光照条件，具有明显时间或天气波动。
- 核电站：使用核燃料，提供高功率、长周期的稳定供电。

“消耗型、环境型、区域型”用于描述发电设施的运行特征，不强制成为互斥职业分类。同一设施可以同时具有多个特征，例如水力发电既依赖区域条件，也受环境状态影响。

具体燃料属性、发电功率、转化效率、启动速度和建设条件留待内容与数值阶段设计。

### 第一版能源设施基准

| 设施 | 发电／储能数据 | 第一版限制 |
|---|---:|---|
| 初始太阳能发电器 | 白天15功率，夜间0 | 不可建造、拆除、出售或损坏 |
| 基础生物质发电机 | 额定60功率 | 1生物质提供60电量 |
| 基础蓄电池 | 240电量上限 | 不设置充放电功率上限和转换损耗 |

- 一个16分钟有效日照阶段最多产生“15×16＝240电量”，恰好等于一块基础蓄电池的容量。
- 一块满电基础蓄电池可以在60功率缺口下维持4分钟，即一个标准作业周期。
- 银穗麦完美批次的10生物质对应600电量；赤芯芒完美批次的30生物质对应1800电量。
- 生物质发电机保存已经投入但尚未消耗完的燃料电量，启停不会直接损失剩余燃料。

### 第一版初始燃料与应急商品

- 新存档初始拥有10生物质，对应600电量。该数量用于保证基础引导不被燃料短缺打断，并与一次银穗麦完美清理的10生物质形成直观补充关系。
- 商店常驻“应急生物质包”：每包提供10生物质，售价1200金币，第一版不限购。
- 应急包售价为其中生物质500基础价值的2.4倍。它负责在玩家仍有金币时快速解除燃料危机，不应成为长期替代农业的常规燃料来源。
- 一包应急生物质在完全依赖生物质发电时可提供600电量；实际持续时间由当前功率缺口决定，太阳能供电会进一步延长其使用时间。

### 发电站两层控制

消耗资源的发电站使用“本地安全调节＋外部策略调度”：

```text
实际输出功率
= min（发电站额定功率，电网分配给该发电站的剩余需求）

基础生物质发电机每分钟消耗
= 实际输出功率 ÷ 60 生物质
```

- 发电站额定功率是固有属性，第一版不能由玩家或算法任意修改；升级、超载或特殊状态后续可以按照明确规则改变额定功率。
- 发电站本地控制器负责不超过额定功率、按照电网分配的真实需求降低输出、避免向已经无法接收电量的电网继续消耗燃料，以及执行基础安全保护。
- 玩家可以直接设置发电站开关、是否允许燃料发电为蓄电池充电和燃料充电目标储能比例。
- 外部机器算法后续可以通过对象状态传感器读取电网、发电站和蓄电池公开状态，再通过兼容控制能力修改同一组设置；建筑本身仍不安装机器组件或运行节点算法。
- 第一版蓄电基础教学先要求玩家手动配置。远程通信能力在制造阶段后解锁，机器算法调度属于后续可用的自动化优化，不是基础供电成立的前置条件。
- 控制机器失联、停机或算法异常时，发电站保留最后一次开关和充电许可，本地安全调节继续运行。
- 第一版基础生物质发电机没有启动耗时、最低稳定功率、空转燃料消耗或频繁启停损耗；处于开启状态但没有需求时显示“待命”，实际输出和燃料消耗均为0。
- 太阳能等不消耗资源的环境发电设施没有输出功率设置：开启时按照环境提供全部可用功率，盈余优先充电，储能已满后的剩余电力可以舍弃。设施仍可开关。

## 机器与组件能耗

机器载体、传感器、计算核心和效应器分别具有自己的能耗数据。整台机器的当前耗电由载体与已安装组件的当前能耗相加得到。

```text
机器当前耗电
= 机器载体当前能耗
+ 所有已安装传感器当前能耗
+ 所有已安装计算核心当前能耗
+ 所有已安装效应器当前能耗
```

每个机器载体和组件预留三档能耗数据：

| 能耗数据 | 含义 |
|---|---|
| 待机能耗 | 设备已经供电、但当前没有执行主要工作时的能耗 |
| 稳定能耗 | 设备以正常模式执行工作 |
| 超载能耗 | 设备以玩家主动开启的超载模式执行工作 |

当前默认规则为：设备未工作时使用待机能耗，正常工作时使用稳定能耗。超载能耗及其效果暂不进入当前详细设计，保留为后续扩展。

### 第一版机器与组件能耗表

- 待机功率默认约为稳定功率的10%，但两者作为独立字段配置，不在运行时强制套用统一倍率。后续对象可以根据特性使用不同待机比例。
- 能源数值允许小数，功率界面最多显示一位小数；该规则不受经济面额必须使用整数的约束。

| 对象 | 待机功率 | 稳定功率 |
|---|---:|---:|
| 通用轮式载体 | 0.2 | 2 |
| 基础计算核心 | 0.3 | 3 |
| 对象状态传感器 | 0.2 | 2 |
| 基础土壤传感器 | 0.2 | 2 |
| 基础探索扫描器 | 0.5 | 5 |
| 远程通信接收器 | 0.3 | 3 |
| 机械臂 | 0.5 | 5 |
| 水枪 | 0.5 | 5 |
| 切割效应器 | 0.7 | 7 |
| 钻探效应器 | 0.8 | 8 |
| 远程通信发射器 | 0.4 | 4 |

- 一级升二级后，载体和组件的待机／稳定功率原则上提高约20%，最终数据保留一位小数并作为独立配置字段。基础计算核心二级稳定功率明确为4。

| 第一版建筑 | 待机功率 | 稳定功率 |
|---|---:|---:|
| 主基地基础仓库 | 0.1 | 1 |
| 基础制造工坊 | 2.5 | 25 |
| 基础蓄电池 | 0 | 0 |
| 发电设施 | 0 | 0 |

- 传感器持续采样时使用稳定功率；计算核心正在运行算法时使用稳定功率；效应器没有执行动作时使用待机功率。
- 正常模式但当前没有工作的单个组件使用待机功率，整台机器是否处于“工作负载”必须按照各部件当前活动分别求和，不能用一个整机倍率替代。
- 机器休眠时，载体、计算核心、传感器和效应器全部使用各自待机功率；整机现场断电时全部为0。

完整农田机器休眠约为1.9功率；持续运行核心与两个传感器、效应器待机时约为8.2功率；执行浇水或收获时约为10.9～14.5功率。加上仓库接收物资的1功率，仍不超过太阳能15功率的最低恢复预算。

### 供电状态、运行模式与当前活动

组件需要区分三个不同层次，不能只用一个“开关”表示：

1. **供电状态**：整台机器已经供电或彻底断电。
2. **运行模式**：待机模式、正常模式；未来可能增加超载模式。
3. **当前活动**：当前没有执行工作，或正在执行具体工作。

建议的能耗关系为：

```text
整机彻底断电
→ 能耗为 0

已经供电，但处于待机模式
→ 使用待机能耗，不能执行算法请求

正常模式，但当前组件没有执行工作
→ 该组件使用待机能耗，可以响应后续算法请求

正常模式，传感器正在采样、核心正在运行算法或效应器正在执行动作
→ 对应组件使用稳定能耗

超载模式，正在执行工作
→ 使用超载能耗
```

“待机模式”和“当前空闲”可以具有相同能耗，但功能不同：前者被玩家禁止工作，后者仍可以随时响应算法。

## 组件能源控制权限

- 算法只能读取传感器信息、进行判断并请求效应器行为，不能改变组件的供电状态或运行模式。
- 玩家可以在现场或中枢通过复选框把单个传感器或效应器切换为休眠或启动。
- 计算核心暂时没有独立复选框；机器通电时保持连接和供电，并跟随整机休眠或断电。
- 现场和中枢都可以控制整机休眠或开机。
- 只有现场可以切断或恢复整台机器的物理电源；不提供单个组件物理断电操作。
- 中枢不能远程切断机器电源。
- 超载模式未来允许从哪里切换，随超载系统一并设计，当前不锁定。

## 激活与供电

- 激活是独立于供电的机器资格状态。
- 整机休眠或断电不会取消激活。
- 断电机器能耗归零、停止工作并断开中枢；恢复供电后保留原激活状态和全部配置。
- 机器完整损坏才会使激活失效；维修后必须现场重新激活。
- 电网自动切除与恢复供电时，以整台机器或整座建筑为最小单位。

## 区域级电网

当前采用简化的区域级电网，不要求玩家在第一版为每台设备铺设完整电线网络。

- 每个区域拥有自己的区域电网。
- 区域内符合供电条件的机器、建筑、发电设施和储能设施参与同一个供需结算。
- 未拓荒区域的前线电网独立运行，必须部署本地发电或储能设施。
- 拓荒成功后，区域能源数据进入基地全局统计，但区域仍保留自己的发电、用电和储能状态。
- 一个区域的富余电力不会在没有输电规则的情况下自动补充另一个区域。
- 是否增加跨区域输电设施及多个子电网，留待后续版本评估。

## 供电优先级

供电不足时不随机选择设备停机，而是采用确定性的供电优先级。

```text
关键设备
→ 普通生产
→ 次要生产
→ 可暂停设备
```

- 系统提供默认优先级，避免玩家在初期承担额外配置负担。
- 后续允许玩家调整机器和建筑的供电优先级。
- 储能无法覆盖缺口时，从低优先级设备开始停止供电。
- 同级设备之间的具体处理顺序暂未确定。
- 界面必须显示当前发电、用电、储能、预计维持时间和因缺电停机的设备。

### 第一版能源界面

- 中枢能源页顶部固定显示当前发电、当前用电、净功率、当前储电／上限、按当前功率估算的充满或耗尽时间，以及缺电停机设备数量。估算时间必须明确标注会随负载、昼夜和设施状态变化。
- 发电设施列表显示名称、位置、开关、额定／实际功率、燃料、消耗速度和预计维持时间。燃料发电设施可以设置是否允许为蓄电池充电及目标储电比例；免费环境能源不显示燃料设置。
- 蓄电设施显示当前电量／容量、充电／放电／待机状态、当前功率和按当前状态估算的剩余时间。
- 用电对象按机器与建筑分组，显示名称、状态、当前功率、默认供电优先级、是否因缺电停机和定位操作。第一版只显示固定优先级，不允许玩家调整。
- 第一版不制作连续功率曲线。能源历史只记录电量过低／耗尽、缺电停机／恢复、燃料耗尽和负载首次超过供给等离散事件。

## 中枢能源例外

- 中枢采用独立核动力，不参与任何区域电网的发电、用电或储能结算。
- 中枢不会因基地或区域断电停止运行，也不需要玩家补充燃料或维护供能。
- 中枢界面、状态查看、远程配置和中枢算法不会因为普通能源不足而失效。
- 这一规则用于避免能源与全局管理互相锁死，并控制当前系统复杂度。
- 后续即使中枢增加世界实体，其功能定位和能源独立原则暂不改变。

## 信号塔与前线供电

- 信号塔属于区域电网的用电建筑，需要持续供电才能推进拓荒。
- 信号塔因断电停止时，拓荒进度以极慢速度回退至上一个进度保存点。
- 前线供电不足不会影响中枢自身，但可能使普通机器、建筑与信号塔停止运行。
- 具有完整远程通信能力的探索机器仍需解决自身所在区域的能源来源；具体方式暂未完成。

## 资源点临时缓存

- 每个能够产出资源的资源点具有独立临时缓存和缓存上限。资源完成采集或生产后，先进入所属资源点的缓存，不会直接进入基地库存。
- 主动采集包括开采、收割等由机器发起的离散行为。缓存无法容纳本次预期产出时，不允许开始主动采集，不消耗资源储量，成熟作物等可采集对象继续保留在资源点。
- 主动采集开始时为本次预期产出预留缓存空间，避免行为完成后才发现无法存放。可变产出的具体预留口径留到数值与实现阶段。
- 被动产出包括无法因缓存状态主动停下的持续生成过程。缓存达到上限后仍继续生成，溢出部分直接损失，并产生明确警告。
- 运输机器从资源点缓存装载资源；缓存不是仓库，也不纳入基地可用库存。

## 运输能力

运输不是机器职业，而是一组能力条件。基础运输能力与自主装卸能力分开计算：

```text
移动能力
+ 货舱容量
= 基础运输能力

基础运输能力
+ 资源转移能力
= 自主装卸运输能力
```

- 任何具有移动能力和货舱容量的机器都能承担资源运输，不设置专属运输机器硬分类。
- 没有资源转移能力的运输机器不能自行装货或卸货，需要资源点、仓库或设施旁的另一台转移机器协助。
- 具有资源转移能力的运输机器可以独立完成装载、运输和卸载循环，但需要为相应效应器付出槽位、算力和能耗成本。
- 实体物品以及尚未完成入库结算的通用资源，在资源点缓存、机器货舱、仓库和生产设施输入缓存之间移动时，必须经过实际装载、移动和卸载过程。

## 统一资源转移行为

- 第一版不把装载、卸载、取货和供料设计成四套独立行为。机械臂等兼容效应器统一提供“转移资源”行为。
- “转移资源”行为至少接收来源、目标、资源类型、转移数量或停止条件。来源和目标可以是资源点缓存、机器货舱、仓库以及生产设施输入输出缓存。
- 行为表现由来源和目标自动决定：缓存到货舱表现为装载，货舱到仓库表现为卸载，仓库到货舱表现为取货，货舱到设施表现为供料。
- 执行资源转移的机器不一定需要自己的货舱；只要效应器能够同时接触来源和目标，就可以在两者之间按转移速度搬运资源。
- 第一版不模拟每个物品的独立物理抓取。资源按效应器转移速度连续或分批结算，并通过动画表现搬运过程。
- 转移以整数单位逐步结算；每个成功单位同时从来源扣除并加入目标。中途断电、取消或抢占时已经转移的部分保留，未完成部分仍在来源。
- 多台机器同时转移同一来源时，每个单位通过原子结算避免资源复制；行为结束时统一返回实际转移数量和停止原因。机器仅仅前往来源不预占资源。
- 行为结果包括转移完成、来源无资源、目标容量不足、不在交互范围、物品不兼容、来源／目标失效、被抢占和被取消。其中“目标容量不足”只适用于具有实体库存容量的目标。
- 资源点、仓库和生产设施提供宽松的装卸区域，不要求机器进行像素级精确停靠。
- 机械臂使用统一资源转移规则处理可运输物品，不再按液体、危险品或特殊容器扩展新的物流层；资源差异通过物品配置表达。

## 运输组织方式

玩家可以在两种基础组织方式之间选择：

- 自主装卸：货运机器同时配置货舱和机械臂，能够独立完成完整循环，适合少量、临时和前线运输。
- 装卸运输分工：无机械臂货运机器只负责移动和携带，由资源点或仓库旁的转移机器装卸，适合固定路线和规模化运输，但会产生等待与排队。

初始运输方案应当能够自主装卸，保证玩家不必在教学阶段立即处理多机协作。专用装卸机器作为后续物流优化方式开放。

第一版固定路线运输采用“运输机驻守来源并自行监测”的拉取方式。运输机安装对象状态传感器并首次部署在来源附近，本地算法读取缓存、达量出发、交付后返回，不需要资源点旁另设通信监控机。通信调度加入后，生产机器、运输机器或独立监控机器都可以按玩家设计承担状态发送职责，但系统不强制专用机器类型。

当运输机器到达装卸区域但自身和附近机器都没有可用资源转移能力时，系统应明确警告“缺少资源转移能力”，并标出阻塞位置。

## 实体仓库与中枢库存视图

- 仓库属于固定功能建筑，并承担两种不同职责：通用资源的入库结算，以及其他实体物品的本地储存。
- 木材、矿石、水和生物质在送入任意仓库后立即转换为全局资源余额，不再占用仓库容量、不保留位置，也不能从余额中重新取出。
- 因此，兼容仓库接收木材、矿石、水和生物质时不会出现“仓库容量不足”；只有农产品、种子、燃料、专有原料、材料和战利品等实体物品可能因仓库实体容量不足而无法入库。
- 金币直接进入全局余额，不经过仓库。通用资源的常规消耗直接扣除全局余额，不需要再次运输到制造、建造、升级或生产地点。
- 农产品、种子、燃料、区域专有原料、建筑材料、高级与合成材料、战利品等继续作为实体物品。每座仓库对这些物品具有独立库存与容量，物品存入哪座仓库就实际位于哪座仓库。
- 纳入中枢库存视图的实体仓库不会合并成能够瞬移实体物品的全局背包，仓库之间也不会自动转移物品。
- 仓库本身不直接连接中枢。中枢通过附近已连接机器的对象状态传感器取得仓库库存，并汇总显示当前可远程观测仓库的资源总量。
- 第一版中枢只能从具有有效观测数据的主基地基础仓库出售实体物品；其他仓库即使能够远程查看，也不能直接出售其中物品，必须先由机器运回主基地基础仓库。
- 制造、建造和生产中的通用资源成本直接从全局余额扣除；配方要求的实体物品必须实际运抵当地仓库、设施输入缓存或施工供给位置。
- 仓库中的物品不会因为观察机器断开中枢、区域信号中断或信号塔失效而消失，只会在缺少有效观测数据时暂时退出中枢汇总、远程交易和远程管理范围。

第一版商店交付按物品类别处理：实体资源与物资送入主基地初始仓库；购买的通用资源在该仓库完成入库结算；组件进入组件库；未部署机器载体进入机器库。后续版本可以允许玩家选择交付仓库。

所有从世界或制造设施进入仓库的实体同样执行统一自动分类：金币进入全局金币余额；木材、矿石、水和生物质进入全局资源余额；组件进入组件库；未部署机器载体进入机器库；其他物资继续保留在当地仓库实体库存中。仓库是统一入库入口，不另建组件或机器接收设施。

### 第一版仓库界面

- 仓库现场面板显示实体库存容量／上限、是否已满、分类库存、最近入库与自动分类记录，以及等待卸货或容量不足记录。
- 实体库存只保留种子、农产品、建筑材料、专有／合成材料和其他实体物品；金币、已结算通用资源、组件库组件和机器库载体不重复显示。
- 没有随机词条的同类物品按照物品类型与品质／等级合并堆叠。详情显示描述、数量、用途／能力标签、可出售状态、实际回收价、常见用途和来源标签。
- 仓库不提供玩家手动搬出、跨仓拖动、直接送入工坊、点击完成运输、丢弃和复杂预留。可以跳转统一出售页并预选物品，但物品世界转移继续由机器执行。
- 入库记录必须明确显示最终分类去向，例如进入组件库、机器库、全局余额或保留在当前仓库。

## 拓荒区域本地储存

- 正在拓荒的区域可以建设本地仓库或临时储存设施；其中的实体物品只在当地存在和使用。
- 拓荒区域可以直接消耗已经结算的全局通用资源余额。所需种子、燃料、专有材料、补给和回收物等实体物品仍必须通过机器实际运输进入或运出。
- 当区域拓荒成功并通过信号塔正式接入基地后，当地机器可以自动连接中枢；仓库库存需要由附近装有对象状态传感器的已连接机器上传，才能进入中枢汇总视图。
- 后续若观察机器或区域失去连接，当地库存继续保留在原实体仓库中；恢复有效观测后重新进入汇总并恢复远程交易资格。

## 第一版能源范围

- 初始基地已经建有一台基础生物质发电机和一台低功率太阳能发电器，并拥有足够完成基础引导的生物质。
- 太阳能发电器不消耗燃料，只在白天持续发电，夜间输出归零。其定位是能源死锁恢复保障，白天最低应能支持一台基础机器完成获取生物质所需的恢复作业，但不能承担基地正常扩张后的主要负载。
- 第一版一个完整昼夜暂定为24分钟，其中16分钟为有效日照、8分钟为无日照；新存档从白天早期开始。能源结算只使用“有日照／无日照”两段状态，不模拟天气、季节、朝向和逐时功率曲线。
- 为保证恢复路径始终存在，第一版中的初始太阳能发电器不能拆除、出售或损坏；玩家可以手动关闭，并能在无电状态下重新开启。
- 商店常驻价格较高的应急生物质包，作为有金币时的快速恢复渠道；初始太阳能发电器则保证玩家没有金币和生物质时仍能等待白天恢复生产。
- 基础引导期间能源只提供运行结果，不强迫玩家处理供电。
- 中枢2级后先通过蓄电基础任务开放完整能源界面和基础蓄电池。玩家需要让蓄电池实际充放电并维持生物质供应；完成后获得基础制造工坊图纸。
- 蓄电基础任务只统计派发后的累计量：至少充入30电量、放出30电量；当前全局生物质与发电机剩余燃料折算量合计不少于10生物质，且不存在能源严重异常。
- 制造工坊稳定运行且区域真实负载首次超过单台基础生物质发电机60额定功率时派发供电扩张任务，不要求等待夜晚或先发生实际停电；太阳能和蓄电池暂时补足不影响触发。
- 第二台发电机建成开启后，在制造工坊或其他有效负载运行的条件下连续2分钟无对象因缺电停机，才完成供电扩张。停机使计时归零，关闭全部负载不能完成。
- 第一版实现区域发电功率、当前耗电、储能、默认供电优先级、缺电停机与恢复、警报和最小历史记录。
- 除作为恢复保障的初始太阳能发电器外，第一版不解锁或建造其他太阳能设施，也不实现其他发电方式、跨区域输电、电线、损耗或高级供电策略。

## 第一版数值引用

资源缓存、货舱、仓库、工坊输出缓存、机械臂转移速度、移动速度和阻塞阈值统一见[第一版行为、容量与结算规格](14-第一版行为容量与结算规格.md)，避免在物流文档中重复维护。

第一版机器断电后保存动作、任务、算法状态和断电前运行状态；恢复供电时恢复原运行状态并自动重新判断中枢连接，动作从安全保存进度继续，不能重复结算已经完成的单位。同优先级负载按对象进入供电队列的时间停机与恢复，恢复时仍需满足当前功率和对象运行条件。

## 后续版本问题

- 煤炭、石油等不同燃料的供能量、输出速度和兼容发电站。
- 跨区域输电、区域接入边界和拓荒前线独立供电。
- 通信请求驱动的动态运输与跨机器调度；第一版明确不运行实际通信。
- 生产设施需要实体专有材料时的输入缓存，以及机器间直接转运的高级节点。
- 多物流口、储能损耗、充放电功率上限和玩家可编辑供电顺序。
